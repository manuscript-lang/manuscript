# Standard-library design lessons

Cross-cutting rules for shaping `stdlib/*.ms`. Domain-specific mechanics stay in [runtime.md](runtime.md); exact signatures live in the `.ms` sources.

### One spelling per operation; consolidate by domain

Decision: the stdlib reorganization (#659) removed duplicate routes: `cli` moved into `process` (`process.arguments`, `process.control().environment()` is the only environment API), the temp-root query moved to `FileSystem.temporary_root` (`fs` is the only temp-dir API), string-typed `crypto.hmac` was dropped for `HashAlgorithm.hmac`, and the SSE decoder became an interface with `feed`/`finish`/`retry` methods. Before adding a function, search for an existing home with `ms search_symbol`; a second spelling needs a new decision. Do not restore removed names from old docs or branches.

Apply when: adding or moving a stdlib function, or when two modules could both own an operation.
The scalar `math.abs`, `abs_int`, `sign`, `sign_int` and `to_float32` functions duplicated the `.abs()`, `.sign()` and `.to_float32()` methods and were removed, as was `Set.entries()`, which only repeated `values()` as `[value, value]` pairs; `String.parse_float()` joins `parse_int()` as the Optional form while `math.parse_float` keeps the Result form with its cause.
Evidence: commit 9a2dc4e6, [process](../stdlib/process.ms), [fs](../stdlib/fs.ms), [crypto](../stdlib/crypto.ms), [sse](../stdlib/sse.ms).
Verify: `ms search_symbol <old name>` finds no declaration; `make docs-check` passes and every moved symbol has an updated fixture.

### Pick the failure mode by cause, then the shape

Decision: absence is `Optional`, invalid external data is `Result`, a violated documented precondition faults. `[]` returns `T` and faults out of range; `get(index, default)` on List, String, and Bytes returns `T` or the default; `at()` is removed (#669). `Optional.get(default)` and `Result.get(default)` replace `unwrap`/`unwrap_or` (a missing default on none/error still faults), `get_or_else(create)` on Optional and Result replaces `unwrap_or_else`; `or_else(create)` returns the same wrapper on both (lazy alternative) and `Result.map_error` transforms the error, and `Result.err()` replaces `unwrap_error`. Eager `get(default)` and lazy `get_or_else(create)` are the only pair; `or_else` never unwraps.

Apply when: designing any fallible read, lookup, or conversion.
Evidence: [Optional](../stdlib/core.ms), [Result](../stdlib/core.ms), commits f7a3f26a and 040f6321, [collection rules](../documentation/core-language/types/collections.md).
Verify: out-of-range `[]` faults, `get(i, default: x)` returns `x`, and no `unwrap*` or `at` declaration remains (`ms search_symbol unwrap`).

### Fallible APIs return domain errors that implement Error

Decision: `Result[T, E: Error]`; plain text uses the flat record `TextError("message")` (one `text` field, not a one-case alternative); domain packages define their own error types with `impl Error`. No `Result[T, String]` anywhere, including docs and fixtures.

Apply when: writing a Result-returning API, example, or test.
Evidence: [core.ms](../stdlib/core.ms), [core.ms](../stdlib/core.ms), commit fd5b0bf9; see also the Result bound entry in [language.md](language.md).
Verify: `Result[Int, String]` is rejected; `TextError("x").text == "x"`.

### Text in, bytes by explicit sibling

Decision: write-like operations accept `String`; the raw form is a `_bytes` sibling (`write_bytes`, `send_bytes`, `request_bytes`). Interface operations cannot be generic or overloaded, so sibling names carry the choice. Details and implementer obligations are in [runtime.md](runtime.md).

Apply when: adding a stream, socket, file, or transport write.
Evidence: commits f42b47f1 and cd1ab831.
Verify: `stdout().write("text")` and `write_bytes(bytes)` both check (`ms check`); source `impl`s declare both.

### Collections: construct from a list, keep insertion order

Decision: `Set(list)` constructs from a list; Map and Set iterate in insertion order; mutators are verbs that return the receiver. See [runtime.md](runtime.md) for the failure-mode and order rules.

Apply when: adding collection constructors, conversions (`to_set`), or fixtures.
Evidence: commit c025937b, [collections.ms](../stdlib/collections.ms).
Verify: `Set([3, 1, 2])` iterates 3, 1, 2.

### Every public module needs a fixture, a guide comment, and a doc comment with an example

Verified: public modules have a fixture in `tests/e2e/testdata/stdlib/*.ms`, and all stdlib prose lives in `stdlib/*.ms` (book Markdown is generated by `make docs`). A new member documents its failure mode in its doc comment. The `.ms` declarations are the signature authority for the Rust runtime, which binds natives through `stdlib/bindings.json`.

Apply when: adding a module or public member.
Evidence: [development checks](../documentation/contributing/development.md), [runtime conventions](../documentation/contributing/runtime-conventions.md), [bindings](../stdlib/bindings.json), [docgen](../crates/ms-tooling/src/guide/src/docgen.rs).
Verify: `make docs-check` (add `make docs-coverage` for doc-comment coverage) and `make conform`.

### List structure ops: `entries()` already is `indexed`; piece lists come from one runtime call

Decision: `List.entries()` (`ListEntry` with `index`, `value`) covers the "walk with an index" need, so no `indexed()` alias was added. `zip` returns `Pair[T, U]` and `partition` returns `Partition[T]`, both exported from `@std/collections.ms` but not prelude names, so user types called `Pair` keep working. `chunks`/`windows` share `msrt_list_pieces`; `zip` and `partition` lower to loops with no closure for `zip`. A non-positive size faults.

Apply when: adding List methods that return records or nested lists.
Evidence: `tests/e2e/testdata/stdlib/list-structural-ops.ms`, `snippets/list-{chunks,windows}-zero-fault`.
Verify: `ms test tests/e2e/testdata/stdlib/list-structural-ops.ms`; `make stdlib-bench BENCHFILTER=list.` shows zip 2, chunks 7, windows 70, partition 9 ns per element.

### List operations that need an element bound are written in Manuscript

Decision: `sum`, `min`, `max` and the comparator-less `sorted()`/`sort()` live in the source half of [collections.ms](../stdlib/collections.ms), a bundled source module (`@std/collections.ms+source`) every program loads. Each group is a bounded interface (`ListOrder[T: Comparable]`, `ListExtremes[T: Comparable & Clonable]`, one `sum` interface per numeric element type) with `impl ... for List[T]`; a bundled module may extend a native standard type this way, and its methods apply without an import. A `List[T]` has the operations only when `T` meets the bound. Native `sorted`/`sort` keep a required `compare`; when a native and a source operation share a name, the call's argument count picks one. `Float.compare` must treat NaN as equal to itself and above every value, or float sorts are inconsistent. A file with native inherent methods and bodies is split at load by `split_mixed` in `ms-check/src/stdlib.rs`: bodied contract impls and the interfaces only they implement become the `+source` module, and a bodied inherent `impl List[T]:` method works directly: the split rewrites it to a generated interface plus contract impl, while a bounded or defaulted operation still needs an explicit interface (see `proposals/mixed-native-source-modules.md`).

Apply when: adding a List operation that depends on an element contract, or changing `sortgen`'s recognized comparator shapes.
Evidence: [collections.ms](../stdlib/collections.ms), [list-aggregates fixture](../tests/e2e/testdata/stdlib/list-aggregates.ms), `list.sorted` and `list.sorted_natural` in `bench/perf/stdlib/src/lists.ms`.
Verify: `make stdlib-bench BENCHFILTER=list.sort` shows `sorted_natural` within noise of `sorted`.


### Calls that fail only on a programmer's constant return plain values; fixed-width codecs are methods

Decision: `String.pad_start/pad_end` and `Float.to_fixed/to_precision/to_exponential` return `String`. Their only failures were a negative budget or a digit count outside 0..100, always a literal in the caller, so every table printed `.get()`. A short target or empty padding returns the text unchanged, there is no byte budget (`repeat` keeps one because it multiplies), output beyond the string limit faults like `concat`, and a digit count out of range faults. Binary data reads and writes are methods: `Bytes.int32_le(at)` and siblings return `Result[T, BinaryError]` (only `OutOfRange`), `BytesBuilder.append_int32_le(value)` and siblings return `Unit`, and `BytesBuilder.concat` became `append_bytes` so `append` means one byte. `read_integer`/`write_integer`/`read_float`/`write_float` were removed: the one stdlib use (`processes.ms` frames) is fixed width. The codecs are written in Manuscript in the source half of `stdlib/bytes.ms` (`@std/bytes.ms+source`), which extends the native `Bytes` and `BytesBuilder` (like the source half of `collections.ms` extends `List`; `EXTENSION_MODULES` in `ms-check/src/stdlib.rs` lists them, and an extension module and what it imports are not given the extensions, which would be a cycle). The natives are one word reader (`msrt_bytes_read_word`) and four float bit casts; a `Float32` crosses a native as the `f64` holding its value. The cost against one native per codec: `bytes.read_int32_le` 2 to 9 ns and `bytes.append_int32_le` 3 to 12 ns per call (a method call, a `Result`, and per-byte appends), measured with `make stdlib-bench BENCHFILTER=bytes.`. If binary parsing becomes hot, the reader is the place to add a native fast path.

Apply when: giving a native a `Result` whose error comes only from a constant argument, or adding a sized-number codec.
Evidence: [text-padding fixture](../tests/e2e/testdata/stdlib/text-padding.ms), [binary fixture](../tests/e2e/testdata/stdlib/binary.ms), `bytes.read_int32_le` and `bytes.append_int32_le` in `bench/perf/stdlib/src/binarybench.ms`.
Verify: `ms test tests/e2e/testdata/stdlib/binary.ms tests/e2e/testdata/stdlib/text-padding.ms`; `make stdlib-bench BENCHFILTER=bytes.`.

### Options records as plain defaults; fetch helpers are methods

Decision: a function that takes a settings record declares it `options: FetchOptions = FetchOptions()`, never `Optional[FetchOptions] = none`, so callers write `fetch(url, FetchOptions(method: HttpMethod.Post))` without `some(...)`. Interface operations cannot carry such a default (the checker only allows `= none` there, and the bundled-module exemption hides the error until lowering, #1510), so a type that needs one is a record with methods, not a single-implementation interface: `Fetcher` is a record wrapping `HttpClient` with `impl Closeable`. Since source methods take type parameters (#1475), `read_json[T](response)` became `FetchResponse.json[T]()` and `check_status(response)` became `response.check_status() -> Result[Unit, FetchError]`; the proposal's free functions were workarounds for the missing feature. The same pass renamed `Worker.join` to `wait` (the stdlib's one verb for "wait for an end": `Subprocess.wait`, `Process.wait`, `HttpServer.wait`, `TaskGroup.wait`) and `TaskError.Faulted(message)` to `Faulted(report)`, matching `WorkerError`. A second pass, approved by the user: `time.duration(nanoseconds:)` was removed because `nanoseconds(n)` and the other unit constructors already spell it; `List.reverse_in_place` became `reverse`, the in-place pair of `reversed` like `sort`/`sorted` (`String.reverse()` still returns a copy, since strings are immutable; the fuzz corpus pins that name); `ProcessGroup.spawn` fails with `ProcessError.NotStarted(cause: CommandError)` so a group has one error type, as `WorkerError.NotStarted` does; and the raw worker pipe is a `Channel[Bytes, Bytes]` over a `Transport[Bytes, Bytes]` (`worker.bytes()`, `worker_bytes()`) instead of a second channel-like type. A third pass: the property generator combinators `mapped`, `filtered`, `zipped` and `flat_mapped` became `Gen` methods `map`, `filter`, `zip` and `flat_map`, the names `List` uses, since source methods on generic records can take type parameters and a method cannot collide with another module's export; and `process.ms`'s `ProcessError` became `ControlError` (the error of `ProcessControl`, as `CommandError` is the error of `Commands`) because `processes.ms` exports a `ProcessError` of its own and two sibling modules must not export one name.

Apply when: adding a parameter that is a record of settings, choosing between an interface and a record for a type with one implementation, naming the operation that waits for work to end, adding a second spelling of a constructor, naming a combinator over a record (prefer a method with the List name), naming an error type (derive it from the type whose operations return it, unique across sibling modules), or adding a type that sends and receives (make it a `Transport` behind `Channel`).
Evidence: [fetch.ms](../stdlib/fetch.ms), [fetch fixture](../tests/e2e/testdata/stdlib/fetch.ms), [workers fixture](../tests/conformance/fixtures/e2e/stdlib/workers.ms).
Verify: `ms test tests/e2e/testdata/stdlib/fetch.ms tests/conformance/fixtures/e2e/stdlib/workers.ms`; `ms search_symbol read_json` finds no declaration.
