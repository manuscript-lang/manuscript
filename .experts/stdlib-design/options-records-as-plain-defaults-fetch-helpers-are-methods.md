# Options records as plain defaults; fetch helpers are methods

Decision: a function that takes a settings record declares it `options: FetchOptions = FetchOptions()`, never `FetchOptions? = none`, so callers write `fetch(url, FetchOptions(method: HttpMethod.Post))` without `some(...)`. Interface operations cannot carry such a default (the checker only allows `= none` there, and the bundled-module exemption hides the error until lowering, #1510), so a type that needs one is a record with methods, not a single-implementation interface: `Fetcher` is a record wrapping `HttpClient` with `impl Closeable`. Since source methods take type parameters (#1475), `read_json[T](response)` became `FetchResponse.json[T]()` and `check_status(response)` became `response.check_status() -> Result[Unit, FetchError]`; the proposal's free functions were workarounds for the missing feature. The same pass renamed `Worker.join` to `wait` (the stdlib's one verb for "wait for an end": `Subprocess.wait`, `Process.wait`, `HttpServer.wait`, `TaskGroup.wait`) and `TaskError.Faulted(message)` to `Faulted(report)`, matching `WorkerError`. A second pass, approved by the user: `time.duration(nanoseconds:)` was removed because `nanoseconds(n)` and the other unit constructors already spell it; `List.reverse_in_place` became `reverse`, the in-place pair of `reversed` like `sort`/`sorted` (`String.reverse()` still returns a copy, since strings are immutable; the fuzz corpus pins that name); `ProcessGroup.spawn` fails with `ProcessError.NotStarted(cause: CommandError)` so a group has one error type, as `WorkerError.NotStarted` does; and the raw worker pipe is a `Channel[Bytes, Bytes]` over a `Transport[Bytes, Bytes]` (`worker.bytes()`, `worker_bytes()`) instead of a second channel-like type. A third pass: the property generator combinators `mapped`, `filtered`, `zipped` and `flat_mapped` became `Gen` methods `map`, `filter`, `zip` and `flat_map`, the names `List` uses, since source methods on generic records can take type parameters and a method cannot collide with another module's export; and `process.ms`'s `ProcessError` became `ControlError` (the error of `ProcessControl`, as `CommandError` is the error of `Commands`) because `processes.ms` exports a `ProcessError` of its own and two sibling modules must not export one name.

Apply when: adding a parameter that is a record of settings, choosing between an interface and a record for a type with one implementation, naming the operation that waits for work to end, adding a second spelling of a constructor, naming a combinator over a record (prefer a method with the List name), naming an error type (derive it from the type whose operations return it, unique across sibling modules), or adding a type that sends and receives (make it a `Transport` behind `Channel`).
