# Sell the language through a story and concrete proof

Decision: preserve the prominent tagline, “The language for the agentic era.”, and lead with agents writing correct, fast programs that are easy to review. The user's October 27 corrections rejected a generic feature inventory, a human-review-led pitch, and a correctness story reduced to `try` beside selected benchmark wins. The approved outline presents the language holistically through correctness, performance and reviewability, followed by how it is built and a short trial action. Explain how types without an `any` escape hatch, ordinary generics, Optional/Result, ownership, mutation and scoped concurrency work together; tools and one natural example support that story. Performance means both iteration and execution: Cranelift Debug builds for fast feedback, direct LLVM IR for optimized builds, no tracing GC, documented last-safe-use release of plain data, value representations and measured tradeoffs. Do not turn this into a feature dump or imply all allocations are freed immediately. Show complete, explicitly scoped Rust ranges with linked methodology; omit hardware details from the front page. Keep native measurements separate from agent-coding evaluations. Readability and compiler-derived change facts explain reviewability without implying behavioral proof. Word-count reduction is not the objective. Keep alpha status and setup near the trial action, and a batteries-included environment as direction.

Decision (distinctive-first refinement): the user then asked that the README be appealing, correct, and about what is unique to Manuscript rather than features every language has. Lead each section with a mechanism no mainstream language ships in the same shape: `cause; fix` diagnostics with machine-applicable repairs and named replacements for other languages' habits, `ms guide` and `ms search_symbol`, borrows inferred from bindings with `ref` only in a result type, the list of faults the checker rejects, `with`-scoped task, worker and process groups, property testing with shrinking and `--fuzz`, a standard library written in Manuscript, and deterministic review output. Generic claims (static types, generics, a test runner) appear only as the setting for one of those. Capture every quoted diagnostic and example output from the built `ms`; a benchmark table shows slower rows beside wins and cites the dated section.

Apply when: revising the README, landing page, `why-manuscript`, or the vision's status section, or when a benchmark result is cited anywhere public.
Evidence: the user's October 27 marketing, tagline and agent-correctness corrections, request for an Astra pass, approved holistic outline, and requests for Rust ranges, memory design and the building process; [README](../../README.md), [measurements](../../README.md#fast-ordinary-code), [why Manuscript](../../documentation/learn/why-manuscript.md), [landing shortcode](../../website/layouts/_shortcodes/docs-home.html), [perf index](../../bench/perf/README.md).
Verify: independently ask whether a skeptical engineer can explain how the language helps an agent write correct, fast programs that are easy to review and has a reason to try it, then inspect desktop/mobile renders. Ask for outline approval before another structural rewrite when requested; implement only after that approval. Capture rather than invent example and tool output. Distinguish diagnostics that suggest a repair from those carrying machine-applicable edits. Check claims against dated results and the actual harness, not just a table caption; examples and exact commands must run, and documentation/repository checks must pass. Hold the requested editorial review before merging; a previous publication approval does not waive that checkpoint.

Verified: a result page can contain several revisions and reruns with different outcomes. The October 21 agent run passed 9/10 small challenges; the October 22 compact-guide run passed 10/10 and its terse rerun 9/10. The earliest HTTP table predates whole-file I/O offload, while the dated October 25 table includes a higher post-load memory cost. Cite the particular dated section and its tradeoffs rather than carrying an old explanation forward as current behavior. Evidence: [October 21](../../bench/agent/results/summary-2026-10-21.md), [October 22](../../bench/agent/results/summary-2026-10-22.md), [dated HTTP results](../../bench/perf/web/results.md#2026-10-25). Verify the prose against the whole cited section, including reruns and slower rows.
