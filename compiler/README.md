# compiler

`libms`, the Manuscript compiler as a C library, replacing the Rust crates one stage at a time. Plan: [plan section 5, "Compiler"](../proposals/c-runtime.md) and the workstream list in the project files. This folder holds the MIR (below), the front end (the lexer with the layout rules `src/lex.c`, the syntax tree `include/ms/ast.h`, the parser `src/parse.c`, diagnostic codes `src/diag.c`, editor recovery `src/partial.c`) and the start of the checker: the tables every pass reads (`types.c`, `tables.c`) the standard-library loader (`stdlib.c`), and the table-independent checks: diagnostic hints (`hints.c`, `import_hints.c`), constant folding and its certain faults (`constfold.c`), the syntax walker (`walk.c`), the machine-applicable fixes for diagnostics (`fixes.c`, `prelude_fix.c`), type substitution (`ty_subst.c`) and the finite-generic-application walk (`recursion.c`). The formatter is written in Manuscript over this library.

```
compiler/
  include/ms/   public headers: libms.h (entry points and the stage table), driver.h, base.h (arena, names, diagnostics), token.h, lex.h, ast.h, parse.h, diag.h, types.h, tables.h, stdlib.h, dump.h
  src/          one file per stage; libms.c includes them all, and building that one file builds the library
  tools/        ms (the thin executable over the driver), ms_syntax_dump: prints tokens and trees for the comparison below
  tests/        syntax-diff.sh, mutate.c, driver-test.sh, check-diff.sh, types_test.c
```

## Rules

- No global state. Every function takes the arena or table it works in; a failed parse leaves nothing to free except the arena, which is dropped whole.
- Allocation failure aborts. Errors in the lexer and parser unwind with `longjmp` to the entry point.
- Static helpers in different files must not share names, because `libms.c` is one translation unit.
- Positions, messages, fixes and token boundaries equal the Rust front end's, byte for byte. The comparison below is the contract until the Rust front end is deleted.

## Checking against Rust

`make c-compiler-test` (`compiler/tests/syntax-diff.sh`) builds `crates/ms-syntax/examples/c_oracle.rs` and the C dump tool with AddressSanitizer and UBSan, runs both on every `.ms` file in the repository and on mutated copies (`MS_FUZZ`, default 3000; `MS_FUZZ_SEED`), and compares the outputs with `cmp`. A mutant is a corpus file with a few bytes inserted, deleted or swapped for lexer-hostile pieces, so most of them end in a lexer error and every message is compared. The nightly run uses more mutants.

`src/unicode_debug.inc` is the table of scalars that Rust's `{:?}` escapes, which error messages quote; `tests/gen_debug_table.rs` regenerates it.

## MIR

`include/ms/mir.h`, `src/mir.c` (types, opcode table, module), `src/mir_print.c` and `src/mir_parse.c` port `crates/ms-mir` (`ir.rs`, `types.rs`, `print.rs`, `parse.rs`). Structures follow the Rust ones one to one, with the same numbering for the builtin types; ids are indices into flat arrays in the module's arena, and names are interned. `include/ms/mir_ops.def` is the opcode table, generated from `ops.rs`.

`sh compiler/tests/mir-diff.sh` (part of `make c-compiler-test`) compares the opcode tables, then the canonical text of every `.mir` file in the repository and of mutated copies, byte for byte with the Rust printer (`crates/ms-mir/examples/c_oracle.rs`). On rejected input only the error line is compared. The C parser differs from the Rust one in three ways: error messages do not quote tokens, non-ASCII outside string literals is rejected, and a stray token in a function header is an error (the Rust parser loops on it, so such mutants are dropped from the comparison).

`include/ms/mir_layout.h` and `src/mir_layout.c` hold the boxing decision (`MirBoxing`, `mir_alt_is_boxed`, `mir_opt_is_boxed`: which recursive alternatives and optionals live behind a pointer), compared with the Rust `Boxing` by `mir-diff.sh` on every `.mir` file and mutant. `include/ms/mir_analysis.h` and `src/mir_analysis.c` hold what every pass and the verifier read: operand and result ownership modes, terminator targets, predecessors, reverse post-order, dominators, value sets and block editing; `mir-diff.sh` compares them per function with the Rust `analysis` mode. `src/mir_shape.c` is `layout.rs`: leaves, memory layout, alternative payload slots, indirect type blocks, closure objects and the pointer and boolean leaf flags (`MirLayouts`), compared by `mir-diff.sh` the same way. A type nested too deep or with over a million leaves sets `MirLayouts.failed` and gets an empty shape; the Rust version overflows its stack there.

`src/mir_val.c`, `src/mir_interp_ops.c` and `src/mir_interp.c` (`include/ms/mir_interp.h`) are `interp.rs`: the reference interpreter, with reference-counted copy-on-write values. `mir-diff.sh` runs the entry of every `.mir` file in both and compares output, exit code or fault, frames, cleanup faults, and the drop and step counts. The C interpreter does not yet expand the owned shorthands (`alt.own`, ...) the Rust one expands on construction; such a module stops with an internal fault, and the comparison skips those modules until the expansion passes are ported. libms now calls `sqrt`, `floor` and friends, so programs linking it add `-lm`.

`include/ms/mir_verify.h`, `src/mir_verify.c` and `src/mir_verify_types.c` port the verifier: declarations, function shape, SSA dominance, the operand and result rules of each op (one rule per op in a table) and linear ownership. The comparison's `verify` mode prints every error as the Rust verifier does, over the repository's `.mir` files, `tests/mir/verify/` (one failing program per rule) and mutated copies; mutants that panic the Rust verifier are dropped. Not ported yet: the drop-glue functions the Rust verifier skips (`Module::drop_glue`, `glue_bodies`), which only exist once glue generation is ported.

`include/ms/lower.h` and `src/lower_body.c` start the lowering: the functions the checker's body pass claims (`body_checked`), lowered with the MIR builder when every construct is one the pass handles (`Int`, `Float` and `Bool` locals, returns, operators, short-circuit `and`/`or`, `String` concatenation). `tests/lower-diff.sh` lowers the fixtures in `tests/lower/` and the conformance corpus in both languages (`crates/ms-build/examples/c_lower_oracle.rs` prints the Rust side) and compares each function's text; the set grows with the checker's facts.

Next: the remaining optimisation passes one at a time, each checked by running both implementations on the same MIR text.

### MIR passes

`include/ms/mir_pass.h` declares the ownership and expansion passes and their shared helpers (`src/mir_pass.c`); each pass is one file, `src/mir_<name>.c`: `exit_drops`, `expand`, `expand_owned`, `cancel_edges` and `glue` so far (`glue` keeps what it made in a `MirGlue` table, where Rust keeps `drop_glue` and `addr_glue` on the module; `glue_expand` runs it with `expand_owned` until nothing new is wanted). The flags and closer lists that lowering sets are not in the text form, so the diff cannot reach `unwind_only` or `capture_closers`. A pass rewrites the module in place, builds what it adds in the module's arena and returns whether it changed anything. `mir-pass-diff.sh` runs every pass on the `.mir` files that parse and verify (the corpus and the mutants) in both implementations (`c_pass_oracle pass NAME`, `ms_mir_pass pass NAME`) and compares the printed module, a `changed` flag and the cold blocks byte for byte. To add a pass: write it, add its name to `run_pass` in both tools and to `PASSES` in `compiler/tests/mir-pass-diff.sh`.

## The checker tables

`MsTyTable` (`types.h`) is the one representation of checked types: a struct of arrays of interned type constructors, indexed by `MsTy`. Equal types share an index, so identity is an integer compare; type variables are never shared. `MsCheck` (`tables.h`) holds the type table, the symbol columns (name, identity text, kind, module, native binding, export flag, declaration, type, variable count) and one row per module with its scope. A pass adds columns beside these, indexed by the same ids. `ms_std_load` (`stdlib.h`) parses the bundled files, splits a file that mixes native operations with bodies into a native half and a `+source` half, and registers symbols as the Rust loader does. `compiler/tests/check-diff.sh` compares the result with `crates/ms-check/examples/c_oracle.rs` byte for byte. `ms_module_declare` (`check.h`) builds a module's top-level names (primitives, prelude, `@std/` imports, declarations) and its resolution diagnostics; the same script diffs them with `c_oracle --scope` over every conformance fixture. `ms_module_resolve_types` (`check.h`) then declares the module's types: type variables with defaults and bounds, nominal types, aliases and type sets, function signatures, fields and cases, and reports unknown types, arity errors and duplicates; the diff compares them with the Rust checker's symbol types and `type_refs`. Not yet ported: imports of project modules, the exact-source fix of a redundant prelude import and of a renamed standard module, constants, interface and implementation operations, `Self`, and the well-formedness check of type defaults. Files whose inherent `impl` fails to desugar are left out of the diff until the desugaring is ported. Later passes (types, interfaces, ownership, effects) add their own lines to that script.

## Effects

`effects.h` holds the two parts of the effect pass that need only source text and a reference graph: `effect_directives.c` reads `// ms: effect` and `// ms: allow_effect` lines and matches patterns, and `effect_reach.c` propagates declared effects through the graph and reports project callables that reach an effect no scope permits. `check-diff.sh` compares both with the Rust code (`c_oracle_effects.rs`) on every `.ms` file and on generated graphs (`effect_graph_gen.c`). Building the graph from checked code (the scan) comes when the typed-tree columns of `facts.h` exist.

`libms.h` has one entry point and one row in the stage table (`ms_stage_table_default`) per pipeline stage: parse, format, check, lower, emit, link, and the command's own tool logic. `driver.c` knows which stages each command needs. A command runs in C only when every stage it needs is in C; otherwise the whole command goes to the Rust `ms` (`$MS_RUST_CLI`, or `ms-rust` beside the executable), so the conformance corpus runs through the C `ms` from the first day and a command flips to C when its last stage lands. Stage data cannot cross between the two implementations, which is why the handover is per command. `MS_DRIVER_TRACE=1` prints the choice; `MS_STAGES=parse=rust` overrides a row for comparison runs. Porting a stage: add its entry point to `libms.h`, write it in `src/`, flip its row. `make c-driver-test` runs the unit tests and checks that `ms` in front of the Rust `ms` gives identical output and status.

## Tools over libms

Manuscript tools call libms through `compiler/tools/tool_shim.c`: `extern fn` declarations (`tools/repo-check/libms.ms`) and `make libms-tools`, which builds `target/libms_tools.a`; run a tool with `ms run tool.ms --link target/libms_tools.a`. The first entry point is `ms_tool_syntax_dump`, the canonical tree dump of `ms_syntax_dump ast` as a string. The shim includes only `ms_abi.h` because its names collide with libms's.
