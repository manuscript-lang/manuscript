# compiler

`libms`, the Manuscript compiler as a C library, replacing the Rust crates one stage at a time. Plan: [plan section 5, "Compiler"](../proposals/c-runtime.md) and the workstream list in the project files. This folder holds the MIR (below), the front end (the lexer with the layout rules `src/syntax/lex.c`, the syntax tree `include/ms/ast.h`, the parser `src/syntax/parse.c`, diagnostic codes `src/syntax/diag.c`, editor recovery `src/syntax/partial.c`) and the start of the checker: the tables every pass reads (`types.c`, `tables.c`) the standard-library loader (`stdlib.c`), and the table-independent checks: diagnostic hints (`hints.c`, `import_hints.c`), constant folding and its certain faults (`constfold.c`), the syntax walker (`walk.c`), the machine-applicable fixes for diagnostics (`fixes.c`, `prelude_fix.c`), type substitution (`ty_subst.c`), the finite-generic-application walk (`recursion.c`) and the type algebra the contract checks use (`ty_algebra.c`). The formatter is `src/format/`; its cases are `tests/format/` (`tests/format-golden.sh`).

```
compiler/
  include/ms/   public headers: libms.h (entry points and the stage table), driver.h, base.h (arena, names, diagnostics), token.h, lex.h, ast.h, parse.h, diag.h, types.h, tables.h, stdlib.h, dump.h
  src/          libms.c includes every file, and building that one file builds the library; folders: syntax/ (lexer, parser, folding, fixes), check/ (types, tables, checker, effects, lowering), own/ (ownership), mir/, opt/, emit/; includes are written relative to src/
  tools/        ms (the thin executable over the driver), ms_syntax_dump: prints tokens and trees for the comparison below
  tests/        syntax-diff.sh, mutate.c, driver-test.sh, check-diff.sh, types_test.c
```

## Rules

- No global state. Every function takes the arena or table it works in; a failed parse leaves nothing to free except the arena, which is dropped whole.
- Allocation failure aborts. Errors in the lexer and parser unwind with `longjmp` to the entry point.
- Static helpers in different files must not share names, because `libms.c` is one translation unit.
- Positions, messages, fixes and token boundaries equal the Rust front end's, byte for byte. The comparison below is the contract until the Rust front end is deleted.

## Checking against Rust

`make c-compiler-test` (`compiler/tests/syntax-diff.sh`) builds `crates/ms-syntax/examples/c_oracle.rs` and the C dump tool with AddressSanitizer and UBSan, runs both on every `.ms` file in the repository and on mutated copies (`MS_FUZZ`, default 3000; `MS_FUZZ_SEED`), and compares the outputs with `cmp`. A mutant is a corpus file with a few bytes inserted, deleted or swapped for lexer-hostile pieces, so most of them end in a lexer error and every message is compared. The nightly run uses more mutants.

`src/syntax/unicode_debug.inc` is the table of scalars that Rust's `{:?}` escapes, which error messages quote; `tests/gen_debug_table.rs` regenerates it.

## MIR

`include/ms/mir.h`, `src/mir/mir.c` (types, opcode table, module), `src/mir/mir_print.c` and `src/mir/mir_parse.c` port `crates/ms-mir` (`ir.rs`, `types.rs`, `print.rs`, `parse.rs`). Structures follow the Rust ones one to one, with the same numbering for the builtin types; ids are indices into flat arrays in the module's arena, and names are interned. `include/ms/mir_ops.def` is the opcode table, generated from `ops.rs`.

`sh compiler/tests/mir-diff.sh` (part of `make c-compiler-test`) compares the opcode tables, then the canonical text of every `.mir` file in the repository and of mutated copies, byte for byte with the Rust printer (`crates/ms-mir/examples/c_oracle.rs`). On rejected input only the error line is compared. The C parser differs from the Rust one in three ways: error messages do not quote tokens, non-ASCII outside string literals is rejected, and a stray token in a function header is an error (the Rust parser loops on it, so such mutants are dropped from the comparison).

`include/ms/mir_layout.h` and `src/mir/mir_layout.c` hold the boxing decision (`MirBoxing`, `mir_alt_is_boxed`, `mir_opt_is_boxed`: which recursive alternatives and optionals live behind a pointer), compared with the Rust `Boxing` by `mir-diff.sh` on every `.mir` file and mutant. `include/ms/mir_analysis.h` and `src/mir/mir_analysis.c` hold what every pass and the verifier read: operand and result ownership modes, terminator targets, predecessors, reverse post-order, dominators, value sets and block editing; `mir-diff.sh` compares them per function with the Rust `analysis` mode. `src/mir/mir_shape.c` is `layout.rs`: leaves, memory layout, alternative payload slots, indirect type blocks, closure objects and the pointer and boolean leaf flags (`MirLayouts`), compared by `mir-diff.sh` the same way. A type nested too deep or with over a million leaves sets `MirLayouts.failed` and gets an empty shape; the Rust version overflows its stack there.

`src/mir/mir_val.c`, `src/mir/mir_interp_ops.c` and `src/mir/mir_interp.c` (`include/ms/mir_interp.h`) are `interp.rs`: the reference interpreter, with reference-counted copy-on-write values. `mir-diff.sh` runs the entry of every `.mir` file in both and compares output, exit code or fault, frames, cleanup faults, and the drop and step counts. The C interpreter does not yet expand the owned shorthands (`alt.own`, ...) the Rust one expands on construction; such a module stops with an internal fault, and the comparison skips those modules until the expansion passes are ported. libms now calls `sqrt`, `floor` and friends, so programs linking it add `-lm`.

`include/ms/mir_verify.h`, `src/mir/mir_verify.c` and `src/mir/mir_verify_types.c` port the verifier: declarations, function shape, SSA dominance, the operand and result rules of each op (one rule per op in a table) and linear ownership. The comparison's `verify` mode prints every error as the Rust verifier does, over the repository's `.mir` files, `tests/mir/verify/` (one failing program per rule) and mutated copies; mutants that panic the Rust verifier are dropped. Not ported yet: the drop-glue functions the Rust verifier skips (`Module::drop_glue`, `glue_bodies`), which only exist once glue generation is ported.

`include/ms/lower.h` and `src/check/lower_body.c` start the lowering: the functions the checker's body pass claims (`body_checked`), lowered with the MIR builder when every construct is one the pass handles (`Int`, `Float` and `Bool` locals, returns, operators, short-circuit `and`/`or`, `if`, `while`, `match` over literals, `String` concatenation). `tests/lower-diff.sh` lowers the fixtures in `tests/lower/` and the conformance corpus in both languages (`crates/ms-build/examples/c_lower_oracle.rs` prints the Rust side), compares each function's text, and verifies every lowered function. Where C deliberately differs (a `while` keeps a parameter as one value; a `match` is one `switch` or `br_if`, not a chain of tests) it runs both modules over sample arguments and compares the results instead. The set grows with the checker's facts.

Next: the remaining optimisation passes one at a time, each checked by running both implementations on the same MIR text.

### MIR passes

`include/ms/mir_pass.h` declares the ownership and expansion passes and their shared helpers (`src/mir/mir_pass.c`); each pass is one file, `src/mir/mir_<name>.c`: `exit_drops`, `expand`, `expand_owned`, `unwind` (`src/mir/mir_unwind*.c`, with `src/mir/mir_persist.c` for the persistent owner sets and position maps), `elaborate` (`src/mir_elaborate*.c`: the move-state dataflow, the block emitter and the scope-end cleanup; it returns `false` with a `function: message` error where Rust returns `Err`, and `tests/mir/elaborate/` holds the Raw programs of the Rust elaborate tests, which the diff runs whole because they only verify after elaboration), with `mir_elaborate_with(m, true, ..)` it also builds explicit cancel exits (`mir_elaborate_cancel.c`, `_sites.c`, `_convert.c`: the port of `cancel_exit.rs`; the diff pass `elaborate-cancel` runs `tests/mir/elaborate-cancel/` and the elaborate programs made task programs), `depth` (`src/mir/mir_depth.c`; `tests/mir/depth/`), `cancel_edges` and `glue` so far (`glue` keeps what it made in a `MirGlue` table, where Rust keeps `drop_glue` and `addr_glue` on the module; `glue_expand` runs it with `expand_owned` until nothing new is wanted). `explicit_cancel`, `noalias(..)`, `slot_result(@f)` and `close_exit(@a, @b)` are in the text form of a function header. The flags and closer lists that lowering sets are not in it, so the diff cannot reach `unwind_only`, `capture_closers`, `raw_scratch` or `slot_close` (`tests/mir/unwind/` holds the programs of the Rust unwind tests). A pass rewrites the module in place, builds what it adds in the module's arena and returns whether it changed anything. `mir-pass-diff.sh` runs every pass on the `.mir` files that parse and verify (the corpus and the mutants) in both implementations (`c_pass_oracle pass NAME`, `ms_mir_pass pass NAME`) and compares the printed module, a `changed` flag and the cold blocks byte for byte. To add a pass: write it, add its name to `run_pass` in both tools and to `PASSES` in `compiler/tests/mir-pass-diff.sh`.

## Building through the C pipeline

`MS_BACKEND=c ms build ...` (crates/ms-build `c_backend.rs`) prints the lowered module as MIR text and hands it to libms in process (`include/ms/emit_program.h`, `src/emit/emit_program.c`; `ms-build`'s build script builds the CMake target `ms_backend` and links it): `ms_backend_ir` runs `mir_optimize`, `mir_pipeline_finish` and the LLVM emitter (Debug and Release) and returns the IR with the functions and inlined scopes of the module (the meta). The pinned LLVM tools write assembly from the IR (`opt` for Release, then `llc`); `ms_backend_tables` (`src/mir/mir_asm_tables.c`) labels every `.loc` in it (the emitter's debug locations carry the line and scope) and appends the fault tables as data whose addresses are those labels, so the assembler and linker fill them in and no debug info is read (`compiler/tests/asm-tables.sh`). The pinned tools have no assembler, so the result is wrapped as an IR module of `module asm` lines, which `llc` assembles; it links with the real runtime. No C compiler and no helper program runs. `ms_mir_build` and `ms_asm_tables` (`compiler/tools/`) are the same two calls as tools, for the tests. A program the emitters cannot write fails with their reason and does not fall back to Cranelift. `sh compiler/tests/build-diff.sh [LIMIT]` builds the `phase=run` corpus both ways, runs both executables, compares output and status, and prints a census of the emitter's reasons: the list of gaps. The C MIR reader accepts generic type names (`Result[Void, Error]`), which the Rust printer writes and the Rust reader does not read; the printer gives a second function of the same name (`main` and the exported entry) a `.1` suffix so the text parses.

## LLVM emitter

`include/ms/emit_llvm.h` and `src/emit/emit_llvm.c` write LLVM IR text from MIR for debug and release builds (the Rust `ms-mir-llvm` is the one they replace). They are written in C's own terms (flat buffers, tables of leaf kinds), not as a copy of the Rust builders. Contract: `compiler/tests/llvm-run.sh` (part of `make c-compiler-test`) compiles the programs in `tests/run/`, `tests/llvm/` and `tests/llvm-only/` with clang, runs them and compares exit statuses. Static data (descriptors, vtables, globals) comes from `mir_data` (`include/ms/mir_data.h`), the table of static data; `mir_emit_llvm` takes it and prints the definitions and the `typedesc` and `global.get`/`global.set` operations. No text comparison with the Rust output: its metadata numbering is incidental.

## The checker tables

`MsTyTable` (`types.h`) is the one representation of checked types: a struct of arrays of interned type constructors, indexed by `MsTy`. Equal types share an index, so identity is an integer compare; type variables are never shared. `MsCheck` (`tables.h`) holds the type table, the symbol columns (name, identity text, kind, module, native binding, export flag, declaration, type, variable count) and one row per module with its scope. A pass adds columns beside these, indexed by the same ids. `ms_std_load` (`stdlib.h`) parses the bundled files, splits a file that mixes native operations with bodies into a native half and a `+source` half, and registers symbols as the Rust loader does. `compiler/tests/check-diff.sh` compares the result with `crates/ms-check/examples/c_oracle.rs` byte for byte. `ms_module_declare` (`check.h`) builds a module's top-level names (primitives, prelude, `@std/` imports, declarations) and its resolution diagnostics; the same script diffs them with `c_oracle --scope` over every conformance fixture. `ms_module_resolve_types` (`check.h`) then declares the module's types: type variables with defaults and bounds, nominal types, aliases and type sets, function signatures, fields and cases, and reports unknown types, arity errors and duplicates; the diff compares them with the Rust checker's symbol types and `type_refs`. Not yet ported: imports of project modules, the exact-source fix of a redundant prelude import and of a renamed standard module, constants, interface and implementation operations, `Self`, and the well-formedness check of type defaults. Later passes (types, interfaces, ownership, effects) add their own lines to that script.

## Effects

`effects.h` holds the two parts of the effect pass that need only source text and a reference graph: `effect_directives.c` reads `// ms: effect` and `// ms: allow_effect` lines and matches patterns, and `effect_reach.c` propagates declared effects through the graph and reports project callables that reach an effect no scope permits. `check-diff.sh` compares both with the Rust code (`c_oracle_effects.rs`) on every `.ms` file and on generated graphs (`effect_graph_gen.c`). Building the graph from checked code (the scan) comes when the typed-tree columns of `facts.h` exist.

## Desugaring

`desugar.h` prepares a module before its declarations are entered in the tables: it expands an impl on a set alias into one per member, adds the `// ms: data` marker impls of bundled types, and reports misused `impl Type:` blocks (unknown or interface receiver, wrong arity, overlapping forms). The blocks themselves stay as written; a type's methods attach to the type through `impls.c`, which adds method rows keyed by the receiver with no synthesized interface and no merge (`methods.h` holds interface operations and the method table). `ms_module_desugar` runs the pass on a module row. `ast_copy.c` copies a method with fresh node ids for set expansion. `check-diff.sh` compares declarations, node ids and errors with `passes::desugar_inherent_impls` (`c_oracle_desugar.rs`) and the operations and method rows with `c_oracle_methods.rs`; the intended differences are in `check-divergences.txt`.

`libms.h` has one entry point and one row in the stage table (`ms_stage_table_default`) per pipeline stage: parse, format, check, lower, emit, link, and the command's own tool logic. `driver.c` knows which stages each command needs. A command runs in C only when every stage it needs is in C; otherwise the whole command goes to the Rust `ms` (`$MS_RUST_CLI`, or `ms-rust` beside the executable), so the conformance corpus runs through the C `ms` from the first day and a command flips to C when its last stage lands. Stage data cannot cross between the two implementations, which is why the handover is per command. `MS_DRIVER_TRACE=1` prints the choice; `MS_STAGES=parse=rust` overrides a row for comparison runs. Porting a stage: add its entry point to `libms.h`, write it in `src/`, flip its row. `make c-driver-test` runs the unit tests and checks that `ms` in front of the Rust `ms` gives identical output and status.

## Tools over libms

Manuscript tools call libms through `compiler/tools/tool_shim.c`: `extern fn` declarations (`tools/repo-check/libms.ms`) and `make libms-tools`, which builds `target/libms_tools.a`; run a tool with `ms run tool.ms --link target/libms_tools.a`. The first entry point is `ms_tool_syntax_dump`, the canonical tree dump of `ms_syntax_dump ast` as a string. The shim includes only `ms_abi.h` because its names collide with libms's.

## Driver and stages

`libms.h` has one entry point and one row in the stage table (`ms_stage_impl`) per pipeline stage: parse, format, check, lower, emit, link, and the command's own tool logic. `driver.c` knows which stages each command needs. A command runs in C only when every stage it needs is in C; otherwise the whole command goes to the Rust `ms` (`$MS_RUST_CLI`, or `ms-rust` beside the executable), so the conformance corpus runs through the C `ms` from the first day and a command flips to C when its last stage lands. Stage data cannot cross between the two implementations, which is why the handover is per command. `MS_DRIVER_TRACE=1` prints the choice; `MS_STAGES=parse=rust` overrides a row for comparison runs. Porting a stage: add its entry point to `libms.h`, write it in `src/`, flip its row. `make c-driver-test` runs the unit tests and checks that `ms` in front of the Rust `ms` gives identical output and status.

A command's own logic can be in C one command at a time: `c_commands` in `driver.c` lists the commands with a C entry (`include/ms/cmd.h`), and a listed command runs there when the other stages it needs are in C. A C command that meets a request it does not cover returns `MS_CMD_HANDOVER` before it prints anything, and the driver hands the command line to the Rust `ms`. `ms check FILE.ms [--json]` (`src/check_cmd.c`) is the first: it loads the file and its project modules, runs the checker passes (names, types, bodies, ownership, unused bindings) and prints `Checked FILE` or the empty `--json` document; every diagnostic, every function or declaration no C pass covers, and every feature in `check_unported` (a check with no C port yet: generics, externs, entry signatures, field defaults, prelude imports, public-signature exposure) is a handover. `tests/check-cmd-diff.sh` runs the C driver (`MS_STAGES=check=c`) and the Rust `ms` over the conformance fixtures in text and `--json` mode, requires identical output and status, and prints how many files the C command served and why it handed over the rest; a port removes its `check_unported` entry only when that script shows no difference. The Manuscript front (`tools/ms/check_run.ms`) calls the same code through `ms_tool_check` (`include/ms/tool.h`, `src/tool_check.c`, linked with the embedded standard library only into programs that call it) and runs the Rust command when it gets status 2.

## Ownership

`include/ms/ownership.h` and `src/ownership_*.c` are the C port of `crates/ms-check/src/ownership`: places and binding sets, value classes (`ownership_class.c`), liveness (`ownership_live.c`) and the walk that reports moves and borrows (`ownership_walk.c`). `ms_module_check_ownership` runs after `ms_module_check_bodies` and handles the functions whose bodies the checker accepted; a function with a construct the walk does not know yet has its `body_checked` flag cleared and stays with the Rust checker. `check-diff.sh` compares the diagnostics inside every handled function with the Rust checker's (`c_oracle --ownership`) on `compiler/tests/ownership` and the corpus; the set of handled constructs grows with the checker's.

## Building

The C compiler builds with the repository CMake project (`CMakeLists.txt`, `cmake/MsCompiler.cmake`), generated with Ninja and cached with ccache when it is installed. `make c-configure c-build` builds every tool and unit test into `target/cmake/test/compiler/` with the sanitizers on (`ctest -L compiler` runs the unit tests); the `*-diff.sh` scripts build the tools they need through `compiler/tests/cbuild.sh`. A new `compiler/tools/ms_<name>.c` becomes the target `ms_<name>` by glob; a new unit test needs a line in `cmake/MsCompiler.cmake`. `make libms-tools` and `make target/c-tool/libmstool.a` build the archives Manuscript tools link with `--link` (`MS_BUILD_RUNTIME=OFF`, so no runtime libraries are needed).
