# Manuscript observations while writing c21-c35

- Top-level `let` constants are not allowed ("top level holds only import, fn, type, ..."); use a zero-arg `fn` returning the constant.
- `"{"` inside a string literal starts interpolation; literal braces need `\{` and `\}` (bit c27, c33).
- `List.concat(x)` returns a new list (does not mutate); `List` has no `clear()` (Map and Set do). Reassign `var l = List[T]()` instead.
- `String.split(sep, max_parts)` truncates (drops the remainder) rather than keeping the rest in the last part; hand-roll an "at most N parts" split with `index_of` (c34).
- `String.replace` replaces only the first occurrence; use `replace_all(old:, new:)` (returns Result).
- `trim()` strips all Unicode whitespace; "spaces and tabs only" trimming has to be written by hand.
- `repeat`, `pad_start`, `pad_end`, `replace_all` return Result, so `.get()` is needed.
- No performance problems seen: all hidden cases (up to ~6000 commands/lines, 30000-scalar inputs) run well under 1 s; `PriorityQueue` keeps FIFO order for equal priorities as documented.
- No compiler bugs hit.
- Mid-task the `ms` binary/stdlib changed (#306): `String.slice`, `List.slice` now return `Result[..., OutOfRange]` and no longer clamp, and `String.substring` is gone. All ms references were updated with `.get()` (c30 `word` got an explicit bounds check). Earlier-written solutions that rely on clamping slices will fault.
