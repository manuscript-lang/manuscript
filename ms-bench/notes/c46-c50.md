# Manuscript observations while writing c46-c50

All five reference solutions build with the repo-root `ms` and pass `run.py oracle`. Limitations and
surprises hit while writing them:

- Match arms cannot contain a standalone `try expr` statement: `ms check` reports
  `parse: an arm value must be its final expression` (the same code works at function level). Arm bodies that
  need `try` have to move into helper functions (c46 `check_unary`, `check_if`, `check_let`).
- A one-line arm after `let x = match ...:` cannot be `error(f): return ...`; it must be written as an
  indented block (`error(f):` then `return ...`).
- `try expr` as a statement requires the success type to be `Unit`. A parser helper such as
  `expect(kind) -> Result[Tok, E]` cannot be called as a bare `try expect(...)`; split it into a `Unit`-returning
  `expect` and a value-returning variant (c46 `expect` / `expect_id`).
- Patterns cannot be nested, so rule tables over recursive variants (c47 simplifier) need accessor helpers
  (`neg_inner`, `pow_parts`, `sub_parts` returning `Optional[...]`) in place of the nested patterns other
  languages use. Structural `==` on recursive alternatives works and made `l == r` rules trivial.
- Constructing an empty typed list/map works as `List[T]()` / `Map[K, V]()`; an explicit
  `Result[T, E].error(...)` constructor is needed to initialise a `var` of Result type.
- `String.parse_int()` is not used directly on untrusted tokens in these solutions because its accepted forms
  (signs, leading zeros) differ from the specs; each solution validates the shape with `scalar_values()` first.
- No in-place mutable list/map cell access beyond `set`/`add`; the worker-pool simulation (c48) keeps worker
  state in a `List` of mutable records (`Worker`) rather than a list of optionals, which is also the only
  ergonomic way to update fields in place.
- Int arithmetic is checked (faults on overflow), so c49 limits input magnitudes in the spec so every
  product stays in 64-bit; TypeScript needs `BigInt` for the same task while Go/Rust use `int64`/`i64`.
