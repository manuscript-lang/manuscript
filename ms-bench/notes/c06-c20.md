# Manuscript observations from c06-c20

Short notes from writing the ms reference solutions. No blocking compiler bugs were found.

- `from` and `unit` are reserved words: `let from = 2` and `let unit = 3` fail to parse. Rename (`radix_in`, `unit_price`).
- `continue` cannot be a match arm value ("an arm value must be its final expression"). Repro:
  `match r: ok(v): use(v) / error(_): continue`. Workaround: `let r = ...` then `if r.is_error: continue`.
- Callback parameter names must match the expected function type: `sorted(compare: fn(a: String, b: String) -> Int: ...)`
  is rejected; use `left` / `right`.
- String literal braces must be escaped as `\{` `\}`; a bare `{` starts interpolation.
- `String.slice(...)` returns a Result (and `substring` was removed): append `.unwrap()` when bounds are known valid.
- `List[Int]` has no `join`; build the string with a loop or map to strings first.
- Map operations are slow compared to the other languages; keep per-case map operations under roughly 30k
  (c19 and c20 index bookings in a List and keep Map use per command small).
- `split(",")` keeps empty fields (`"a,,b"` gives 3 parts, trailing `","` gives a final empty part); handy for CSV row validation.
- Reference-typed records (`type X:` instances) can be mutated through any alias (`o.status = ...`), which makes
  order-book / booking state machines straightforward.
