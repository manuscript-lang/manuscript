## Principle

Each stage consumes the previous stage's output and erases the concepts it owns, so a later stage never sees or re-decides them. Crates are already layered and enforced (`ms-repo-check` `layering.rs`); the language stages inside them are not. The checker is the single source of ownership decisions; lowering reads them and decides only by monomorphic type class.

## Problem

- Typecheck to lowering is a working boundary: per-node `Info` read through `ModuleHir`. Two leaks: native identity is partly string-keyed (`Native` is an enum, but `ms-lower` has 58 `Native::`/`native.is`/`native_str` sites, 2 of them `native_str`; the audit's N5 and N7 list the string forms; count by `grep -rnE 'native\.is\(|native_str|Native::' crates/ms-lower/src`), and the `none` default is found by spelling.
- Ownership is the broken boundary. `Program` holds type-check results plus nine ownership tables filled in afterwards by `check_in`; `Cx` copies them field by field. The ownership stage is incomplete, so lowering finishes it: `mutation.rs::infer_mutated` (about 60 lines plus a 90-line scan in a 529-line file: a second interprogram fixpoint over which parameters change; its result `cx.mutated` feeds about 10 lowering sites that decide slotting and own-copy per local), `only_read_in_place`/`split_read_in_place`/`trim_view` (view safety by method name), `FnLower`'s private lattice (`Val.own`, `views`, `boundary_reads`), and `owned()`/`copy_gaps` (clone a borrow when the facts did not decide). `copyelim` and `copies.rs` in `ms-mir` then repair or report what lowering did.
- Modes are shared vocabulary (`ParamMode` Borrow/Mutate/Move; MIR `Mode` Borrow/Move/Var) but lowering reads `ParamMode` once (`closure.rs`). Native operations are decided twice by name: `ownership/modes.rs` (`native_method_modes`, `collection_mutation`) and `ms-lower/native/*.rs`.
- Clonable is decided twice: `contracts.rs:866` and `ownership::Classifier::clonable` (comments say they must agree); resource class is held by `contracts.rs::holds_resource` and `Classifier`. `ms-lower` `is_resource` already calls `Classifier`, and `ms-mir` `needs_drop` is a storage question.
- `check_module` and `check_group` write the declaration passes twice (#3498, #3501 were pass-order bugs).
- Related bugs, cause partly inferred: "implicit copies of a borrow" ICEs #2649, #2667, #2920, #2943, #3144, #3164, #3218; double close or leak per call form #3075, #3078, #3086, #2883.

## Target stages and IRs

Three IRs, no more: AST; typed HIR (AST plus `Info` through `ModuleHir` plus one `OwnershipFacts` value); MIR (monomorphic SSA). HIR is a view over the tree and fact tables, not a materialised tree (`hir.rs`), so any CFG-HIR is a new IR, and tooling (21 files, about 8.9k lines in `ms-tooling` and `ms-lsp`, plus `effects`, `recursion`, `constfaults`, `unused`) keeps tree plus `Info` permanently, with ownership facts keyed by binding uid and `(file, NodeId)`.

| # | Stage | Erases | Next stage may rely on |
| --- | --- | --- | --- |
| 1 | parse | layout | one tree, stable `NodeId`s |
| 2 | resolve | imports, aliases, prelude | every name is a symbol or local; no string identity |
| 3 | typecheck | inference, overloads, impl selection, labels, defaults, `T?` wrapping; conversions marked | one callee per call for concrete receivers (bound-method calls in generic bodies resolve at monomorphization, per evidence module), positional arguments, native identity as an enum |
| 4 | analyses | effects, recursion, const faults | diagnostics only; today `ms-lower` reads `api::effects::{collection_mutation, is_text_builder, discards_entries}` (10 sites), which are standard-operation vocabulary shared by the effect scan and the ownership walk; they now live in the foundation module `std_ops` and `ms-lower` reads them through `api::ownership` |
| 5 | ownership (HIR walk) | borrow, move, mutation, capture modes, close method, resource class | `OwnershipFacts`: the only judge of legality and the only source of user ownership diagnostics |
| 6 | lower | generics, closures, `try`/match/loops, borrows into views, interface types into data plus vtable | monomorphic MIR; consumes facts and decides only by monomorphic type class (see invariant) |
| 7-9 | MIR opt, unwind, codegen | late copies and drops; cancellation release; layout and glue | verifier holds |

Interfaces cross several stages, each erasing one part: typecheck selects the impl and marks the conversion (`Info.interface_source`); ownership decides its mode (`iface.borrow` view, stored move, `contract_mutates`, resource only into an interface with `close`); lowering erases the source type into `{data, vtable}` and builds vtables; MIR keeps `iface.new/borrow/view` because the vtable tag records ownership for the verifier; codegen erases them to a pointer pair. Exceptions: `natiface.rs` hand-lowers `HttpExchange` and `FileSystem.glob`, and impl-versus-interface mode agreement is unchecked (`OWNERSHIP.md`, Limits).

**Generics invariant.** Facts are keyed `(file, NodeId)` once per generic body and are instance-independent. Lowering may specialize only by monomorphic type class (`needs_drop`, has-closer, `Opt` layout, view versus value, `concretely_clonable`, owned-boundary copy, evidence scope), through one named function; it never changes a mode, move, borrow or view the facts state. Guard: that function is the only reader of type class in `ms-lower`, and the ownership-count tests run generic fixtures at two instances (unverified: default-argument expressions lowered at the caller under the callee's `NodeId`s).

**Rule for a new IR or layer** (all three, with evidence in its proposal): (1) a named concept cannot be erased in an existing IR without an invariant its verifier cannot state; (2) two consumers need it, or it deletes more lines than it adds, measured; (3) it has one producer, one verifier and a text form, and an existing representation is deleted in the same PR. A stricter verifier phase on an existing IR is always preferred.

## Steps, each gated on evidence

1. **Guard (built locally).** `repo-check` `stages.rs`: stage table for `ms-check`, five shrink-only back-edges; `types` no longer names `hints` or `stdlib`. Extend later with an `ms-lower` table (only `cx.rs` names `api::ownership`; `mutation.rs` on a shrink list; no string identity) and an `ms-mir` pass table (input and output phase).
2. **Native contracts and facts first.** Derive native operation modes from stdlib declarations (scope per `ownership-facts-layering-proposal-2026-11-08` after its skeptic review: `wrapper_passthrough` and `discards_entries` first, `api::effects` vocabulary is already moved to `std_ops`), so later facts are not added on top of name lists.
3. **Replace `infer_mutated`.** 3a: parameter set to `ParamMode::Mutate`; evidence: dump what it adds beyond declared `var` over the corpus (including `aliasing`-tagged fixtures) and bundled stdlib bodies; empty or native handles only means delete. 3b: its per-local uses (`mutated_locals`, `changing_method_roots`, `method_changes_receiver`) become a per-binding `BindingFlags` fact, or are kept as a documented storage decision.
   3c. **Make `owned()` total.** Evidence: classify `copy_gaps` sites (`MS_COPY_PROBE=strict`, corpus, the ICE issues; `copy_gaps` records the producing op and caller line, so cause is assigned by hand) by whether a fact keyed by `NodeId`, independent of path and instance, fixes it. Add one checker fact per such cause (as `OwnedBorrow` did); move `split`/`trim` view decisions into `NodeFacts`. Promoting the copy check to a verifier rule turns latent gaps into user-visible ICEs, so it lands only after the count is zero on the corpus.
4. **One `OwnershipFacts`** replaces the nine `Program` fields; impl-versus-interface mode agreement is checked (a vtable call with a mismatched mode is the double-close class); one declaration-pass driver for `check_module`/`check_group`; one clonable rule shared by `contracts` and `Classifier`.
   **4b. Drop plan on the tree.** The ownership walk gains a forward may/must-moved pass (the Limits entry "moved-on-every-path is not tracked forward") and emits `ExitDrops: (exit key, value key) -> Drop | DropIfNotMoved | DropRest | ClosedOnPath | None`. Exit key: a statement or expression `NodeId` (`try`, `break`, `continue`, `return`) or `(owner NodeId, block role)` for fallthrough scope end (blocks are `Vec<Stmt>` with no id). Value key: a binding uid or `(producing NodeId, role)` for values with no node of their own (Optional wraps, interface-conversion views, `OwnedBorrow::Clone` copies, pending list-element and record-field copies, default arguments lowered at the caller). `DropRest` covers the early exit of a consuming `for` (`list_iters`); `ClosedOnPath` covers `closed_on_path`, `rest_closers`, `hidden_closers` and split release. Evaluation order and temporary holding across a later `try` become one checker fact that lowering consumes (see `call-argument-staging.md`); it is never computed twice. Cancellation is not an exit key: `ms-mir` `unwind` stays and consumes plan liveness. Lowering emits drops from the plan and filters only by monomorphic type class (a Copy or no-drop instance erases the obligation; a resource instance becomes a closer call; the drop flag's representation stays a layout choice), so `Val.own` and the scope-drop logic in `func.rs` (`drop_scope_locals`, `unwind_to`, `pop_scope`) and `stmt.rs` shrink. One producer, no new IR, analysed once per generic body. Prototype the mid-expression-temporaries case first (partial arguments built before a later `try`), since it decides whether 4b works or triggers 5(iii). Gates: `tests/ownership-counts` and the resource matrix unchanged; resource-matrix rows exist first for each hard case (mid-expression `try`, `try` in a loop condition, `break`/`continue` out of nested arms, moved-in-one-branch at a back edge, early exit of a consuming `for`); structural gate: `Val.own`, `closed_on_path` and `scope_done` deleted or on a shrink-only list, with a debug assertion that the drops lowering emits equal the plan per exit; `ms check` at N/2N/4N regresses by no more than a threshold set beforehand. Prerequisite: impl-versus-interface mode agreement (step 4) with a two-instance bound-method fixture, because bound-method calls in generic bodies resolve at monomorphization.
5. **Decision after 4b, three ways, thresholds set before measuring.** (i) Stop if zero resource-matrix rows fail on `try`, loop or cancel edges and `copy_gaps` is zero. (ii) Build Raw/Elaborated phases on monomorphic MIR (lowering emits moves, borrows, call modes and scope markers; the Raw verifier asserts modes equal `OwnershipFacts`; one `elaborate` pass places drops; `lastuse` and `copyelim` stay optimizations) if the residual causes are per-instance (layout or closer-dependent placement). (iii) Classifier: a residual cause is (iii) only if it is not expressible as `(exit key, value key)` under the fixed evaluation order; otherwise it is (ii) if per-instance. Take a CFG-HIR (generic, typed, non-SSA, built after typecheck, keeping `NodeId` and binding identity, replacing both the ownership walk (8.3k lines, 74 diagnostic sites) and the tree-walking half of lowering (about 13k of 26.6k lines) in one PR series, shadow diffs test-only) only if the residual causes are edges no `NodeId` can name, such as mid-expression `try` with partially evaluated arguments or evaluation-order temporaries. A CFG-HIR must cite: fixpoint walk time saved by CFG reuse, LSP check latency, and the diagnostic diff over the corpus. A shipped shadow would be a second producer of the same facts, so it is never merged as a second path. `lastuse` moves drops after `inline`, so MIR does not decide nothing: it is a verifier-checked optimization of the plan. Cancellation release (`unwind`) stays in MIR; whether cancel edges can be expressed in HIR is unverified.

Every step is behavior-preserving: `make verify`, conformance corpus, `tests/ownership-counts`, resource matrix; steps 3 and 5 cite `bench/perf`; every step times `ms check` at N/2N/4N before and after.

## What this gives up

- Ownership is judged on HIR and elaborated per instance on MIR, so a mode summary must agree between them; the Raw verifier checks it against `OwnershipFacts`.
- No analysis of generic bodies once on a CFG (see Not doing).
- Elaboration failures are internal errors, deduplicated by `Inst.loc`, never user diagnostics.
- More facts add to the checker's ownership fixpoint (`callables + 16` rounds) and to LSP latency; measure `ms check` at N/2N/4N per step.
- Interface payload copies through `Tap`-style middleware stay runtime-guarded and `natiface.rs` stays outside the facts until its question below is settled.

## Not doing

- **Generic MIR (Rust style) and an analysis-only CFG that leaves lowering on the tree** (second producer, fourth representation). Review of the code (not timed; no `ms` binary built): MIR has no type-parameter variant (`ms-mir/src/types.rs`, `cx.rs:581` errors on an unsubstituted variable); layout (`Opt` of scalars versus an alternative, `Local.opt`) is chosen during type lowering; about 69% of `ms-lower` (`close.rs`, `closure.rs`, `func.rs`, `stmt`, `call`, `native/*`) interleaves emission with concrete-type queries and about 27% only synthesizes monomorphic code, so a generic emitter plus a specializer would redo most of it; it needs a second op set and verifier level, which fails the IR rule; `ms-lsp` and `ms-driver` depend only on `ms-check`, and building MIR per check covers bundled stdlib bodies; retiring the 8.3k-line ownership walk means reproducing lexical-borrow, NodeId- and binding-keyed diagnostics on an SSA substrate that erases binding identity. Trigger to revisit: per-instance elaboration measured above a set share of compile time, or a bug class that only an all-instances-once analysis can catch.
- Ownership diagnostics from monomorphic MIR.
- Splitting `ms-check` into crates; moving drop placement out of `lastuse` before step 5's measurement; lowering optionals or interfaces before MIR.
- Doing nothing: the resource matrix finds these per row after the fact; each new call form adds rows.
