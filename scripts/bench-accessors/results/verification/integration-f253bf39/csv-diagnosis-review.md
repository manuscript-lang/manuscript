# Independent CSV timeout diagnosis review

The proposed mechanism is sound against the pinned Go **1.25.1** source. It explains a possible coordinator-level `context deadline exceeded` failure at the normal fuzz budget. It does **not** establish that this mechanism caused CI run 38648209971, and the available retries do not establish a fix or justify calling the failure flaky.

Source trace independently checked:

1. `internal/fuzz/fuzz.go:105–114` derives a timeout `ctx`, then a child `fuzzCtx = context.WithCancel(ctx)`, while selecting on the parent's `ctx.Done()`.
2. `context/context.go:559–570` stores the parent's error and closes its Done channel before cancelling children. `cancelCtx.Err` at 463–468 is an atomic load rather than an acquisition of the parent's mutex. Consequently another goroutine can observe the closed parent Done channel and parent DeadlineExceeded while the child still reports nil. Even with only one child, scheduling between close and propagation permits the ordering; the model's 10000 siblings substantially widen that interval and do not represent the coordinator's actual child population.
3. On parent completion, `internal/fuzz/fuzz.go:225–228` calls `stop(ctx.Err())`. At 129, stop suppresses only equality with `fuzzCtx.Err()` (or an interrupt error). If the child still reports nil, DeadlineExceeded survives, is saved into `fuzzErr` at 135–136, and `cancelWorkers()` then runs at 142. Later cancellation of the child does not itself clear the saved error. The worker-stop path normally sends nil and stop(nil) also leaves that saved error intact. When the last worker terminates, 235 returns it. This is a timing-sensitive control-flow gap, not an unsynchronized Go memory access.
4. `testing/internal/testdeps/deps.go:152–169` supplies an outer signal.NotifyContext over Background and suppresses errors only if they equal that outer context's Err. Without an interrupt, the outer Err remains nil: the inner fuzz deadline is not its deadline. Thus a retained DeadlineExceeded can propagate to testing, whose `testing/fuzz.go:368–377` reports the error and fails the fuzz target without writing a crasher unless the returned error implements the crash interface.

The public-context probe source and recorded JSON output were inspected. In 6/10 recorded iterations the parent reported DeadlineExceeded while the child Err was nil; the copied suppression condition retained DeadlineExceeded. In those cases cancelChild then made the child Canceled, further distinguishing its eventual error from the retained parent timeout. This demonstrates the context ordering and suppression mechanism under an amplified model; it is not a reproduction of the full fuzz coordinator or a rate estimate for CI.

The raw baseline CI log records FuzzCSVRoundTrip failing after 11 seconds and 102384 executions with only `context deadline exceeded`; it reports no panic, failing-input path, or rerun corpus command. That output is consistent with the mechanism, but does not identify where that particular error arose. The target's source uses CSV stringify/parse and equality, with no explicit context-deadline return. Input-dependent slowness, worker/coordinator behavior, other error paths, and the exact original scheduling remain unproven alternatives; absence of a logged crasher is not proof that every target input is correct.

Recorded retry manifests inspected: 3 debug timed main runs plus 3 plain timed main and 3 plain timed integration runs (9 timed runs), 2 additional 100000-count runs, and 30 debug plus 50 plain no-op runs. All list exit code 0. These constrain reproducibility, but do not reproduce or falsify this narrow scheduling window. No new tests, source edits, harness suppression, toolchain correction, or publication were performed in this independent check.

Recommended wording: **“The baseline CI timeout remains unreproduced. Pinned Go source and a public-context model demonstrate a plausible coordinator timeout-propagation race; the exact CI cause is unproven. All recorded targeted retries passed.”** Keep this separate from the accessor/default recursion bug, whose cause and correction were independently reproduced.
