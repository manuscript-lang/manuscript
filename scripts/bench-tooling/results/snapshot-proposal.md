# Bounded editor snapshot and diagnostic scheduling proposal

Base: a988705cbd5ed9c7424ac891aa42893c2805474a. Review baseline a3b14fbc found ten URI caches retained ten independent checked graphs (+37.5 MB versus +3.76 MB for one on a 1000-function library); 41-module ten-tab diagnostics ~110 ms per edit, ten-edit burst ~986 ms; canceled workspace symbols blocked later hover ~707 ms. New-base before measurements retained separately. No compiler incremental frontend or concurrent checker redesign is proposed.

## Immutable session generation

Keep server mutation and analysis serialized. Each accepted edit/open/close or relevant watched-file event invalidates the previous generation's maps. Own cache entries only for this live document/overlay generation; never retain historical snapshots globally.

Share a nearest-manifest **default entry** recovering analysis across open URIs only when that default graph contains the requested canonical module, exactly matching current analyze's first attempt. Keep a separate result for an unreachable module selected with Options.Module, keyed by canonical manifest + canonical selected-module path. Never union declarations across files or substitute the fallback graph for the manifest-entry graph. A library default graph already discovers its full source/test scope. No reuse for ScopeMarker/repaired completion snapshots or different Recover/Module options. Standalone files retain independent roots. Keep canonical URI/module mapping, invalid nested manifests, aliases, unsaved overlays and standard-library identity behavior delegated to existing project/frontend/compiler APIs.

Each checked result/snapshot may lazily own occurrence indexes and program lint, reused while its checker.Program and source are immutable. Do not globally reuse checked standard symbols across programs. Static standard lexing/header information may be separately immutable but is optional. Workspace discovery groups equal canonical roots before walking. Strict workspace Module-root analyses remain transient: never retain N distinct selected closures or before/after rename graphs in a generation cache. Do not substitute a default graph for a strict selected-module graph, even if its modules cover the target; strict failure/diagnostic scopes differ. If the default recovering analysis has Program==nil, return those diagnostics with no selected-module fallback, matching the existing analyze state machine. Retain rename's before/after validation; do not reduce searched files or checking coverage to make benchmarks pass.

First implementation can preserve per-URI aliases in server.cache pointing at shared values, minimizing caller churn; a dedicated session analysis owner is preferable if it avoids duplicated caches/invalidations. Compare simplicity and measured retained heap before choosing.

## Coalescing without losing edits

Apply every didChange increment and version guard sequentially to server.docs. Coalesce only consecutive already-queued didChange frames and publish the latest accepted versions before any non-didChange frame, lifecycle event, request, shutdown or EOF. If the queue is empty, publish immediately; no timer or concurrent worker is required. Limit each drain by 32 messages or a 25 ms scheduling budget to prevent continuous edits starving analysis; this is a scheduling bound, not a promised diagnostic completion deadline, because one compiler check is non-preemptible. Do not silently discard invalid/stale edits or ordered range operations. The protocol permits suppressing obsolete diagnostic versions; newest valid/invalid diagnostics and correctness remain mandatory.

Maintain version-stamped dirty documents and clear diagnostics on close. If implementation uses a small scheduled timer/select in the serial Serve loop, only the main loop accesses docs/cache. Unit tests must avoid wall-clock sleeps by explicit barriers or injectable scheduling.

## Cancellation

Check transport cancellation before dispatch and between workspace discovery/files/analyses/index phases. Abort with RequestCancelled and do not cache a partial result. One compiler check is currently non-preemptible; report that limit rather than adding context checks throughout compiler/runtime in this patch. Existing response-time check remains to close races.

Keep transport memory bounded. A 32-frame queue can delay reading cancellation under saturated input; don't replace it with an unbounded queue. Consider separating reader cancellation signaling from bounded dispatch using a bounded mutation batch or explicit backpressure. At minimum prove cancellation of already-read queued requests avoids work; do not claim it bypasses arbitrary unread input backlog. No extra concurrent checker execution or changes to runtime cancellation.

## Alternatives and validation

Do nothing preserves serial correctness but repeats whole graphs and all diagnostics for obsolete versions. Debounce alone removes bursts but leaves one-edit tab/heap multiplication. Full incremental parsing/checking, dependency-diff invalidation and concurrent workers are broader changes, unsupported by this bounded review. Prefer conservative whole-generation invalidation with shared equivalent results, then measure before adding cross-generation reuse. Watcher filtering should ignore unrelated non-source/non-ms.toml paths; changes to relevant files conservatively invalidate all live snapshots initially.

Validate output equivalence before/after for diagnostics, hover, semantic tokens, completion and workspace results; explicit negative tests must observe introduced errors/new declarations and disappearance after reverting, rather than only counts. Cover two nearest manifests including invalid nested manifest; aliases/symlinks/new unsaved overlay files; reachable and unreachable application modules; source/test libraries; standard virtual documents and checked identities; ScopeMarker completion; UTF-16/CRLF; cross-file rename collisions. Count checker invocations/identity reuse and post-GC heap, not latency alone. Exercise two incremental edits where the second range depends on the first, stale versions, invalid latest version, close/EOF/shutdown, burst longer than queue, cancellation before and during workspace scanning, and race tests. Re-run retained wire/Go harnesses adapted only to allow legitimate diagnostic coalescing while checking latest versions and nonempty feature results.

Requested skeptical review: challenge equivalence of selection/coverage, invalidation and snapshot lifetime; whether proposed coalescing preserves protocol ordering and error visibility; cancellation/transport limits; whether a smaller alternative achieves the measured benefit. Do not implement architecture until review concerns are resolved.
