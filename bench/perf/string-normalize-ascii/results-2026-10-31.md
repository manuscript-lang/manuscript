# Reject ASCII normalization candidates, 2026-10-31

**Both production candidates are rejected.** The simple ASCII identity shortcut
repeated a Unicode compatibility NFKD cost; the distinct first-byte-gated version
avoided that specific flag but introduced consistent Unicode NFD costs. The
production source is restored to its baseline. This change retains experiments,
Rust controls, raw measurements, reproducible analysis and contract tests; it
ships no normalization optimization.

The simple shortcut's 320 KiB ASCII NFC case falls from 3.59 ms to 15.7 µs, and a
4 MiB ASCII process's peak RSS falls from 29,088 to 8,484 KiB. These gains do not
justify the common Unicode costs. No favorable cohort replaces an unfavorable
one. No backend, placement, allocator or runtime-lifetime cause is investigated
or claimed. No more timings were taken after rejecting the first-byte candidate.

## Protocol and comparable Rust controls

Base main is `8dd79f417` (full SHA in records), Linux x86_64, Rust/Cargo 1.99.1.
The same fixed Manuscript compiler builds four native states from the same path:
baseline, byte-word/vector fix only, ASCII shortcut only, and both. Exact patches,
source hashes and archive hashes are in [states](results-2026-10-31/states/record.json);
[program builds](results-2026-10-31/program-builds/builds.json) record every source,
archive selection, executable hash and public build metadata. The compiler hash
is fixed; all Manuscript programs use normal Release, whose companion metadata
reports Cranelift. No stronger backend claim is made.

The final Rust controls use the same unicode-normalization 0.1.26 library and
features as the runtime. `eager-input` builds a Vec<char> with individual pushes,
then normalizes its copied iterator, matching the native input-buffer algorithm.
`eager-input,ascii-identity` additionally returns an owned ASCII copy when its byte
budget permits. The Rust output builder/return ABI differs; tiny wrapper overhead
and physical storage are not language-parity proofs. Both languages validate exact
output bytes or named errors during timing and consume the checked checksum.

The earlier [discovery](results-2026-10-31/discovery/record.json) uses idiomatic
lazy Rust character iteration, with/without its ASCII identity feature. It is a
comparable observable workload, **not an identical input-decoding algorithm**;
its much faster Unicode zero-budget failures must not be presented as an isolated
language/codegen gap. Exact original discovery inputs are retained as document
snapshots; [name mappings](results-2026-10-31/archive-name-map.json) preserve their
original paths/hashes.

The normalization matrix rotates six variants and reverses the rotations:
12 rounds, each variant twice per order position, 100 cases and 7,200 raw rows.
Byte search (220), line splitting (16), and reversal (83) use four variants/eight
balanced rounds, producing 7,040/512/2,656 rows. One validated warmup precedes each
variant; builds/setup/output are excluded from timing. All producers pass complete
case/byte/count/checksum guards. Samples stay phase-specific, not pooled.

## Unfavorable controls and A/A follow-up

A descriptive screen (over 5% median, over 1 ns paired median, at least 5/6 slower
signs) identifies follow-up cases; it is not a CI threshold or acceptance proof.
The first reverse cohort flags `ascii_mixed_n63`: baseline→byte +6.63%, paired
+9.76 ns, 7/8 slower; baseline→ASCII +6.18%, paired +11.05 ns, 7/8 slower.
The same four binaries then run two predeclared full 83-case repeats with an
identical-baseline A/A cohort between them:

| Phase | Baseline n63 ns | Byte n63 ns | ASCII n63 ns | Both n63 ns |
| --- | ---: | ---: | ---: | ---: |
| first factorial | 214.66 | 228.88 | 227.92 | 230.04 |
| full repeat 1 | 221.20 | 226.09 | 227.40 | 215.01 |
| full repeat 2 | 224.38 | 227.71 | 217.81 | 224.15 |

The n63 flag does not reproduce in either repeat, while byte medians remain
somewhat slower in all three phases. A smaller persistent cost remains possible.
Identical-binary baseline A/A medians are 217.15/228.03 ns; its four pairs have less
power than the eight-pair comparisons. The material penalty is unconfirmed, not
disproved. Repeat 2 separately flags an early-Unicode 4 KiB reverse case for ASCII
only (+7.39%, paired +794 ns, 7/8); that flag is absent in the other two cohorts.
The original baseline→both comparison also flags `ascii_mixed_n64`: +5.33%,
paired +15.32 ns, 8/8 slower (paired range +0.13 to +54.26 ns). Its two full repeats
instead show −2.30%/−2.10%, paired −1.17/−0.72 ns, with 4/8 and 3/8 slower signs.
For n63, word's paired medians remain +9.76/+3.44/+3.25 ns across the three phases,
with 7/8, 5/8 and 6/8 slower signs. Identical-baseline A/A has a +15.99 ns paired
median, 3/4 slower, range −5.84 to +29.86 ns: zero screens was not zero variation.
Every full repeat and A/A row remains, including newly unfavorable cases.

The first normalization matrix also flags adding byte fix after ASCII for
`ascii_scale_4096_NFKD_full` (+5.17%, paired +33 ns, 10/12). A predeclared full
100-case A/A replay uses two labels per identical ASCII/both executable (eight
balanced rounds, 3,200 rows). That specific flag does not reproduce. Its identical
both-executable A/A itself flags two other cases: ASCII 4096 NFC (+5.17%, paired
+31 ns, 7/8) and early-Unicode 1 MiB NFD (+5.21%, paired +510 µs, 7/8). This
quantifies variability and false screens; it cannot prove absence of a real cost.
No favorable cohort replaces the first run and no placement tuning occurred.

## Rejection of the simple ASCII shortcut

The first 100-case factorial phase shows `compatibility_scale_4096_NFKD_full`
slower for baseline→ASCII (+4.71%, paired +5.22 µs, 10/12 slower) and
baseline→both (+6.32%, paired +7.63 µs, 11/12). A predeclared full 100-case,
four-state/eight-round [native repeat](results-2026-10-31/normalize-native-repeat/record.json)
retains 3,200 rows. The same case remains +3.45%, paired +4.63 µs, 7/8 for
ASCII, and +5.05%, paired +3.81 µs, 6/8 for both. Independent review rejected the
shortcut. The A/A variation above and later smaller results do not erase this
repeated material Unicode cost.

## Rejection of the first-byte gate

The distinct candidate uses `text.is_empty() || (text[0].is_ascii() &&
text.is_ascii())` before the identity copy. The content-based hypothesis was to
reject Unicode-leading inputs without calling the whole-slice predicate. The
negative-budget guard, outer form validation, and subsequent Unicode body stay
unchanged. It was tested as a new algorithm candidate; no placement tuning was
used. Exact [patches and native-state hashes](results-2026-10-31/leading-byte/states.json)
and [program builds](results-2026-10-31/leading-byte/builds.json) are retained.

The [new full matrix](results-2026-10-31/leading-byte/normalize-matrix/record.json)
has 100 cases, eight variants and 16 balanced rounds: baseline, word-only,
rejected-simple-ASCII, rejected-simple-both, first-byte-ASCII, first-byte-both,
matched Rust, matched Rust + ASCII. Every one of the **12,800 rows** passes the
same exact case/input/iteration/checksum guards, including all warmups. The
[complete paired analysis](results-2026-10-31/leading-byte/paired-comparisons.csv)
reports all 2,800 inventory-ordered variant pairs/cases, ranges and slower signs,
including all unfavorable observations; no threshold filters the report.

The old NFKD flag subsides, but the new NFD controls fail. The first-byte standalone
ASCII 320 KiB NFC median is 16.24 µs versus baseline 3.57 ms; matched eager Rust
is 3.11 ms and matched Rust + ASCII 12.68 µs. For 1 MiB early-Unicode NFD, baseline
is 8.23 ms versus matched eager Rust 6.41 ms; first-byte standalone is 8.62 ms.
These are workload-specific comparisons, not universal parity claims or a causal
attribution of the remaining language/runtime difference.

This candidate is rejected after this full phase. New byte/lines/reverse/RSS
programs were built, but **not measured** after rejection. The older four-state
controls and RSS results above measure the simple candidate only. No first-byte
RSS, full broad-control acceptance, final combined-main replay, or clean
normalization lane is claimed. Outstanding performance gaps remain visible.

## Correctness, limits, and reproduction

The retained tests cover all 128 ASCII byte values, all typed forms, omitted/none,
exact/short/zero/negative/empty budgets and invalid form spellings. On the simple
ASCII-only and combined states, two new plus seven existing source tests pass in
Debug and Release (36 executions). Three native normalization tests, workspace
all-target Clippy, formatting and repository checks passed for that historical
candidate. The stale-archive rejection and successful fresh-runtime rerun logs
are retained. Those checks are historical, not acceptance of either optimization.
The two new tests additionally pass in Debug and Release against the restored
baseline archive. The first-byte candidate's two new tests passed in both profiles;
its full final-check suite was not pursued after the measurements rejected it.

The final evidence utilities are checked with
`python3 -m unittest discover -s bench/perf/string-normalize-ascii -p test_matrix.py`.
Controlled producers exercise complete balanced matrices, empty/missing/duplicate
rows, changed checksums, and incomplete/truncated saved phases. Invalid phases
produce no summary; the analyzer rejects incomplete or missing samples.

Full workspace/native corpus execution was not run locally under this campaign's
backend/ownership/lifetime/Windows/network restrictions. Required CI remains in
force. The final evidence-only checkout also passes Rust-control formatting, all-feature/all-target
Clippy, and `make repo-check`. [Host CPU metadata](results-2026-10-31/host-cpu.json)
identifies the same campaign host. The final branch adds no runtime or API changes. Benchmark phases are
pinned to main `8dd79f417165200a4208b860d653fc5c4ec22d1e`, rather than being
relabeled as measurements of a newer publication base.

Build archived patches from their stated revision using the same fixed compiler
and matched native archives; keep all program templates and output guards
unchanged. Build matched Rust controls with `cargo build --release --locked
--features eager-input` and `--features eager-input,ascii-identity`; the idiomatic
lazy discovery remains separate. The [original protocol](results-2026-10-31/factorial-protocol/record.json)
and [first-byte command](results-2026-10-31/leading-byte/matrix-command.json)
record exact commands and hashes. `compare_matrix.py PROGRAMS_JSON IDENTITIES_JSON
NEW_OUTPUT` validates every producer before reporting. Stop other host work before
timing. Recompute the full pair report with `analyze_matrix.py MATRIX_DIRECTORY
IDENTITIES_JSON NEW_CSV`; it validates the full sample lattice and writes hashes
of its inputs/script/output beside the CSV. All native archives and executables
remain local; the [manifest](results-2026-10-31/manifest.json) covers only retained
text/code/commands/hashes/raw observations. Historical snapshots ending in `.txt`
