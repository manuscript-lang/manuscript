# Reversing existing UTF-8 scalar spans

Superseded measured experiment at baseline `4be5d6d8c2defb9fc6eb75c8c43bd68a5314d192`.
All 22 Rust string tests and both source tests in Release and Debug pass.
The 79-case seven-pair comparison and separate ten-case nine-pair focus are
complete. This version was discarded; final V3 is documented separately in
[../string-reverse-ascii](../string-reverse-ascii/).

The reverse loop already decodes each scalar from the end of the input. A valid
scalar has canonical UTF-8 bytes in that same input span, so copying that span
avoids encoding the scalar again through a temporary four-byte buffer. Malformed
bytes, reported by the existing decoder as U+FFFD with width one, retain the
original encoding path. A literal valid U+FFFD has width three and copies its
original bytes. No constructor, allocator, representation, or cleanup machinery
changes.

The source fixture checks scalar order rather than grapheme order, embedded NUL,
literal replacement characters, combining marks, ZWJ, mixed byte widths, and
boundary/large ASCII prefixes. Internal Rust cases additionally check malformed
lead/continuation bytes, truncated sequences, overlong encodings, surrogates, and
out-of-range encodings with the existing one-replacement-per-invalid-byte rule.

The 79 generated-program cases cover mixed/control ASCII at exact lengths around
8/16/32/64-byte boundaries and scaling through 1 MiB. Unicode controls include
two-, three-, and four-byte scalars, mixed widths with NUL and U+FFFD, combining
marks, ZWJ, and literal U+FFFD. Expected output uses hand-written reverse patterns;
no expected output is generated by calling `reverse`.

Each timed operation compares its complete output with the independent expected
text, then adds the byte length plus 17 to a checked checksum. Conversion,
validation, and result release are included. Input and expected construction,
checked warm-up, compilation, process startup, and output are outside timing.
`identities.json` fixes every case name, byte size, iteration count, and checksum.
Short cases use one million iterations, intermediate cases use 100000, 4 KiB
and larger cases use 1024, and cases at least 256 KiB use 16.
