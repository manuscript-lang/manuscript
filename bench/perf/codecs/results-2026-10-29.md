# 2026-10-29 native Base64 setup

Baseline: `4c0a1cb820e772f56a0c831a0f2fe37fbc96a9a7`; the changed runtime differs only by the reverse-table patch in this PR. Generated-program source and compiler are identical. See [environment and hashes](evidence-2026-10-29/environment.json), [binary hashes](evidence-2026-10-29/binaries.json) and [all samples](evidence-2026-10-29/samples.jsonl).

Linux x86-64, Intel Xeon Platinum 8573C, five exposed CPUs with a four-CPU cgroup quota, Rust 1.99.1, LLVM 23.1.1. `Release` selected MIR Speed, then actual `opt -passes=default<O3>` and `llc -O3`; native runtime was compiled for x86_64-unknown-linux-musl. No compilation or other task CPU work ran during measurements. Each case has nine paired trials after a discarded warm-up pair.

Times are microseconds per complete JSON parse, including checksum/byte validation and result destruction. Ranges are min–max; the change column compares separate medians. The shared host is noisy: these are measured distributions, not a general throughput promise.

Empty/small-list medians fell 9–24%; the single-three-byte-value median fell 14%. Large-value controls overlap substantially, so no large-payload speedup is claimed. All 140 producer executions succeeded with identical requested identities and checksums; every decoded byte was compared inside each program.

The causal work removal is visible in the production archive disassembly: before, sixteen vector stores initialize a 256-byte stack table and the alphabet loop installs 64 entries on every call; after, the decoder selects one immutable table. The local stack reservation shrinks from `0x148` to `0x48`. Output capacity and allocations are unchanged; immutable tables add 512 bytes of read-only storage. The [before](evidence-2026-10-29/decoder-before.asm) and [after](evidence-2026-10-29/decoder-after.asm) disassemblies retain this evidence.

## Further bounded codec pass

CSV escaped-cell concatenation was rejected as a quadratic finding: consuming append optimization already reuses the buffer. Five baseline scaling trials (with a discarded warm-up) produced these median times for one quoted cell with repeated `ab"` content (escaped on input), plus a `tail` field. Full cell/row output and checksum were validated.

| Escaped quote count | Median parse, µs |
| ---: | ---: |
| 8 | 0.704 |
| 64 | 4.506 |
| 512 | 24.038 |
| 4096 | 389.748 |
| 16384 | 1492.714 |
| 65536 | 5706.425 |

At 16,384→65,536 escaped quotes, input grows 4× and median time grows 3.82×. Quote-free quoted and plain-cell controls also scaled approximately linearly (84.7→372.2 µs and 76.1→374.5 µs respectively over the same sizes). No CSV patch was made.

A separate source-codec experiment removed `.values()` materialization before indexed reads from public Base64 encode/decode and hex decode, preserving direct parameter borrowing. Seven paired trials after warm-up covered 0, 3, 32, 1,024 and 65,536 decoded bytes, validating all outputs. Although empty inputs improved, every nonempty case regressed; after/before median ratios were 1.13–2.40 for Base64 decode, 1.26–2.03 for hex decode and 1.29–1.95 for Base64 encode. The direct Bytes access path outweighed the saved copy. This experiment was rejected and public encoding source remains unchanged. This is evidence about that candidate, not a request to change compiler/codegen behavior.

The fresh pass also checked the existing JSON scanner and serializer structure against recent landed changes: hashed duplicate detection for wide objects, eight-byte digit scanning and the recent string/number serialization fast paths. No further actionable source/native codec issue was established within this bounded pass. Network/protocol, ownership/cleanup, compiler/backend changes, and Debug JSON depth/retention/compile-latency work were excluded.
