# Perf bash, 2026-11-09

Base `3fbb7cfe`, `ms` Release build with LLVM. Machine: Intel Xeon @ 2.10GHz, 4 vCPUs, Linux 6.18 (shared cloud VM). Rust is `rustc -C opt-level=3 -C overflow-checks=on` on the reference solutions in `bench/agent/challenges/*/solutions/rust`. Wall times are noisy on this VM (up to 40% between runs); the gaps below are explained with `valgrind --tool=callgrind` instruction counts, with the allocator reservation lowered as in the [callgrind note](../../wiki/benchmarks-and-performance/callgrind-needs-a-smaller-allocator-reservation.md).

## Where Manuscript stands against Rust

Kernels (`bench/perf/kernels`, min of 5 runs, microseconds, identical checksums): sieve 25285 vs 35605, life 3532 vs 6152, trees 26403 vs 35386, collatz 175638 vs 294198, map_count 12762 vs 21172, matmul 6674 vs 6813, nbody 7496 vs 6620 (1.13x, the only loss). The matmul gap against unchecked C in the 2026-11-09 kernels page is layout: `plain.c` uses one flat `n*n` array, the Manuscript and `c-bounds` kernels use `List[List[Float]]`.

Workloads (3 MB stdin, min of 5, ms): c05 calculator 40 vs 44, c13 inventory 87 vs 129, c18 cron 626 vs 691 (8.78G instructions vs Rust's 9.18G), c09 ciphers ~40 vs 33, c36 bank ledger 66 vs 50, c03 csv 43 vs 29.

## The remaining gaps, explained

- **c09 ciphers, 1.2x wall, 1.7x instructions (404M vs 237M).** `rest = rest.slice(...)` allocates and copies a new owned `String` per field (Rust borrows a `&str`): `owned_copy`, `msrt_string_slice` and `sub_scalars` are 18% of instructions; `line.replace(old: " ", new: "").is_empty()` copies the whole line; `transform` is 1.3x Rust per character (the scalar list plus `from_scalars` round trip). This is the owned-string model, not a codegen defect.
- **c03 csv, 1.5x wall, 2.1x instructions (731M vs 354M).** No single function: `split_view`, `find`, `all_digits`, `walk_sub_scalars`, `replace`, `parse_int_decimal`, `trim_view`, `contains` and `Lines.next` each cost 3 to 13%, as separate runtime calls LLVM cannot inline (the runtime is an opaque archive; whole-runtime LTO was tried and rejected in `architecture/runtime-lto-proposal.md`).
- **c36 ledger, 1.3x wall, 1.26x instructions.** 13% in `msrt_string_concat`: interpolations did not fuse (below). Fixed in part; the rest is `msrt_map` string-key probing and `owned_copy`.
- **nbody 1.13x.** Float field loads and stores through `List[Body]`; same instruction count class as Rust, bounded by the VM's noise.

## Change: string fusion across paths

`strfuse` refused to fuse a concat chain when any leaf had a drop in another block, so `"ok {next}{sfx}"` with `sfx` also used on a sibling path stayed as `string_fmt2` plus `string_concat`, and the 10-piece interpolation in `report` stayed ten `string_concat` calls with seven `int_to_string` temporaries. A drop now counts only if its block can reach the join without redefining the leaf. At the chain cap an `int_to_string` leaf still becomes the integer.
