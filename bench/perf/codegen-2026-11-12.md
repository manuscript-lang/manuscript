Reproduce with `MS=./target/release/ms ms run bench/tools/workloads.ms -- 5`. The `c05` reference was ported from `try f(x)` to `f(x)?` first (it no longer parsed).

## Change: `var` records in place, `Bytes` reads inline

`Lines.next` (every `stdin() | lines` program) took its 13-leaf `Lines` receiver out of the caller's slot, kept the leaves in registers and spilled, and put them all back at each return; `self.data.get(i, 0)` was an out-of-line `msrt_bytes_get` call. A `var` record parameter now stays in the caller's slot and `Bytes` indexing lowers to `list.get`.

Line loop (`stdin() | lines`, 20,000 lines): 8.97M instructions to 7.26M; `Lines.next` self 147 to 75 per line.

## Change: lookups in a small literal map build nothing

`{"stock": 3, "price": 3, ...}.get(name).get(0)` (also `.get(k)`, `.contains(k)`, `.is_some()`) built the map on every call: an allocation and one insert per entry. A literal of at most 12 constant entries (`Int` or `String` keys; `Int`, `Float`, `Bool` or `String` values) is now searched by comparing the key with each constant; the last of two equal keys wins. A 5-entry lookup in a 2M-iteration loop: 171 ms to 8 ms (85 ns to 4 ns per call).

## Change: one-byte `contains` inlined, string element copies without a call

`"#.SE".contains(cell)` called `msrt_string_contains` (80 instructions for a one-byte needle in a 4-byte text). `msrt_string_contains` now lives in `ms-rt-hot` and the program inlines the scan for a needle of one byte in a text under 32 bytes; every other search calls `msrt_string_contains_long`, the old function. `copy_range` copies `String` elements in a loop that keeps short and static strings as two words, instead of a `slot_copy` call per element (`flatten`, `clone` of a `List[String]`).

`c16-maze-bfs` (a `List[String]` of one-character cells), callgrind on 400 KB: 55.5M to 32.4M instructions; on the full 3 MB input 478M to 405M. Wall time is unchanged at about 125 ms against 45 ms for Rust: the program keeps three 16-byte-per-cell lists, 25,000 page faults against 6,500, so the remaining gap is the `String` cell representation, not generated code.

## Change: the heap reservation asks for huge pages

The small-block pages and the grow area of the heap (`ensure_region`) are `madvise(MADV_HUGEPAGE)` on Linux, so a program that builds megabytes of cells takes one fault per 2 MiB where the kernel allows it, not one per 4 KiB. `c16-maze-bfs` (3 MB input, min of 5): 103 ms to 86 ms, minor faults 25,200 to 12,000. A hello-world program is unchanged (RSS 13.1 MB, 94 faults against 99).

## Change: `map`/`filter` chains over numbers run as one loop

`xs.filter(fn x: x % 3 == 0).map(fn x: x * 2).sum()` built a list for each stage. A chain of `map`/`filter` calls over numbers or `Bool`, ending in `map`, `filter` or `sum`, whose lambdas only read (no calls) now runs as one loop that builds only the final result. 50 rounds over 2M `Int`, min of 3: 163 ms to 78 ms; Rust 95 ms with a fused iterator and 120 ms collecting each stage. A lambda that calls anything, or a chain over strings or records, keeps the staged lowering.

## Change: constant list tables in loops are built once

`for d in [[1, 0], [-1, 0], [0, 1], [0, -1]]:` inside a loop built and freed five lists per pass. The outermost enclosing loop now builds such a literal once and the inner `for` borrows it. 5M passes of a four-direction loop, min of 2: 248 ms to about 20 ms (Rust folds the array: 2 ms). `c16-maze-bfs` gains under 10% (hand-hoisting the table: 84 to 75 ms, inside the VM's noise).

## Remaining gaps

- `Map.values()` on a map of records copies every value (c13 `report`: 15% of instructions in `slot_copy`, 16% dropping the copies).
- A literal map with more than 12 entries, or one passed on or iterated, is still built on each evaluation.
- A `List[String]` of one-character cells (c16) is 16 bytes per cell against 4 for `Vec<char>`; page faults dominate its wall time (halved by huge pages, 86 ms against 45 ms for Rust).
- `filter(..).map(..).sum()` over a 2M-element list is 2.0x Rust (7.7 ms against 3.8 ms): each stage builds a list.
