# Cost of exits on by default (2026-11-24)

Change: faults and cancels leave by return in every program (`design/proposals/ownership-by-construction.md`): each call that can post or park is followed by a test of the task's `unwinding` byte, each checked operation by a `fault.site`, and the cleanup stack, the guard longjmp and the unwind passes are gone. Machine: x86-64 Linux sandbox, 4 cores, release `ms`. Method: `tools/perf-counts.ms`, instructions under callgrind (machine load does not move them). Before is `fb8319a6a0` (main), after is the branch head; both built with `cmake --preset ci` on the same machine. The committed `bench/perf/counts.txt` differs from both columns by up to 30% on this machine, so it is not the baseline here.

`guard-http-request` and its small shape start themselves as a child, which this machine's valgrind does not follow (1.9M in both columns), so they are not compared.

What the first run found and fixed: the byte test was a runtime call at every site (graph 1,604M, 18% in `ms_unwinding`); it is now two loads in line (the region cell's header pointer, marked `!invariant.load`, then the byte), graph 740M. The `splitview` pass stopped seeing `line.split(" ")[0]` once a site separated the call from the read (splitfirst 155M); it now looks through the site.

What remains: a test after every call that can post, and, after inlining, a second test in the caller on the callee's exit edge, where the byte is known set. Threading that edge, and dropping tests after calls that cannot post, would take back most of graph, strcmp and resultvar.
