# 2026-10-31: linear semantic-token coordinate conversion

Baseline: `f33f13359a02b59467f042eb67d6ecd06d706c7a` (current remote main when
this separate candidate began). Candidate changes only semantic coordinate
conversion, plus tests/evidence. It does not include navigation PR #2095.
This measures the Rust tooling implementation; no Rust-language parity ratio
or universal language-server speed claim is established.

Host: Linux 6.18.57 x86_64, AMD EPYC 9V45, five allowed CPUs, about 17 GiB RAM.
Every measured child was pinned to allowed CPU 0 with `taskset`. Rust/Cargo
1.99.1 (`58cf8f9c3 2026-10-13`), identical release `opt-level=3`, debug info,
panic abort, default host target, no LTO/custom CPU flags. No simultaneous
builds/tests or other intentional CPU-intensive jobs ran during measurement.

All 1,360 measured invocations (68 workloads × ten samples × two binaries)
completed and matched workload fingerprints/source sizes. AB/BA order is
balanced, each process warms once, and query time excludes setup/checking except
completion's own request analysis. JSON rendering/fingerprinting is included.
See [the protocol](README.md) and [every raw sample](results-2026-10-31.csv).

## Result and qualifications

The old line index still counted UTF-16 characters from the beginning of a line
for each token endpoint. At 8,192 items on one line, semantic tokens fall from
161.1 ms to 2.09 ms (about 77×); the multiline control improves from 2.51 ms to
2.16 ms. At 1,000 ordinary functions, 2.56 ms becomes 2.27 ms. A forward cursor
visits each new source span once, while backward/partial-character lookups call
the original conversion without changing its valid anchor.

Tiny cases are not universally faster: a one-item Unicode/CRLF list rises from
7.78 to 8.23 μs (+5.8%, about 0.45 μs); an eight-item multiline list rises from
11.17 to 11.55 μs (+3.5%). These costs are retained, not removed from the table.
Unchanged hover/index/symbol/reference/completion/formatter controls have median
ratios about 0.969–1.013. No performance threshold or blanket regression-free
claim is implied. The large scaling gain is separated from small control shifts.

The strict/forgiving integration goldens were captured using the prepatch binary
before editing the helper, then compared as complete JSON with LF/CRLF and
scalar-boundary endpoint checks. The oracle unit test checks every byte offset,
partial characters, EOF/oversized offsets, backward and alternating sequences.
An independent reviewer also ran the copied integration test against untouched
baseline production code at `f33f13359`: one passed, confirming the old renderer
reproduces the complete goldens.
Current multiline-string token offset arithmetic is deliberately untouched;
possible unrelated CRLF correctness work belongs to the editor correctness lane.

Passed: 161 affected tests/doc tests; final focused coordinate/golden reruns;
affected-crate clippy with warnings denied; workspace formatting; repository
invariants; standalone harness clippy/formatting and comparator syntax. Independent
skeptical review reported no correctness findings. No GitHub approval was made.
Full workspace/native/conformance execution is left to required CI under the
campaign's backend/ownership/Windows/network scope restrictions. Integrated
merged-main replay with #2095 and correctness #2065/#2070/#2075 remains pending.
