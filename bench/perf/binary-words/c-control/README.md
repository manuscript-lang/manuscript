# Checked C fixed-width control

Baseline repository: `f21eb91d65abb3f655c267dd0b64c6c66e02601e`. Isolated fixture only; no production changes.

CLI: `probe OP TYPE INPUT EXPECTED START FIELDS COUNT WANT KIND`. Operations: read, pack, roundtrip. Types: i8/u8 and i16/u16/i32/u32/i64/u64/f32/f64 with le/be suffix. WANT is decimal signed/unsigned-in-Int-range integer or finite float; UInt64 uses hi32:lo32. Inputs and expected output come from files, arguments are parsed before warmup/timing. Values must fit their public type, counts be nonnegative (COUNT positive), and offset expressions fit Int64; invalid harness arguments are outside the API comparison.

Each read checks the exact offset bounds before memcpy/byte-swap, compares every decoded value, and increments checksum per field. Signed integer comparisons use equivalent fixed-width bit patterns. Unaligned access uses memcpy, avoiding alignment and aliasing UB. Negative/truncated offsets produce ERANGE. UInt64 methods use `binary: out of range` from their explicit preflight; all other fixed-width methods use the native error message `binary: value out of range`. This observed public distinction must be retained by any candidate. Pack constructs a fresh geometrically growing output (initial capacity32, doubling), reserves per typed word, writes in selected byte order, verifies full output and frees it inside the timer. It never reserves the final output size in advance. Roundtrip reads/appends each typed field and compares complete bytes. Float32 roundtrip explicitly widens through volatile double then narrows through volatile float to preserve requested NaN quieting; float64 bits remain unchanged. Finite1.5 is the performance control; nonfinite/signed-zero patterns are correctness controls.

C width/order functions are specialized like the per-type Manuscript loops. A zero-instruction compiler memory barrier at each operation prevents repeated read verification from being hoisted out of the measured loop. Bounds checks remain enabled. C's inline error status, typed store, geometric-growth policy and output representation differ from Manuscript's Result/Error and byte-at-a-time builder helpers; measured ratios would describe complete implementations, not compiler overhead alone.

`cc -O3 -Wall -Wextra -Werror -o probe driver.c` builds the release control. Sanitizer command and hashes are in metadata.json. `python smoke.py` runs250 independent Python-generated smoke cases; `--binary` selects sanitizer/alternative executable and `--output` chooses evidence path. Smoke coverage includes18types, integer extrema, endian, unaligned/range checks, NaN quieting/signedzero/infinity bit patterns. Parent-generated fixtures provide shared MS/C comparison. No timing matrix has been run here.
