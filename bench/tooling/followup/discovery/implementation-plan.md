## Stage 1: physical discovery reuse without sharing selected analysis

1. Split `workspaceDocumentsWithCancel` into a small request-local discovery helper and candidate assembly. The helper owns a `map[walkScope][]document`, with scope `(canonical containing directory, effective recursive flag)`. Resolve nearest manifest using the original requested filename first, including invalid manifests; only then canonicalize the containing directory. If that directory cannot be canonicalized, do not merge it with another scope. Retain current WalkDir error/nonexistence behavior.
2. Walk the **canonical directory**, not the first alias spelling. Keep existing `.ms`, hidden/vendor/node_modules and symlink-file/subdirectory exclusions. Cache only successfully completed disk walk results for this request; a canceled/error walk is never recorded as complete. No persistent discovery cache or new filesystem abstraction.
3. Preserve selected analysis contexts: rebase physical disk-relative paths onto each caller's selected lexical scope before turning them into documents. This prevents a canonical disk path from silently selecting a different nearest ancestor manifest from a lexical alias path. Sharing physical walk bytes does not authorize sharing strict analyses. Deduplicate assembled disk scope by lexical root plus recursive flag, independently of physical-walk deduplication.
4. Add selected/open candidates independently of a visited-walk decision; preserve original URI, text and version. Keep encoded filename-URI variants separate. Never deduplicate all open candidates by canonical filename. A selected private document replaces only its own URI. Keep deterministic URI sorting.
5. Prefer open text when constructing disk candidates using a deterministic per-physical-file table. Gather all actual ordinary open URI records (not a filename-keyed text winner), and canonicalize each through existing `project.SourcePath(scopeRoot, filename, rawOverlayKeys)`; those outside/conflicting with confinement cannot grant membership. If all admitted records for a physical file have equal text, use that text for a rebased disk candidate. Suppress a disk candidate already represented by an actual open URI with the same decoded filename. If admitted open records have divergent text, **suppress every generated disk candidate for that physical identity and preserve every actual open URI**. This covers encoded-filename ambiguity without selecting an arbitrary variant or manufacturing stale disk-vs-unsaved conflicts. For distinct-path symlink conflicts the original URI records still reach `analyzeWith` and its mandatory `CanonicalOverlay`, which must diagnose the real conflict. Never turn `CanonicalOverlay` failure into an empty overlay map. Candidate assembly does not replace compiler overlay validation or admit a dangling link. These rules apply even without assembled-list reuse.
6. Workspace-symbol discovery uses one helper per request; references/rename retain one ordinary invocation using the same helper/assembly contract. Continue existing per-URI strict analysis and dedup final locations. No selected-file target canonicalization or default/Module result merging.

No ambiguous-overlay fallback may select disk text or reuse a first-request winner. The explicit suppression rule above is the deterministic action; normal unambiguous physical walks still share.

Tests: alias-first/physical-first workspace root orders discover all unopened symbols; duplicate physical walks count once under external overlay instrumentation; unsaved alias produces updated symbols without a new conflict; divergent encoded URI texts remain individually selected; real conflicting symlink overlays remain errors; standalone symlink and symlinked-manifest root contexts retain existing success/error outcomes; recursive/nonrecursive scopes stay distinct; cancellation returns no partial success and next uncanceled request is complete. Existing snapshot and workspace reference/rename regressions remain required.

## Stage 2: whole-owner watcher invalidation and targeted publication

Ownership granularity is the selected manifest's canonical containing root, or standalone selected containing directory. It intentionally over-invalidates within that root and supports new/missing files and library/test discovery; it does not build import-edge dependency state.

1. Add a small owner descriptor retaining selected lexical filename/target, lexical containing root and canonical containing root. Capture it **before compilation** so invalid manifests/failed results retain ownership. Record per-URI owner on a live `checkedDocument` cache miss and per-analysis-key owner when `compileSnapshot` creates a shared default/Module entry. Immutable virtual standard-library documents and exact pinned standard-library disk documents receive an explicit immutable sentinel (using the existing `isStandardLibraryURI`/`standardLibraryDocument` policy), not an absent local owner that triggers fallback. Root identity groups eviction only; checked-result sharing continues using current `analysisKey` and overlay safety gate.
2. Reset these owner maps in ordinary global `invalidate`. They must not retain Programs themselves or survive cache release. Do not use `Program != nil` as a prerequisite for owner invalidation. Default/Module results under an affected owner are all evicted. Metadata missing for a live entry is uncertainty requiring conservative global fallback, not silent preservation.
3. Parse watched-event envelopes independently of the generic requestParams. Known empty changes means no work. Missing/null/invalid envelope or missing/invalid individual URI means global fallback. Require absolute local file URIs for path comparisons; ignore known immutable stdlib scheme; unsupported relevant URI falls back globally. URI-only relevant entries remain accepted because root granularity does not need create/change/delete precision.
4. Canonicalize event paths using existing containing directories when the file was deleted or not created yet; do not demand full-file EvalSymlinks or invent an overlay admission. Keep lexical event spelling too. If a path/root cannot be resolved confidently, fall back globally. For root symlink retarget/deletion, compare old captured owner with freshly selected owner for each open URI (memoized per written directory), and invalidate old and new owner groups on drift. Failure to reselect/canonicalize an old live owner falls back globally.
5. `.ms` event membership is containment under any old/current canonical or lexical owner root. Use the union: never route exclusively by the changed file's nearest manifest. Parent graphs may explicitly import nested-project files, and compiler/LSP discovery currently cross nested manifests. Explicit hidden/vendor imports are not excluded from ownership. Known external `.ms` outside every owner is ignored; unsupported external imports are not introduced.
6. `ms.toml` events also check ancestor/descendant intersections with selected lexical paths and canonical/lexical roots. This covers new nested/ancestor manifests, deletion, invalidation and restoration, including owners with failed results. Ancestor manifests may conservatively invalidate a still-nearer unchanged manifest owner; ordinary disjoint siblings remain isolated.
7. Handle received directory/root deletion/rename events conservatively when the path is an ancestor of an owner, selected file or known loaded module, or an existing directory inside an owner. Unknown directory topology should fall back rather than silently ignore a possibly affected scope. No claim that the editor emits events for every host filesystem topology change.
8. Build affected-owner/URI sets before evicting. Remove affected per-URI results and every matching shared default/Module analysis. Gather their Program pointers, scan retained cache/shared entries, and remove derived index/lint entries **only for Programs no retained live entry still owns**; this also guards any future sharing beyond one owner. Retain untouched B Program/index/lint object identity. Reset global overlay-sharing bookkeeping conservatively if needed without discarding B results. Owners with uncached open documents must still be eligible for publication. Add an A/B plus open virtual/exact-disk-stdlib sentinel test proving stdlib does not turn every A watch into global invalidation.
9. Refactor publication into an existing all-document wrapper plus a URI-set variant using the same diagnostic rendering. Watcher handling flushes existing pending all-document diagnostics before selective processing (serve-loop barriers already do this for didChange batches), then publishes only affected open documents. Unknown fallback calls global invalidate and full publish, preserving prior behavior. Ordinary document notifications continue using current global path.

Tests use real temp filesystem changes and cached results, not mock dependency graphs: A dependency type change updates A diagnostics/hover; B Program, cached index slice/map entry and lint slice/map entry remain identical and B is not republished. Parent+nested consumer union; missing import created/deleted/restored; library unimported source and root test files; invalid manifest cached without Program then fixed; new nested and ancestor manifests; manifest deletion; aliases and deleted paths; explicit hidden/vendor dependency; unrelated external source/TOML; empty versus malformed/missing changes; root alias retarget; all affected owner cache/derived references released. Compare output with fresh uncached `analyze` after mutations, including both query orders for ambiguous overlays.

## Stage 3: bounded consecutive-watch batching, only after owner tests pass

1. Add a watch notification classification bit beside existing incoming.change. Only valid JSON-RPC2.0 notifications without IDs and the exact watched-files method are eligible. Malformed frames, requests, didOpen/change/close and all other methods are barriers.
2. Reuse the current main-loop batching contract: only already queued consecutive watch frames, maximum32 frames or25ms, no timer wait for a lone event. Keep watch and didChange batches separate.
3. During a watch batch, each notification computes/evicts affected owners immediately but adds affected open URIs to one temporary union. Delay only the final diagnostic publication until the batch boundary. This union is bounded by open documents; no extra retained event payload queue. A malformed event envelope triggers full invalidation and union of all open URIs, rather than clearing an earlier affected set.
4. Flush earlier didChange diagnostics before entering the watch batch. Flush watch union before a request/close/didChange/error/EOF/shutdown barrier. Direct server.handle calls outside a batch still invalidate and publish immediately, retaining unit-test/API expectations. Leave existing didChange scheduling implementation unchanged.

If implementing the union complicates correctness beyond this separate small loop/state, stage1+2 can stand as a complete bounded remedy; do not mix notification categories or weaken barriers merely to batch. Independent reviewer should explicitly accept or reject this stage before code.
