# Manuscript observations while writing c41-c45

All five reference solutions compiled and passed on the first or second build; no compiler or runtime bugs were hit.
Friction points (all compile-time, easy to fix from the diagnostics):

- `from` and `_` are reserved words and cannot be used as parameter or loop-variable names (`fn rest(t, from: Int)` and
  `for _ in list` both fail to parse). Use `start` / a named variable.
- There is no tuple type and no user-defined methods on records, so helper "methods" are free functions taking the record. Records are used for
  every multi-value result (a `Result[T, TextError]` with `error(TextError("..."))` stands in for Go-style `(value, ok)`).
- `String.index_of` / `last_index_of` return `Optional[Int]`; every call needs `.is_some()` / `.get()` or a match.
- No stdin read-all convenience used: all solutions loop on `read_line(...)` until `none` and join output in a
  `StringBuilder`. Lines read by `read_line` come back without the terminator, and empty lines are `some("")`, which
  c44 (unified diff) depends on.
- c44 builds a flat `List[Int]` DP table of up to ~(281 x 300) cells with `append` then `set`; this runs well under a
  second, so no special timeout was needed beyond the 30 s set in `challenge.json`.
- c42 keeps a memo table as a flat `List[Int]` instead of a `Map` (Map operations are slow and the key would be a pair).
