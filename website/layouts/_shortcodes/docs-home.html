Why Manuscript

Agents write most of the code. Manuscript is built so they get it right quickly and you can see what they did.

  • Small enough to get rightStatically typed, with no implicit conversions or truthiness. Fewer concepts means fewer first-draft mistakes and less to review.
  • Errors you can handle in the openOptional and Result are values, try propagates them, and match is exhaustive. No hidden exceptions.
  • API first, no async syntaxFiles, networking, HTTP, and JSON are imported @std APIs, called like any function.
  • Feedback built for agents--json diagnostics, ms search_symbol for exact APIs, ms guide for the cheat sheet, and one ms verify to check, format, lint, and test.
  • Reads top to bottom| pipe flows, try inside a flow, +=, range, and bounds-proven [] indexing keep code flat and short.
  • Typed data in one calljson.parse[T] reads JSON straight into your records. Nominal types, generics, and explicit impl blocks keep boundaries clear.
  • Inspect what was builtms review shows where a change matters and ms diagram draws call graphs from the checked source, deterministically.
  • One binary, native resultLowers to typed Go and builds a standalone executable with a bundled toolchain. Nothing else to install.
  • Cleanup that stays correctwith closes files and connections at block end, even on errors and cancellation.
  • Debug and profile on sourceAn editor language server, a VS Code extension, a source-level debugger, and CPU, heap, and trace profiling, all on .ms lines.

Version 0.1: the compiler, runtime, standard library, and tooling work today and are still evolving.
