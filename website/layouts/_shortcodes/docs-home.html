Why Manuscript

Agents write most of the code now. Manuscript is built for that: Python-like syntax that agents already write fluently, ownership instead of a garbage collector, concurrency without async, and a compiler whose feedback an agent can act on. Every number below has a script that reproduces it.

  • Reads like Python, runs like native codedef, four-space blocks, lambda, 0..n and f-strings, compiled ahead of time through LLVM. Faster than hand-written Go on all seven whole-program kernels and level with overflow-checked Rust on five. Kernel results.
  • Feedback an agent can act onDiagnostics read cause; fix. len(xs), .unwrap() and camelCase get the Manuscript spelling, ms check --fix applies mechanical repairs, and a runtime fault is JSON with a kind, position and trace. Diagnostics.
  • Concurrency without asyncAny function can wait. TaskGroup, WorkerGroup and ProcessGroup own their work inside with and talk over typed channels. Eight CPU-bound jobs over four workers run 3.95x faster than over one. Concurrency.
  • Ownership you can followValues have one owner and are dropped at their last use; var marks mutation and .clone() marks copies. No tracing collector: an HTTP server with 10,000 idle connections sits at 31 MB where Go's uses 197 MB. Ownership and borrowing.
  • Batteries includedFiles, processes, HTTP, TCP, JSON, CSV, TOML, YAML, HTML, time, crypto, regex, logging, sized numerics and a test runner, in one ms binary. JSON parses and writes at 0.9-3.4x the speed of V8 across the standard documents and machines measured. JSON results.
  • Measured against agentsThe same twenty challenges go to a coding agent in Manuscript, TypeScript, Go and Rust with hidden tests. Agents now pass 10 of 10 small challenges in Manuscript; first-build success and source size are the numbers still being driven down. Agent benchmark.
