    Concurrent access and resource lifetime#

    Guide index · Chapter index · Design index

    Every source value may be passed between concurrent operations. Passing a reference does not synchronize access to the referenced object. Sharing needs no annotation, compiler bound, or callable proof. It does not keep a resource open or register cleanup.

    Data and services#

    Records and collections are mutable. Alternative tags, strings, and bytes retain their value behavior. let fixes a binding, while var permits reassignment; neither freezes a referenced record or collection. Closures snapshot captured bindings, including a mutable local’s current value, and cannot assign to captured outer locals.

    Native services and builders synchronize their mutable internals and resource lifecycles. Resource APIs may serialize simultaneous calls or report unsupported overlapping use. Race safety does not make several calls atomic or establish their execution order. Use Synchronized when related reads and writes must run under one lock.

    Wrappers coordinate the closed-state check, access to the underlying handle, and closure as one lifecycle protocol. A flag check followed by unprotected I/O is insufficient. A stale lease or lock guard must never access a resource or protected value after release.

    A Queue is a local mutable collection with no internal synchronization. When shared, keep it in one Synchronized[Queue[T]] and hold a separately acquired guard for each caller’s full use, including reads. Queue aliases and bound methods must follow that same discipline; the compiler does not track or enforce lock ownership. Records may contain queue references. A shallow record clone retains the same queue reference.

    Contract views#

    Contract(value: receiver) retains the implementing receiver. There is one contract-view type; it can be passed through fields, parameters, returns, and collections and used according to its receiver’s concurrency contract. Generic behavioral bounds require the named operations only. Native service adapters synchronize their receivers and resource lifecycles. A source implementation that holds a local queue must use a synchronized wrapper before exposing concurrent operations.

    Function values#

    Named functions, closures, bound methods, function fields, and function parameters are ordinary values. Copies, generic forwarding, collection storage, and return values preserve their normal call behavior. Concurrency APIs check the function signature, with no separate capture-sharing eligibility or proof-erasure rules. An operation may return another function.

    Capture application services and job data for background work, and acquire job resources inside that work’s own with scopes. A resource captured beyond its with scope remains a valid reference, but subsequent operations report closed state. Sharing, resource lifetime, and work lifetime remain separate guarantees.
