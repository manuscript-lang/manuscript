      Type checking and source contracts#

      Guide index · Chapter index · Design index

      The type checker decides whether source operations satisfy Manuscript’s rules before the compiler generates Go. The fact that a value can be represented in Go does not make every use of it legal in Manuscript.

      Required checks#

      Accept source according to the normative grammar ; then resolve names and check the compatibility rules . Each rejected program must identify the violated source rule. Backend assignability and Go compiler acceptance are not substitutes for those checks.

      Source ruleChecker responsibility
      Explicit function signaturesCheck parameter and result types against calls and returns
      Names and scopesCollect module signatures, reject duplicate names, resolve locals in declaration order, and check assignments against fixed mutable binding types
      OperatorsUse the closed precedence and operand table; enforce Bool conditions and short-circuit evaluation without implicit numeric conversion
      Function valuesPreserve parameter labels/order and exact types; require explicit specialization of generic function values and explicit anonymous signatures
      Return completenessAllow Unit fallthrough/bare returns; reject reachable non-Unit fallthrough; track Never and function-local loop/return boundaries
      Mandatory argument namesReject unnamed, unknown, duplicate, or missing required call arguments and match names to declared parameters, including function-value calls
      List literalsRequire the canonical standard List import; check homogeneous shareable element types and use annotations or the expected parameter type for empty lists
      Parallel API packsCheck zero-argument functions in literal tasks: [...] packs and preserve each position’s exact return type; see parallel operations
      Destructuring bindingsCheck positional arity, record fields, renaming, nesting, and duplicate bindings; infer each local’s type independently; see destructuring bindings
      Nominal records and tagged alternativesPreserve type identity and check declared fields and cases
      Expected typesPropagate annotations/substituted constructor context through literals, fields, and parentheses; reject incomplete types and avoid result-context inference for generic calls
      Exhaustive matchCheck the scrutinee alternative, positional payload arity/bindings, exact qualified cases, missing alternatives, duplicate arms, and final nonredundant wildcard
      Generic boundsCheck arity, invariant arguments, argument-only inference, every nested application’s bounds, and generic bodies under their declared assumptions
      Recursive types and specializationReject inline storage cycles and expanding generic type/function specialization, including mutual calls and specialized function values; permit regular recursion guarded by immutable collection storage
      Equality and hashingDerive only the specified properties; reject Float/collection keys and data containing ineligible components
      Explicit implementationsMatch substituted operation names/labels/order/types exactly, check generic bodies and receiver-determined parameters, reject overlap ignoring bounds, enforce defining-module coherence, and require explicit contract views
      Standard bindings and sharingResolve the minimal intrinsic prelude and explicit standard imports by canonical declaration identity, distinguish plain and shared contract views, require receiver sharing proof only for shared views, reject implicit guarantee removal or recovery, and retain callable sharing proofs independently of function signature identity
      Public signaturesReject internal nominal types leaking through exported fields, signatures, bounds, or operation surfaces
      IterationAdmit List/Set/Map only, bind immutable element/MapEntry types, evaluate iterable once, and reject loop control outside the current function’s loops
      Result propagationRecognize the canonical standard Result identity; require the same exact error type at a try expression in the current function; do not infer missing operand type arguments backward
      String literalsValidate escape/scalar syntax, check interpolated scalar eligibility, and preserve left-to-right evaluation

      These requirements derive from the core language guide , with accepted and rejected modules in core conformance . The rules specify observable inference and compatibility; checker data structures and internal pass organization remain implementation choices. A module-level test body is a zero-parameter Unit function for static checking: ordinary local scopes, bare-return/fallthrough rules, and Result propagation restrictions apply. Test discovery and runner execution remain separate tooling contracts.

      Type information feeds typed IR , generated representations , and structural tools .
