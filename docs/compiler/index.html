      Compiler design guide#

      Design index

      This chapter is for compiler contributors and readers who need to understand builds. Follow a program from parsing and checking to generated Go, then read how builds are pinned and tested. For ordinary application code, you can start with project configuration .

      Reading order#

      1. Parsing and checking #

      • Compilation pipeline — Follow a program from project loading to the native executable.
      • Type checking and source contracts
      • Scope and capture checking
      • Typed intermediate representation

      2. Go lowering #

      • Function and concurrency API lowering
      • Source guarantees and Go representations
      • Evaluation order and call preparation
      • Cleanup and fault lowering

      3. Builds and dependencies #

      • Project configuration and module paths — Set the source directory, entry file, and import paths in ms.toml.
      • Pinned dependencies and deterministic output — Record versions and inputs so builds use the intended distribution.
      • Caching and Go package boundaries — Understand what can be cached and when Go must rebuild a package.

      4. Conformance and scope #

      • Core-language fixtures — Check complete modules and rejected variants.

      • Runtime binding fixtures — Check standard imports, sharing, and host bindings.

      • Semantic conformance tests — Test required behavior, including cancellation races and cleanup.

      • Complete-program conformance — Check that guarantees work together in complete applications.

      • Scope and implementation order — Find remaining decisions and the order in which work depends on them.
