      Source guarantees and Go representations#

      Guide index · Chapter index · Design index

      A Go value must preserve the behavior promised by its Manuscript type. For example, generated Int arithmetic must detect overflow, and generated collections must prevent mutation through an alias. The compiler and runtime enforce guarantees that unrestricted Go values do not provide on their own.

      The frontend enforces semantics that Go representations do not provide:

      Source guaranteeGo lowering
      Checked Intint64 with checked operations and conversions
      DecimalVersioned finite decimal implementation honoring the coefficient/exponent grid, exact literals, and per-operator rounding in the numeric contract
      Valid UTF-8 StringValidated construction and conversion; no raw string escape
      Immutable bytes and collectionsEncapsulated storage; copies or exclusive adapter transfer
      Ordered maps and setsOrdered wrappers
      Tagged alternativesGenerated typed tags and payloads; exhaustive frontend checking
      Guarded recursive dataInline records/alternatives with immutable container indirection; reject invalid layouts before Go emission
      Value equality and hashingGenerated operations for eligible types
      Explicit contract implementationFrontend selection of a unique applicable concrete/generic implementation, then Go interfaces and wrappers
      Closures and resource referencesGC-retained environments, snapshot captures, and synchronized native closed-state checks
      Lexical cleanupExplicit with registrations, shielded Closeable.close(), and scope unwind operations
      Parallel resultsTyped positional packs preserving each exact return value

      Use Go generics where suitable; generated typed pack wrappers handle heterogeneous parallel results without exposing unchecked casts to source.

      Representation boundaries#

      For example, emitting a raw int64 does not supply checked arithmetic. A raw Go slice does not establish immutable source bytes. The frontend and runtime cooperate with generated wrappers and operations to preserve those contracts.

      Explicit view constructors create contract wrappers. Plain and shared views may use the same runtime representation, while the frontend and IR retain distinct identities and sharing proofs. Go interface assignment or runtime receiver inspection cannot restore an erased proof.

      Generic implementation bodies use checked substitutions; Go method selection cannot resolve overlapping source implementations. Function wrappers retain source labels/order in frontend identity even though Go erases labels. Check recursive storage rules before emission; a generated-Go error is not a source type check.

      Int division/remainder overflow handling, Float non-finite outcomes, Decimal underflow/overflow, and checked truncation conversions follow runtime numeric outcomes , including parameterized runtime operands. Unchecked Go casts or a decimal package’s defaults do not establish these semantics.

      See foreign conversions , type checking , and scope and capture checking .
