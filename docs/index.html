    Learn Manuscript

    Manuscript is a statically typed programming language. You write .ms files, and the compiler turns them into Go programs that run as native executables. The language makes function inputs, errors, resource cleanup, and concurrent work explicit so people can follow what a program does.

    Get started→ Take the tour→ Module reference→

    Start here#

    If this is your first visit, follow this path:

    1. Build and run your first program . Run the included example and understand each line.
    2. Learn the basics . Read source files, name values, and use expressions.
    3. Write functions . Declare inputs and outputs, then call functions with named arguments.
    4. Model data and choose what runs . Use records, alternatives, conditions, and loops.
    5. Handle expected errors . Return a Result, handle it with match, or pass an error back with try.

    For a shorter introduction, take the language tour and read features and boundaries . The learning guide collects those lessons.

    Keep the plain-language glossary nearby when a term is unfamiliar. You can skip the grammar and compiler chapters until you need an exact rule or implementation detail.

    What to expect from the language#

    A file is a module. It imports the declarations it needs and exports the declarations other files may use. Most standard-library names need an explicit import; a small set of basic types is available everywhere.

    Functions declare their parameter and return types. Local variables can infer their types from their initial values. Functions with multiple parameters require named arguments. A single-parameter function accepts either welcome("Ada") or welcome(name: "Ada").

    Calls run sequentially unless you explicitly start concurrent work. Every function can wait for an operation to finish; there is no separate async function syntax. Parallel calls wait for all their started operations before returning. Background work belongs to a service with a fixed lifetime.

    Expected failures are values that callers can inspect. A with block closes its registered resource when the block ends, including when an error or cancellation ends it early. Access to files, networks, and other external services comes through explicit parameters.

    The language has one canonical syntax and formatter. Tooling derives architecture and flow diagrams from checked source.

    Design and implementation status#

    This book describes Manuscript 0.1. The repository contains a working compiler, runtime, command-line tool, and executable tests. Some adapter and tooling features are still design work. Check implementation coverage before relying on a feature. Scope and implementation order lists remaining decisions.

    The detailed rules on each concept page define how that feature must behave. Test fixtures show how to check those rules. A fixture that merely declares a function proves that the compiler accepts it; runtime behavior needs a test that actually calls it.

    How to read examples#

    The first-program guide contains a complete runnable module. Other pages often show only the part of a function that explains a concept. Put those fragments inside a function or test; local statements are not allowed at the top of a file.

    Short examples may omit imports. Import every standard name that your full module uses; standard imports lists the paths. Examples labeled “rejected” show code the compiler must refuse. Blocks showing standard declarations describe the library API rather than declarations you should copy into an application.

    Reference for tools#

    The implemented standard library is also available as plain Markdown and structured JSON , with an LLM index . These exports describe the compiler-bundled APIs.
