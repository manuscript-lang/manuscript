# Start here

Build your first Manuscript program, learn how to read the language, then use it
for something useful. You only need the `ms` download to begin.

## New to Manuscript? Follow this path

1. **[Run your first program](getting-started.md).** Install `ms`, change an example, and build a standalone executable.
2. **[Take the language tour](tour.md).** Learn bindings, collections, functions, types, errors, and modules through small examples.
3. **[Test your code](testing.md).** Write tests, check success and failure, and run the cases you care about.
4. **[Write idiomatic Manuscript](best-practices.md).** Choose clear control flow, handle errors, and manage shared data and resources.

You can read these pages in order using **Next** at the bottom of each page.
Local statements in language examples belong inside a function or test;
complete programs include a filename or an explanation of how to run them.

## Ready to build?

Start with [task recipes](common-tasks.md): command-line arguments, files, JSON,
HTTP requests, and concurrent work. Each recipe is a complete program with a
command to run it.

Use the standard library to find APIs by task,
concurrent work to coordinate tasks, and
[developer tools](../developer-tooling/_index.md) to set up your editor or build
and debug an application.

## Need an exact answer?

The [language reference](../core-language/_index.md) defines syntax and semantics.
The [API reference](../standard-library/reference/_index.md) lists library
signatures and behavior. The [glossary](../glossary.md) explains unfamiliar terms.
These are lookup resources; you can return to them as questions arise.

## Working with a coding agent?

Point it at `ms guide` for a short language reference and
`ms search_symbol <name or words>` to discover APIs. It can check source with
`ms check`, format with `ms fmt`, and run your tests with `ms test`.
[Commands for agents](../developer-tooling/implementation.md#commands-for-agents)
explains structured output and project navigation.
