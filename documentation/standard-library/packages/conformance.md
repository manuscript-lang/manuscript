# Expanded library conformance

[Standard library guide](../_index.md) · [Coverage](coverage.md) · [Common contracts](contracts.md)

These executable checks exercise package behavior through the compiler and native runtime. Use the listed fixtures and tests to verify data handling, limits, errors, and cleanup.

- `tests/e2e/testdata/stdlib/*.ms`: dedicated Manuscript test blocks spanning every public standard module. Known codec/hash/key-derivation vectors, numeric boundaries, Unicode, collection mutation and callbacks, strict data formats, optional budgets, source stream/entropy implementations, filesystem cleanup, scheduling, loopback TCP/UDP/HTTP/WebSocket, and certificate/HTTPS verification exercise checked declarations and native dispatch together. `tests/e2e/stdlib_test.go` only checks/builds/launches these sources and verifies runner transcripts; it does not implement their library expectations in Go.
- `tests/e2e/testdata/stdlib/yaml.ms` and `toml.ms`: called Manuscript parsers, recursive values, exact numbers, quoted/multiline text, anchors/merge keys, dotted tables and arrays of tables, typed errors, malformed syntax, and omitted/zero/exact/exceeded budgets. Compiler and navigation regressions additionally verify bundled source reachability, private visibility, recursive layouts, and editor definitions.
- `tests/e2e/testdata/stdlib/faults/faults.ms`: intentional panic, absent Optional extraction, sealed builder mutation, invalid queue capacities, stale guards, and invalid slices. The harness verifies each expected failure, cleanup during unwinding, and continued execution with fresh roots.
- `tests/e2e/testdata/accept/library*.ms`: compiler-to-native execution for exact JSON numbers, duplicate-key/depth failures, codecs, hashes, binary range limits, compression, ZIP, and generic sequential callbacks/function values.
- `tests/e2e/log_test.go` and `tests/e2e/testdata/projects/logging/`: real CLI run/build, cross-module logger calls, timestamped stdout, file append across processes, concurrent child records, and failure exit statuses without partial log output.
- `tests/e2e/testdata/stdlib/log.ms` and `pkg/runtime/library_log_test.go`: typed JSON records, all levels, child binding precedence, record budgets, custom/source transports, append-only files, timestamps, cause preservation, concurrent writes, interrupted close, and cancelled file acquisition.
- `pkg/runtime/library_test.go`: malformed strict encodings/numbers, signed 64-bit binary boundaries, surrogate/duplicate-key JSON validation, PBKDF2 vector, AEAD tampering, Ed25519, compression trailing bytes/bombs, ZIP/TAR paths/limits, exclusive filesystem writes, symlink-safe removal, HTTP duplicate headers/status/redirect/limits, and TCP half-close/round-trip, empty/oversized UDP datagrams, socket close/cancellation, and Network close interrupting active HTTP requests.
- `tests/e2e/testdata/projects/library/main.ms`: native CLI acquisition/use of FileSystem, Entropy, WallClock/Timestamp and System roots, including exclusive creation and removal.
- `pkg/compiler/library_test.go`: every registered function is importable, and opaque BigInt/Regex/Timestamp constructors are rejected.
- Existing host, service, compiler/cache and e2e tests remain required. The runtime embeds all new implementation sources for standalone builds and content pinning; test sources are excluded from the runtime bundle.

Run `go test ./...`, `go test -race ./pkg/runtime ./pkg/checker ./pkg/compiler ./pkg/tooling`, and `go vet ./...` with Go 1.25 or newer. Native platform limitations are documented per package rather than inferred from a familiar module name. Written future requirements are not counted as passed tests.

Use `make stdlib-check` for source checking and the public-module fixture inventory; it also runs in `make verify`. Use `make stdlib-test E2EFLAGS=-count=1` for a fresh native stdlib run. Individual fixtures can also run directly with `ms test tests/e2e/testdata/stdlib/encoding.ms`. Full `make e2e` and `make coverage` include the suite automatically. Network fixtures use only loopback and require local socket access; filesystem tests use scoped temporary directories, and TLS uses a public fixture key and fixed certificate.

The inventory ensures every public module has a checked fixture with test blocks. It does not measure exhaustive API or branch coverage. Intrinsics are exercised through primitive receiver calls; unimportable private declarations are excluded from the module inventory. OS-specific controls, custom DNS, native watchers, mutual TLS, HTTP/2, cancellation races, and other deeper host paths retain their existing Go runtime and native conformance checks. Native subprocess execution verifies observable behavior but does not contribute to the Go statement-coverage profile.

Networking checks additionally cover scoped host/CIDR policy (including raw-IP bypass rejection), custom DNS records, listener reuse after timeout, Unix half-close, cancellation during acquisition, pooled cookies/redirects, HTTP/2, custom trust/hostname validation, mutual TLS, duplex streamed upload/response, decompressed WebSocket bounds and shutdown joining hijacked sessions. `tests/e2e/testdata/projects/networking/main.ms` exercises HTTP streaming and WebSocket echo through the compiler and an offline native build.

Host compatibility checks additionally cover `pkg/runtime/library_host_parity_test.go` (Node-generated path/glob fixtures, exclusive opens, positional/vector I/O, line bounds, stream adapters, metadata, tree-copy symlinks, directory EOF, temporary cleanup, watch/timer close and cancellation, OS/process information, and environment parsing; native watch event retention/overflow, copy filters/clone/timestamps, glob exclusions/link cycles, exact stat metadata/numeric flags, after/every restart and shutdown, native constants, and signal streams). `scripts/node-stdlib-fixtures.cjs` refreshes the offline oracle with Node.js 24. The native CLI fixture exercises the new capabilities through Manuscript source. `pkg/compiler/node_host_coverage_test.go` checks every inventory mapping against the current declaration surface; a live Node.js 24 check verifies module exports and returned FileHandle/Dir/Timeout methods against the complete inventory. Runtime-specific facilities stay classified separately. Linux/macOS/Windows CI runs native compatibility checks with CGO disabled. Platform helpers are included in `NativeDependencies` for standalone builds and the compiler/runtime content pin.
