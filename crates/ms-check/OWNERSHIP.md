# Ownership (value semantics)

`Hir::ownership()` enforces the value-semantics memory model of `crates/DESIGN.md` (decision 1) and exposes the moves, drops and borrows lowering needs. It runs on every program that type checks, and its rejections are diagnostics. Rejections carry mechanical fixes (`--json`). Conformance fixtures tagged `aliasing` rely on shared mutation and stay outside the Rust gate.

```rust
let own = program.hir().ownership();
own.diagnostics                       // rejections
let f = own.of(&callable).unwrap();   // CallableOwnership
f.use_at(name_expr.id, &binding)      // Use { access: Copy|Borrow|Mutate|Move|Write, last }
f.bindings[&binding.uid]              // BindingFacts { role, class, owned, borrows }
f.calls[&call.id]                     // CallModes { receiver, arguments, returns_receiver, .. }
f.lambdas[&lambda.id]                 // LambdaFacts { escaping, captures: [(binding, Move|Borrow|Mutate)] }
f.temporaries                         // owned values dropped at the end of their statement
f.consumed_scrutinees                 // match/if-let whose payloads own their parts
f.drops_old                           // assignments storing over a binding (drop flag; cleared by a Move)
f.parameters, f.receiver              // inferred ParamMode: Borrow | Mutate (var) | Consume
```

## Model

- **Classes.** `Copy` (scalars, and records/alternatives/tuples of scalars), `Move` (strings and everything else owned; a borrowed string stored in an owned position needs `.clone()`), `Resource` (types with cleanup, and records, alternatives, `Optional`, `List` and `Map` values that hold one; move-only, never `.copy()` or `.clone()`). A `List[T]` is `Resource` exactly when `T` is, a `Map[K, V]` when `V` is; otherwise it stays `Move`; a resource is not `Hashable`, so a `Set[R]` or `Map[R, V]` is rejected, so collections of plain values pay nothing. `Shared[T]` (`@std/shared.ms`) is the only refcounted source type: `Copy` class, read through `get()` and changed with `take()`/`put()`, whose exclusivity is checked at runtime. Another copy of the handle can replace the value while a reader holds a result, so `get()` lends only within its expression: a `let`, loop or `match` over it holds a copy, a `ref` function cannot hand it back, and `var x = h.get()` is rejected; a `Shared` of a `Resource` payload is still `Copy`, and the payload closes when the last holder releases it (the box's drop glue calls the payload's closer, shielded, unless a `lock` guard has taken the payload out). Type variables are `Move` (conservative); handle types are `Copy`-class handles, their `with` resources `Resource`.
- **Owned parts.** A `Resource` binding nothing moves on is closed when its scope ends, parts included: the lowering (`close.rs`, `close_with_parts`) generates one closer per type. The type's own `Closeable.close` runs first, then its parts in reverse order: record fields last declared first, the fields of the active alternative case last first, an `Optional` payload, list elements last index first, map values last inserted first (maps and sets iterate in insertion order, so no order is unspecified). A part whose type is not `Resource` adds no code. A part that already closed itself sees a second `close`, which the contract makes harmless. An unconstrained type parameter is `Move`, so a generic local `List[T]` is not closed even when instantiated with a resource; bound it with `T: Closeable`. Overwriting or removing a part of a live container closes the old part first (`r.f = x`, `xs.set`, `xs.remove`, `m.add` over an existing key, `m.remove`, `m.clear`; lowering `close_discarded`); `xs.pop()` returns it to a binding, which closes it. `splice` closes the elements it deletes; `fill`, `copy_within`, `merge` and every method that returns a new collection or element built from the receiver's (`concat`, `take`, `drop`, `slice`, `reversed`, `sorted`, `filter`, `find`, `distinct`, `chunks`, `group_by`) copy values and are rejected for resources; a `Set` never holds a resource. `get(default)` on a resource-holding `Optional` or `Result` takes the payload out of its receiver and consumes it.
- **One owner.** A `Move`-class value passed to a consuming position (consuming parameter, record/list/map element, `return`, `let`/`var` initializer from a non-place, closure capture of an escaping closure) is moved. A move is legal only at the value's last use (backward liveness; loops use a head fixpoint; reassignment kills the old value). Use after move is an error.
- **Modes.** Parameter modes are inferred by a program-wide fixpoint: `Borrow` (read), `Mutate` (declared `var`), `Consume` (moved/stored/returned). `var` is declared in the signature (`var xs: T`, `var fn` receivers) and written at the call (`f(var xs)`); the marker is required exactly where the callee takes `var`. There is no `mut`.
- **Mutability.** `let` is immutable including contents; only `var` bindings, `var` parameters and `var fn` receivers change. Fields/elements of a `var` binding are changed through it.
- **Overlap.** Operands that a call keeps hold of (a `var` argument, a `Move`-class borrow, a closure capture) must not overlap: `f(var a, a)` and `f(var r, r.items)` are rejected. A `Copy` value computed before the call (`f(var xs, xs.length())`) is fine.
- **Borrows are lexical.** Payload bindings, loop variables, accessor results and `let x = a.b` / `a[i]` / `let y = x` hold a borrow of their origin until the holder's last use (payload and loop borrows last the whole arm/body). While held, the origin cannot be changed, reassigned or moved; closures that mutate a capture hold it exclusively (reads are also rejected). Moving out of a borrow is rejected (`.copy()` first).
- **Mutable borrows.** `var x = a.b` / `a[i]` binds an exclusive borrow of the part, for scalars as well as records and collections (`n += 1` writes through; bind a `let` first for an independent scalar): changes through `x` change the origin, which must itself be changeable (`var`). While `x` is live nothing else may read, change, move or borrow the origin (so there is only one mutable borrow at a time; disjoint fields are fine). `x` cannot be reassigned or moved out, and ends at its last use. `let x = a.b` stays a shared borrow. `if var x = a.get(k):` borrows the payload the same way for the branch. A borrow taken through another mutable borrow (`var it = b.items`) may be used while `b` is live, but not the reverse. Lowering names the origin's place instead of copying (`ms-lower/src/alias.rs`), so every exit path writes through; the CLI always runs this pass on functions that hold a mutable borrow. `var x = <call result>` owns.
- **One borrow fact for lowering.** `Ownership.borrows` maps each binding that borrows a place to `Shared` (`let`, payloads, loop variables) or `Exclusive` (`var`). A binding of a temporary owns its value and is absent, so lowering never points a binding into storage freed at the end of the statement; lowering lends a binding (no copy, no drop) only when this fact says so.
- **Borrowed results.** A call result is a read-only borrow of the arguments it may come from. A function lends when a `return` gives back a part of a read-only parameter or receiver (`self.item`, `xs[0]`, or another lending call); the second fixpoint in `ownership/mod.rs` records the parameters in `Summary.result` after the modes settle. `let y = f(b)` holds `b` unchanged until the last use of `y`; a result that is stored, passed to a consuming parameter, captured by an escaping closure or returned from a local's part is rejected (the remedy is `.clone()`). `var y = f(b)` is a mutable borrow when every return is one plain field path of the same parameter (`fn list() List[Int]: return self.items`) and `b` is the call's only argument; it behaves exactly like `var y = b.items`, and lowering reads the path from `Ownership.getters`. Any other `ref` call bound with `var` is rejected: write `.clone()` to own a copy, or bind it with `let`. A call of a `ref` interface operation lends from its receiver and arguments, since every implementation lends (a receiver or argument that is a temporary, or a value converted to the interface for the call, makes it owned); a call of an owning operation or through a closure gives an owned result. A function that also consumes the parameter it lends from is rejected.
- **Borrow-carrying records (`ref` fields).** A record field may be written `name: ref Type`; the record is then a *carrier*: it owns its other fields but only views the place its `ref` field was built from. A `ref` field is given a variable or a part of one (a computed value is rejected). `let it = c.cursor()` or `var it = Cursor(source: c, ..)` holds the origins until the binding's last use, like a lending call result. Inside a method, a lending result reached through a `ref` field is a *held* origin of the receiver (`Slot::Held`), so `it.next()` freezes the source rather than `it`, and `it` can advance while earlier items are live. A carrier is linear and non-escaping. Its hold follows it only through one binding at a time: `let b = it` moves the hold to `b` (`it` must not be used again), `return it` hands it to the caller when every source it holds is a read-only parameter (the summary names those slots, as for a constructor call in the `return`), and `let c = it.clone()` binds another carrier holding the same sources (a clone anywhere else, or of a temporary, is rejected). Anything derived from a holder (a call result over it, a binding of its `ref` field, a closure capturing it) also holds the holder's sources, so they stay unchanged after the holder itself is gone (`with_held`). It cannot be reassigned, captured by an escaping closure, moved into a call, constructor, collection or field, compared, hashed, or converted to an interface, and a `ref` field cannot be assigned after construction, and a path through one is read-only (no `var` receiver, `var` argument, `var` binding or assignment through `it.source`), since the view shares its source's storage; a function may return one only by constructing it from read-only parameters. Carrier types are `Move` class. In MIR a `ref` field has type `ref<T>`, a non-owning view with T's leaves that is never dropped (`ref.new`, `ref.get`).
- **Lending from a `var` receiver or parameter.** A `ref` function may return a part of a `var` receiver or parameter (`var fn next() ref Optional[T]` returning `some(self.current)`). The caller's binding holds that argument unchanged until its last use, so `it.next()` cannot be called again, or `it` changed, while its result is live; reads stay allowed. A function without `ref` still cannot return such a part. The MIR verifier treats a `var` parameter's `take`, `rec.set` and `rec.fill` values as that parameter's storage.
- **Explicit `ref` (staged).** A result type may be written `ref T` (`fn list() ref List[Int]`): the checker requires every `return` to give back part of a parameter or the receiver (or `none`): a path that returns an owned value, a `try` exit, a closure call result or a call of an owning interface operation, or a lending call over a temporary or default argument (also through a `let`, loop or payload binding of it) is rejected, since the caller would read a borrow of something freed at return. An implementation lends exactly when its interface operation is declared `ref` (a scalar result, a number, `Bool` or an optional of one, is the same either way; a `Shared` handle is not exempt); `Error.message` owns its result. A part converted to an interface at the `return` is a new value, not a part. A native accessor given a fallback (`o.get(default)`, `xs.get(i, default: d)`) returns an owned copy, not a borrow. A scalar argument never makes a lending call over a temporary owned, since it holds no storage. A call of a `ref` callee whose summary names no slot yet (recursion, or a callee walked later) counts as lending (`CallModes.pending`), and a later pass names its slots. The summary iteration runs up to one round per callable plus a margin; if it has not converged by then, every `ref` callable is taken to lend from all its arguments for a last pass, so a cap never accepts a borrow the true summary would reject. The verifier's `lent_masks` starts every lending callee `f` reaches at no parameters and grows the masks together to a fixpoint. Bindings take no marker: a projection, loop variable or payload borrows, and `let ref`, `var ref`, `for ref` and `match ref` are parse errors. A `var` binding of a call to a `ref` function that is not one plain field path of its only argument is rejected instead of silently copying. `return some(part)` in a `ref Optional[T]` function lends the part, as does returning a match payload of a read-only parameter. Lowering hands back the borrow without a copy (`Func.ret_borrowed` in `ms-mir`; the result of a call is not released by the caller) for every function in `Ownership.lenders`, which is every checked `ref` function. In checked code a `match`, `try` or `for` over a borrowed part reads it in place, and in a lent instance a `let` borrow takes the lent form of `first`, `last` and `Map.get`, so a part reached that way can be handed back. The MIR verifier rejects a lent `ret` whose value is, or is projected from, a value the function owns (`sources` in `ms-mir/src/verify.rs`, which follows a lending call only through the arguments its callee lends from), so a lowering copy can never be lent. The optimizer's `lastuse` pass counts a lending call's result in its arguments' family, so it never moves an argument's drop above a use of the borrow. A function without `ref` that returns an owning interface call result or a lending call over a temporary returns an owned value (`ResultOrigin.owned`). Lowering marks a `ref` operation's `MethodSig.ret_borrowed`: its vtable thunks call the implementation's lent instance and `call.method` yields a borrow; a native or `var def` implementation of a `ref` operation is a lowering error. A method value of a `ref` operation (`let f = n.names`) is an owning closure, so its thunk copies the lent result (`call_method_owned`). `ref` appears only in a declared result type, never in a function type, field, element or type argument. A lambda cannot return a borrow of its parameter, so `opt.and_then(lambda x: x.get(k))` on a lending `get` does not check: read levels with `if let`. The marker is required: a function whose `return` gives back part of a parameter or the receiver without `ref` in its result type is rejected (the fix is `ref`, or `.clone()` to return an owned copy), and a native lends exactly when its standard-library declaration says `ref`; there is no inference from the result type's shape.
- **Match / destructuring** consumes an owned last-use scrutinee (payloads own their parts, `consumed_scrutinees`); otherwise payloads are borrows. A parameter matched or iterated at its last use is borrowed (the function stays `Borrow` for it) unless a payload or loop variable is moved out; that move makes the scrutinee consume the parameter, found by the same fixpoint as closure escapes. `var` in a case payload is rejected.
- **Interface conversion.** A value passed where an interface is expected is converted implicitly and follows the position: a read-only argument borrows it and the interface value owns a copy (`a.compare(b)` leaves `b` usable), a stored position moves it at its last use. Interfaces are never constructed (`Iface(value: x)` is rejected). `Clonable` is a structural bound like `Equal`: it gives a type parameter `.clone()`, which is how a generic container returns an element it still stores.
- **Closures.** A closure that is returned, stored or passed to a consuming parameter *escapes*: it owns its captures (moved at creation, so the captured variable is dead afterwards) and may not change them or move them out when called (it can run many times: return `x.copy()`). A non-escaping closure borrows its captures lexically; one that changes a capture borrows it exclusively, and lowering gives that variable a memory slot the closure reads and writes through (`slotted` in `ms-lower`). Escape is inferred per module by fixpoint; native callbacks on collections are non-escaping.
- **Mutators** (`append`, `set`, ...) take their receiver `var` and return `Unit`-like unusable results: chaining and using the result are errors.
- **`.clone()`** is the temporary spelling of `.copy()` (deep value copy); diagnostics say `.clone()` until the rename (`COPY` constant in `walk.rs`).

## Open decisions: resolved here

| Decision | Resolution |
| --- | --- |
| Projections vs copies | Projections (`a.b`, `a[i]`, accessors, payloads) **borrow**; they cannot be moved out of or changed through a `let`; `.copy()` produces an owned value. |
| Mutator results | Unusable (statement position only); no chaining. |
| Closure escape | Escaping closures own captures (move at creation, no mutation/move-out of captures in the body); others borrow. Inferred per module. |
| Generic copyability | Type variables are `Move`; no `Copy` bound. Monomorphization may copy when the instance is `Copy`-class. |
| Handle types | `Copy`-class handles; resources are `Resource` (move-only, no `.copy()`). |

## String views

`trim`, `trim_start` and `trim_end` on a string held in a variable return an immutable view into it: the checker treats the result as a borrow of the receiver (declared `ref String` in `stdlib/intrinsics.ms`, the same rules as an accessor), so `let t = s.trim()` holds `s` unchanged until `t`'s last use and a result that is stored, passed to a consuming parameter or returned from a local is rejected with `.clone()` as the remedy. Nothing is allocated for a view; strings stay immutable (there is no in-place trim). In the runtime a view is a `StrVal` with `cap == STR_VIEW_CAP`: dropping it frees nothing, copying it allocates, and the scalar-count cache ignores it. A view of a temporary receiver (`read_line().trim()`) is an ordinary owned string. Lowering emits a view only when the receiver is a variable place, which is a subset of what the checker treats as a borrow, so a view never outlives its source.

## Behavior changes for the migration tool

Programs written for reference semantics change as follows:

1. **Aliasing is gone.** `let b = a` of a `Move`-class value borrows (if `a` stays used, `b` is a read-only view that blocks changes to `a`) or moves (last use). Code relying on two names changing one object must pass `var` explicitly or restructure.
2. **`.clone()` is deep** and renamed `.copy()`; `.clone()` for a cheap shallow share becomes a borrow (or, once planned `Shared[T]` exists, a `Shared[T]`).
3. **Mutator chaining/results** (`xs.append(1).append(2)`, `values.prepend(0).set(1, 9)`) become separate statements; results of mutators are not values.
4. **Implicit parameter mutation.** A function that changes a parameter declares it `var` and every caller writes `var` at the argument.
5. **`let` is deeply immutable.** `let xs = []; xs.append(1)` becomes `var xs`.
6. **Closure capture is by borrow or move,** not by snapshot of a shared reference; a closure that mutates its capture exclusively borrows it, an escaping one owns it.
7. **Iteration while mutating** the iterable (`for v in xs: xs.fill(..)`) is rejected.
8. **Accessor-then-mutate** (`let first = xs[0]; xs.append(..); use(first)`) is rejected; `.copy()` the part or finish using it first.
9. **Field assignment through calls/borrows** (`receiver(log, v).val = ...`, `let alias = rec; alias.f = 1`) is rejected; assign through the owning `var`.

## Limits

- Indexed assignment `xs[i] = v` has no syntax yet (`set` is the mutator).
- `var` parameters, `var` call arguments and `var fn` are syntax additions (`ms-syntax`: `Param.mutable`, `Argument.mutable`, `Method.mutating`).
- Native modes come from `collection_mutation` plus type-shape heuristics; a native that consumes an argument without a collection signature is treated as `Borrow`.
- Moved-on-every-path is not tracked forward: `drops_old` is a may-drop fact paired with a drop flag cleared at `Move` uses.
- Impl-vs-interface mode agreement is not checked yet.
