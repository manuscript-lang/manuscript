# Interface conversions of borrowed values are views

Decision (Chinmay, 2026-11-01, "tagging makes sense, let's do it, save on clones"): converting a borrowed value to an interface (`return cause` as `Error`, `error(cause)` as `Int!`, `let e: Error = cause`, a widened lending call, `try` of one) builds a view, never a copy. The vtable word's low two bits say what the interface value owns (0 box and payload, 1 box only, 2 nothing); a function returning one is a *view lender* (`Lend.view`, `Func.ret_view`) whose result the caller owns and drops while holding the arguments. Stage 2 of [proposals/views.md](../../proposals/views.md), PR #2211.

Verified (leak-check, 2026-11-01): an interface with a `var fn` operation (`ReadStream`, `WriteStream`) must keep copying a borrowed operand (`contract_mutates`, checked in both `view_source` and `fit_ty`). Natives such as `copy` call `var fn` operations on the box without the checker's `var` discipline, so a write into a box of borrowed leaves frees the owner's value and leaks the new one (`io-generic-streams.ms` writing into a `Mem` sink). A checked `var` call already requires `var x: Sink`, so Manuscript code never reaches this; do not widen views to mutating interfaces until natives take `var`.

Verified (adversarial review, 41 programs under valgrind): a view local handed on without the checker noticing is the hole to test for. `let e = first_error(cause); return relay(e)`, `return id(first_error(cause))` and `let e2 = e; return e2` each dangled or ICEd until `view_moves` covered relays of a view local and `let e2 = e` at `e`'s last use handed the box on; with `e` used later, `e2` is a plain reference into `e`'s box (origin `e`, not `cause`), so returning or relaying it is rejected. The checker and lowering must agree on what is a view: when the checker calls a conversion a view but lowering copies, the result is still owned and sound; the reverse (lowering lends, checker thinks copy) is a use-after-free.

Verified (bug bash, 2026-11-01): an interface value has no `.clone()` (`Error` offers only `message`), so a remedy that says `e.clone()` is a dead end and its machine fix breaks the build. Ownership diagnostics for interface and function values (`no_clone` in `walk.rs`) say to use the value in place or convert a clone of the concrete value. Probed ~60 adversarial programs under valgrind (Debug and Release) over wrapped lends, view locals, conditionals, closures, tasks and resources; the checker held.

Apply when: changing interface conversion, `fit_ty`, view lenders, the vtable layout, `copyelim`/`lastuse` on owned results, or adding `var fn` to a stdlib interface (its conversions start copying again; say so in the PR).
Evidence: [OWNERSHIP.md](../../crates/ms-check/OWNERSHIP.md), [DESIGN.md](../../crates/DESIGN.md), [interface_views](../../crates/ms-check/tests/ownership/accept/interface_views.ms), [interface_view_held](../../crates/ms-check/tests/ownership/reject/interface_view_held.ms), [e2e interface-views](../../tests/e2e/testdata/accept/interface-views.ms).
Verify: `fn first_error(cause: Cause) Error: return cause` compiles with no copy and `first_error(c).message()` after `c.code = 5` sees 5; `let e: Error = cause; return [e]` is rejected with a `.clone()` remedy; `make leak-check` passes with `io-generic-streams.ms` swept.
