# Results borrow parts of their arguments without a marker

Decision (Chinmay, 2026-11-01): the language has reference semantics with one owner and no reference counting. Primitives copy; a string, record or collection has one owner, bindings and arguments borrow it, storing it moves it, and only `.clone()` copies. A function whose every return path is a part of a parameter or the receiver lends that part, inferred by the ownership fixpoint (`Summary.result`); a path that returns a new value next to one that lends is an error with a `.clone()` remedy. Lambdas and interface implementations always own their results, because the caller cannot know what runs. This reverses the 2026-10-31 decision that results own their value and getters return `.clone()`, which made ordinary code clone-heavy (#2147) and left native lends unheld (#2181).

Latest direction (Chinmay, 2026-11-05): `ref` is removed from the language; do not teach a `ref` construct, borrowing fields or migration guidance as a language feature. At this audit, `token.rs` still maps the word to `Tok::Ref` and parser diagnostics reject it, so removing the obsolete public teaching does not establish ordinary-identifier acceptance. Coordinate lexer/parser removal separately from documentation.

Apply when: changing result types, bindings, interface operation agreement, iteration protocols, native borrow shapes or the ownership pass. Do not reintroduce a lending marker or a borrowing record field; do not make a value copy implicitly to avoid an error (Chinmay: every copy is `.clone()`, and changing an origin while a `:=` of it is live stays an error).
Evidence: [reference-ownership proposal](../../proposals/reference-ownership.md), [remove-ref proposal](../../proposals/remove-ref.md) (superseded), [ownership notes](../../crates/ms-check/OWNERSHIP.md), [references](../../documentation/core-language/types/references.md), [borrow-returning function fixtures](../../crates/ms-check/tests/ownership/accept/).
Lesson (adversarial review, 2026-11-01): a returned borrow held across a sibling operand is the use-after-free shape to test for. `two(label(r), mutate(var r))`, `label(r) + mutate(var r)` and `items_of(r)[idx(var r)]` all passed the checker and segfaulted or printed garbage until the overlap check learned to see `var` and consumed arguments nested anywhere inside a sibling operand; a change that finishes inside its own operand is not a clash. A `var xs = f(b)` alias of a borrow-returning call must still run the call for its effects. When adding a lending shape (projection of a call, conditional arms), add it to `borrow_source`/`pure_origins` and to the lowering join in the same change, and run the program under valgrind in Debug and Release.

Lesson (views, 2026-11-01): wrapping a borrowed part into `Optional` or `Result` (`return ok(r.name)`, `return r.tags[0]` as `String?`, `?` on a borrowed error) is a reference, lowered with `opt.view` / `alt.view` ([proposals/views.md](../../proposals/views.md)). Two shapes were tried and rejected: making a mixed function (borrowed path beside a new value) return runtime-tagged "views" only moves the `.clone()` from the callee's one arm to every caller that stores the result, so mixed paths keep their error; and a wrapped lend beside an owned path is withdrawn rather than reported when both build the same case. Superseded 2026-11-04 (Chinmay: Result, Optional and `?` may return a borrow without owning; "we need to make the language machinery work without copy"): when the borrowed wrapper and the owned paths build different cases of a `Result` (`value?` beside `ok(new)`), the result is a borrowing result with per-case ownership, no copy, no runtime tag ([proposals/try-relays.md](../../proposals/try-relays.md)). `Optional` is not covered yet. Converting a borrowed value to an interface is a view too: see [interface conversions of borrowed values are views](interface-conversion-rules.md).

Lesson (native lends as lend sources, 2026-11-03): `lend_source` knew only places and borrow-returning call, so `fn at(i: Int) T?: return self.slots.get(i)` owned (copied) its result although `List.get(i)`, `first`, `last` and `Map.get` are native lends. `List.get(i)` without a default joined the native lend list (`native_lend_receiver`) and is a lend source whose field chain ends at the element, so `Deque.at` lends. The other native lends (`m.get(k)`, `first`, `last`) stay out of `lend_source`: they wrap the element in an `Optional` that lowering builds by copying the entry (`msrt_map_get`), and an `opt<alt>` is boxed and cannot be a view, so a first attempt to make them lend sources returned an clone from a `ret_borrowed` function (`lookup` in `toml.ms`: "owned value is never released"). Beside a path that returns a new value, `xs.get(i)` is withdrawn like a wrapper (the element is copied out) rather than reported; a bare `return none` owns nothing and never withdraws a lend. The new borrow surfaced two standard-library sites that changed a list while a `:=` of `xs.get(i)` lived (`toml.ms` `flags`, `yaml.ms` `raw`); they now write the `.clone()` they used to get implicitly. Evidence: `Deque.at`; `make copy-check`.

Verify: `fn list() ref List[Int]` is a parse error; `fn list() List[Int]: return self.items` is accepted and `var xs = b.list(); xs.append(1)` changes `b`; `x := m.get("a"); m.remove("a")` is rejected; the MIR of a borrow-returning function carries `ret_borrowed` and its callers never release the result.

Lesson (declared copies, 2026-11-04): Chinmay ruled that `Result` and `Optional` are simple helper types that need not follow the allocation rules of other types, and that the codebase must not be littered with `.clone()`. He then clarified that the special handling he meant is **lending, not copying**, as long as it does not leak. Lending landed for `Result` in #2563 (per-case borrowing variant) and `?` of an owned local moves its error out; `owned_wrap` is gone. What still copies is the same as for any other type: a borrowed part stored into new owned storage (`failure = result.err()`, a wrapped argument) is an `owned` copy that the strict-copy gate reports, tracked with the strict-copies work, not a Result or Optional rule. `Optional` has one payload case, so a function that returns a borrowed `x?` on one path and a new value on another cannot lend per case; it keeps the copy. Rejecting mixed borrowed/new return paths was implemented and dropped: it broke two frozen conformance fixtures (`testtailresultidentity*`) and made the common `try param` then `ok(..)` relay need `param.clone()?`.

Lesson (boundary copies, 2026-11-05): borrowing covers `Result` cases that a function returns, but a borrowed part that is stored into an `Optional` or `Result`, or read back out of one into an owned binding (`some(p.name)`, `?.` chains, `find` items, `get(default)`, a combinator passing the other case through, `o := found.get()`), still copies, and Chinmay's ruling is that these helper types need not follow the allocation rules of other types and must not need `.clone()` everywhere. Lowering declares those copies (`owned_boundary`, and `boundary_reads` for the `get()`/`err()` payloads it borrows) so the strict-copy gate accepts them; everything else a borrowed part is stored into is a build failure (the gate is always on). A borrowing temporary's borrowed error is borrowed by `err()`, not copied. Evidence: `make copy-check`; the strict-copy gate is now always on.
