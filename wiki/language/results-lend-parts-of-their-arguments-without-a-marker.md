# Results lend parts of their arguments without a marker

Decision (Chinmay, 2026-11-01): the language has reference semantics with one owner and no reference counting. Primitives copy; a string, record or collection has one owner, bindings and arguments borrow it, storing it moves it, and only `.clone()` copies. A function whose every return path is a part of a parameter or the receiver lends that part, inferred by the ownership fixpoint (`Summary.result`); a path that returns a new value next to one that lends is an error with a `.clone()` remedy. Lambdas and interface implementations always own their results, because the caller cannot know what runs. `ref` stays a reserved word so the parser can say what to write. This reverses the 2026-10-31 decision that results own their value and getters return `.clone()`, which made ordinary code clone-heavy (#2147) and left native lends unheld (#2181).

Apply when: changing result types, bindings, interface operation agreement, iteration protocols, native lend shapes or the ownership pass. Do not reintroduce a lending marker or a borrowing record field; do not make a value copy implicitly to avoid an error (Chinmay: every copy is `.clone()`, and changing an origin while a `let` of it is live stays an error).
Evidence: [reference-ownership proposal](../../proposals/reference-ownership.md), [remove-ref proposal](../../proposals/remove-ref.md) (superseded), [ownership notes](../../crates/ms-check/OWNERSHIP.md), [references](../../documentation/core-language/types/references.md), [lender fixtures](../../crates/ms-check/tests/ownership/accept/).
Lesson (adversarial review, 2026-11-01): a lend held across a sibling operand is the use-after-free shape to test for. `two(label(r), mutate(var r))`, `label(r) + mutate(var r)` and `items_of(r)[idx(var r)]` all passed the checker and segfaulted or printed garbage until the overlap check learned to see `var` and consumed arguments nested anywhere inside a sibling operand; a change that finishes inside its own operand is not a clash. A `var xs = f(b)` alias of a lending call must still run the call for its effects. When adding a lending shape (projection of a call, conditional arms), add it to `lend_source`/`pure_origins` and to the lowering join in the same change, and run the program under valgrind in Debug and Release.

Lesson (views, 2026-11-01): wrapping a lent part into `Optional` or `Result` (`return ok(r.name)`, `return r.tags[0]` as `String?`, `try` on a lent error) is a reference, lowered with `opt.view` / `alt.view` ([proposals/views.md](../../proposals/views.md)). Two shapes were tried and rejected: making a mixed function (lent path beside a new value) return runtime-tagged "views" only moves the `.clone()` from the callee's one arm to every caller that stores the result, so mixed paths keep their error; and a wrapped lend beside an owned path is withdrawn rather than reported, so existing code that mixes `ok(p.name)` with `try risky(n)` keeps owning its result. Converting a lent value to an interface is a view too (Chinmay, 2026-11-01: "tagging makes sense, let's do it, save on clones"): the interface's vtable word carries a tag (0 owns box and payload, 1 the box only, 2 nothing), so `return cause` as `Error` lends `cause` as an owned `iface.lend` box the caller drops; such a *view lender* (`ret_view`) may mix a new value with a view, since both are owned. A view in a position that outlives its origin (a store, a capture) is the same error as any lend; the fix is an owned conversion (`cause.clone()`), never a copy inside the callee. Copy elision must not turn a copy of a view into a move (`view_tainted` in `copyelim`), and `lastuse` must treat a `ret_view` result as pointing into its arguments.

Verify: `fn list() ref List[Int]` is a parse error; `fn list() List[Int]: return self.items` is accepted and `var xs = b.list(); xs.append(1)` changes `b`; `let x = m.get("a"); m.remove("a")` is rejected; the MIR of a lender carries `ret_borrowed` and its callers never release the result.
