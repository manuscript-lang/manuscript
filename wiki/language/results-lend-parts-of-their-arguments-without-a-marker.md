# Results lend parts of their arguments without a marker

Decision (Chinmay, 2026-11-01): the language has reference semantics with one owner and no reference counting. Primitives copy; a string, record or collection has one owner, bindings and arguments borrow it, storing it moves it, and only `.clone()` copies. A function whose every return path is a part of a parameter or the receiver lends that part, inferred by the ownership fixpoint (`Summary.result`); a path that returns a new value next to one that lends is an error with a `.clone()` remedy. Lambdas and interface implementations always own their results, because the caller cannot know what runs. `ref` stays a reserved word so the parser can say what to write. This reverses the 2026-10-31 decision that results own their value and getters return `.clone()`, which made ordinary code clone-heavy (#2147) and left native lends unheld (#2181).

Apply when: changing result types, bindings, interface operation agreement, iteration protocols, native lend shapes or the ownership pass. Do not reintroduce a lending marker or a borrowing record field; do not make a value copy implicitly to avoid an error (Chinmay: every copy is `.clone()`, and changing an origin while a `let` of it is live stays an error).
Evidence: [reference-ownership proposal](../../proposals/reference-ownership.md), [remove-ref proposal](../../proposals/remove-ref.md) (superseded), [ownership notes](../../crates/ms-check/OWNERSHIP.md), [references](../../documentation/core-language/types/references.md), [lender fixtures](../../crates/ms-check/tests/ownership/accept/).
Verify: `fn list() ref List[Int]` is a parse error; `fn list() List[Int]: return self.items` is accepted and `var xs = b.list(); xs.append(1)` changes `b`; `let x = m.get("a"); m.remove("a")` is rejected; the MIR of a lender carries `ret_borrowed` and its callers never release the result.
