# `main` skips plain frees at exit, and the stack limit lives in the region

Verified (2026-11-12, `bench/perf/structural-gaps`): freeing a 500k-entry map when `main` returns cost 45 to 70 ms of a 211 to 243 ms program. `ms_mir::exit_drops` gates the drops on `main`'s return paths whose type is plain memory behind `msrt_exit_frees`; the counting runtime (`ms-rt/stats`, so `make leak-check`) and `MS_FREE_AT_EXIT=1` keep them. A closure, an interface value or an opaque handle is never gated (`Module::drops_plain_memory`), and a `main` that something calls again keeps every drop. Add a type that closes something to the not-plain side, never to the list of plain ones.

The recursion check reads the limit from the region word beside the task block's address (`STACK_LIMIT_CELL`), one load from the masked stack pointer. Every writer of `Hdr::limit` must follow with `task::publish_limit()` (fault depth reserve, guard exit, segment grow and return); `publish_region` rewrites every segment's cell when a task is switched in, because tasks share a region's slots. A new place that changes the limit without publishing it makes the check use a stale value: too high faults early, too low skips the grow.

A small directly self-recursive function is unrolled once into itself by the MIR inliner (`self_unroll_source`): the copies have no check or frame, so `fib(32)` fell from 137.8M to 98.4M instructions. Fault frames are compared by text because the copy's scope names its function by another table offset; the report's walk spends one step per logical frame, so inlining never changes how deep a diagnostic reaches.

Evidence: [`exit_drops.rs`](../../crates/ms-mir/src/exit_drops.rs), [`task.rs`](../../crates/ms-rt/src/task.rs), fixture `e2e/accept/main-exit-closes-resources`.

A recursive cycle keeps one stack check: `strip_depth` keeps it on the targets of the depth-first back edges only (`cycle_breakers`) and runs before and after inlining, so the unchecked functions on a cycle inline into their callers. Anything that inlines a checked function into an unchecked one would leave a cycle with no check; the inliner never inlines a function that still opens with `depth.enter`.

Leak check in the C port (verified 2026-11-23; the Rust `make leak-check` is gone): programs link the glibc or musl runtime with no sanitizer, so run the built binary with `MS_FREE_AT_EXIT=1 MIMALLOC_SHOW_STATS=1` and read the `allocated ... current` column and the `not all freed` bins; a clean program shows 0. Use the `ms build`, then run, for `phase=run` fixtures; for `ms test` the first `allocated` row is the test binary and the second is the compiler (a compile error leaves only the compiler's row). The runtime baseline is zero under `MS_FREE_AT_EXIT=1` (`release_process_memory` in `entry/start.c` frees the pipe cells, net loop thread, curl engine, serve registry, stream table, stdout captures, kept test faults and each thread's drop worklist), so any nonzero count is a real leak. `ctest -R leak_check` (`cmake/LeakCheck.cmake`, list in `cmake/targets/cli.cmake`) asserts it on a set of fixtures; add a fixture there when a leak is fixed. A noreturn function must not own heap memory: faults built with a string builder call `ms_fault_built`, which frees the builder (a plain `ms_fault(..., ms_strbuild_span(&b))` leaks it on every fault). Fixed this way: a method thunk that consumes its receiver frees the interface box, and a view of a kept resource is `iface.borrow`. A function that returns an interface view is a view lender (`ret_view`): `iface.own` copies the payload into a fresh tag-1 box (size word after the vtable slots) so the caller owns and drops it (#6639, fixture `interface-views`). The runtime prints the allocator statistics itself at the end of `release_process_memory` (`ms_core_heap_report`) and turns mimalloc's exit-time print off: on Windows the exit-time print was missing for `http-close-drains` (other threads alive at exit; cause not proven), so a check cannot rely on atexit. A failing leak_check prints the whole statistics table, whose per-bin `current` column names the size of what leaked.
Leaks fixed with #6656 (verified 2026-11-23, all in the `leak_check` list): a native declared `move key: T` must consume the key itself; the Set and Map natives (`msrt_set_add`, `msrt_set_remove`, `msrt_map_remove`, `msrt_map_remove_take`) declared `key: *mut u8` (lowering then treats the operand as taken) and dropped it, instead of copying or borrowing it. A native that edits the value of its slot argument in place (`@keeps` in its `ms-sig`: list `set`, `insert`, `remove`, `replace`, `splice`, `swap`, `copy_within`) keeps the slot an unwind cell, so a fault inside it (an index error) still frees the list; without the flag a `call.rt` use made the slot uncovered and the whole list leaked. `msrt_list_set` stores the new element before it drops the old one, because that drop may fault in a close. In the unwinder a move-out of a value a call or constructor just made takes the whole value and opens no hole (`uw_call_defs`). Known gap: a plain (non-closing) element passed to `set` or `insert` leaks if the index fault comes first, because nothing covers the incoming value across that native (closing elements go through a closing slot).

Argument faults and owned arguments (2026-11-23): a native that takes an owned argument and faults on a bad index or range leaves that argument owned by no one, so it leaks. Such a native carries `@checks=<native>` in its `ms-sig:`; the check is a small native that faults exactly as the main one does (`msrt_list_check_set`, `_replace`, `_insert`, `_fill`, `_splice`, taking the list length and the call's integer arguments), the main native calls the same check, and lowering calls it first (`fn_native_precheck`) when the element owns memory and is not a resource (a resource is covered by its closing slot; dropping it again double closes). A native declared `move value: T` must consume `value` (`List.fill` used to treat it as borrowed and leaked it on every call) and an in-place editor needs `@keeps`. How these were found: a generated program per owned-argument method of `List`, `Set` and `Map`, each run once with valid and once with out-of-range integers under the stats runtime in a promise, failing on any live block at exit. Tests: `accept/faulting-close-releases-parts`.
