# Runtime guard exits skip native Rust destructors

Verified: production `msrt_guard_call` exits faults and cancellation with a jump, so a Rust
`Drop` guard alone cannot release a response body's active read. Register a runtime cleanup
for state removed across a park; discard it on ordinary return. Interrupted decoders are
closed and abandoned rather than resumed with potentially partial state.

Apply when: native operations take state or resource ownership across a cancellable wait.
Evidence: [response body guard and cancellation regression](../../crates/ms-std-net/src/http/client.rs), [runtime guard](../../crates/ms-rt/src/fault.rs).
Verify: `make leak-check` on `tests/conformance/fixtures/e2e/stdlib/tasks-cancel-release.ms` reports zero live blocks; use the production runtime dependency (not `ms-rt`'s own unwinding unit-test guard), assert a stack destructor is skipped, join reports cancellation, later reads return Closed, and the peer observes connection release.

Same class, found by a soak (client aborts mid-body leaked ~1 fd per few hundred connections): a server exchange held an `Rc<dyn Io>` clone across `wait_fd`, so a handler cancelled while parked kept the socket open after `close_conn`. `HeldIo` in `http/exchange.rs` owns that clone through a cleanup. The client's shared 64 KiB read buffer, taken out of its thread-local for the read, leaked once per fetch cancelled by a timeout (`rt::Parked<T>`, aliased `ParkedBuf` for buffers, now frees it through a cleanup).

The same applies to the request itself: `Client::send` owned its method, URLs, header vectors and pool key in locals, about 340 B per cancelled fetch (#3008). They now live in one `Sending` struct behind `rt::Parked`, and the helpers borrow from it. Measure with `memory_usage().heap_used` over thousands of cancels; `tests/conformance/fixtures/e2e/stdlib/http-fault-leak.ms` pins it. `make leak-check` cannot see either (Rust heap, not `ms-rt` blocks): count `/proc/<pid>/fd` under load instead.

Main-isolate scheduler state is a `ManuallyDrop` thread-local; `run_main` calls `task::teardown()` in every build so valgrind sees no definite losses in an empty program (#2470). Check new per-isolate state is released there.

A promise's closure is dropped when its task ends, which closes what it captured. That drop runs shielded (`promise::task_ended`): a task ended by a cancel still has the cancel pending, and a close that parks (a WebSocket's close frame) would otherwise re-enter `msrt_cancelled` with no guard and exit the program with 143 (#3041).

The HTTP/2 client had the same gap: a request cancelled while waiting for its response left its `H2Stream` open on the shared connection (never reset), so after about a hundred cancels the peer's stream limit was full and later requests on that connection timed out, and its request headers leaked. `exchange_h2` now holds the stream and headers in `rt::Parked`; `tests/conformance/fixtures/e2e/stdlib/http2-cancelled-requests.ms` pins both. The last 16 B per cancelled h2 request was the `Box<Release>` of a socket-drive turn, now a `Parked<Release>` whose drop releases the turn (#3046). The in-process "15 B" after a redirect was the test's own server, whose sleeping handler outlives the cancelled client: measure client leaks with the server in another process.

A `Listener` registers each accepted connection with its owning `Network`, whose lists are not thread safe, so a `promise(fn:)` that accepts must run on the listener's thread. `Listener` now holds a `sched::Pin` touched on creation and accept, which keeps promises started on that thread there (#3047, fixture `net.ms`).

A closure that moves its `var` parameter through a local slot to a helper (`serve_buffered` passes the exchange to `read_body` this way) made the helper "unsafe" for the unwind pass, which then left the caller's slot uncovered: a buffered handler cancelled on its request body leaked the 16 B interface view `serve.stream` holds (#3083). `slot_safe_params` now follows a taken value through local slots that hold only that value, and `function` treats what is taken back out of such a slot as the caller's. Dropping it there too freed the view twice (live blocks `-1`), so read a negative count from `make leak-check` as a double free. Tests: `ms-mir/tests/unwind.rs`, `http-hardening.ms`.

Preferred fix for a Rust park (#3087, [proposal](../../proposals/cancel-by-return.md)): call `wait::try_wait_fd`, which returns `Err(rt::Cancelled)` instead of jumping, and propagate it with `?` so ordinary destructors run; `ffi::report`/`code` ask `rt::cancel_pending()` and run `msrt_cancelled()` once the Rust frames are gone. The sweep sets the cancel flag at the injected park, as a real cancel does, so code that swallows the error fails at its next park. Converted: dial, connection reads and writes, TLS handshake, HTTP/1 and HTTP/2 client, DNS pool wait (`pool::try_run`); `Parked`, `HeldIo`, `HeldWire` and the read-state cleanup are gone, so those frames hold plain locals. Also converted: HTTP/2 server `h2_wait` and `process::command::run` (its `Reaper` kills and reaps on return; the FFI function raises the cancel). Also converted (#3108): fs `poll_cancel` returns a failure (`fs_status*` and `io::status` raise the cancel at the boundary), `read_file` closes its fd by plain code, stream waits and pipe-readiness waits use `try_task_wait_fd`, terminal `next_event` and writes return a failure (`terminal::fail` raises), and `Server::close_inner` finishes closing every connection and returns `Cancelled` after the drain (`close_resource` shields it). Windows adopted pipes (`glue::pipe::read/write` return `Stop::Cancelled`), `process::command::run` parks (`Waiter::park`, `try_task_sleep`, `object::try_wait`) also return. Also converted (#3161): `pool::run_shielded` and `admit` return `Result<_, Cancelled>` (`ms-std-fs` `offload` maps it through its `Cancelled` trait: `Res`, errno results, `bool`), `Subprocess::wait`, the signal waits, `park_until_exit`, and the watcher and Windows readiness sleeps (they ignore the early wake: the caller's next `poll_cancel()?` returns). Still jumping, deliberately: `pool::run` (test caller only), the entry `poll_cancel()` of terminal and bigint natives (they hold nothing, so a jump skips no destructor), and `msstd_fs_admit` (it raises at once, nothing held). A `Drop` that parks during this unwind is not shielded: take an `rt::Shield` first (`H2Stream::drop` does). Code that classifies an error afterwards asks `rt::cancel_pending()` first, so a cancelled park is not recorded as a connection failure (`Session::failed`), and a body whose read was cancelled is closed (`ResponseBody::produce`) since its decoder cannot resume.

A boundary that raises the cancel must drop the error it holds first (soak, 2026-11): `ffi::report` and `code` (net), `fs_status*` and io `status` kept the failure's text alive across `msrt_cancelled()`, which jumps, so every call cancelled mid-read leaked the `"cancelled"` String (~1 per cancelled fetch, found by a leak tracer: allocation under `Connection::failure`). A boundary that takes the error by value drops it before the jump; `http-fault-leak.ms` pins it with `heap_used`.

Sweep `heap:` hits that were not frame leaks (#3087, #3108): `run_shielded` skipped the job's output when the cancel applied after the job (`pool.rs` drops it first); the scheduler mailbox's grown capacity is freed by `teardown` (`sched::release_mail`, fresh buffers at `shutdown`); the sweep injected a cancel at a worker's idle root park (`sweep::internal` excludes it); `promise-semantics.ms` varies by a block between identical uncancelled runs, so the sweep compares against the largest of five uncancelled runs. `heap:` now fails the sweep. Trace a hit with a scratch allocation-site tracer (a counting `GlobalAlloc` that records frame-pointer stacks, symbolized with addr2line; not committed).
