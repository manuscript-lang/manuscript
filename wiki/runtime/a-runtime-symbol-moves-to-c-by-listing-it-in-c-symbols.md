# A runtime symbol moves to C by listing it in `runtime/symbols/<module>.txt`

Verified (2026-11-20, Linux x86-64): `cargo xtask runtime` compiles `runtime/{sys,core,io,net,std}/**/*.c` (see [the C libraries](the-c-libraries-are-folded-into-each-runtime-archive.md)) with clang per target (musl gets `--target`; `third_party` and `tests` are skipped) and adds the objects to every archive with `ar`. `ms-rt/build.rs` reads `runtime/symbols/<module>.txt` only when xtask sets `MS_C_RUNTIME`, and emits `cfg(ms_c = "<symbol>")`; the Rust definition carries `#[cfg(not(ms_c = "<symbol>"))]`, so the archive has one definition and `cargo test` and clippy keep the Rust one. To port a symbol: write it in C, declare it in `runtime/include/ms_rt/<module>.h`, list it in `runtime/symbols/<module>.txt`, gate the Rust fn, and run `cargo xtask symbols --check`, which fails when the header and the recorded signature disagree or a header function is unlisted. C unit tests live in `runtime/tests/core_*.c` and run under ASan and UBSan with `make c-test` (nightly, not the PR gate).

Rules: C under `core` and `sys` includes only freestanding headers (`stdint.h`, `stddef.h`, `stdbool.h`) so one source builds for glibc, musl and mingw; a symbol whose state is shared with Rust (the allocator, a table both sides touch) moves together with every Rust reader of that state, never alone, because Rust code inside `ms-rt` calls its own copy directly and would bypass the C one.

The allocator moved as one group (verified 2026-11-20): `msrt_alloc` is the switch for the whole Rust module (`crates/ms-rt/src/alloc.rs` picks `alloc/c.rs`, a binding, or `alloc/rust_heap.rs`, the old implementation kept only so `cargo test` runs without the C archive). Rust-only callers keep the `alloc::alloc` names. A C function the Rust runtime must supply (out of memory) is an unlisted `msalloc_*` symbol, because a module header may only declare listed functions. C code that needs the system goes through `runtime/sys` (`ms_sys.h`, `mssys_*`), with the few libc functions declared by hand so no libc header is included. Counting (`stats`) builds still use the Rust allocator and fail to compile with `MS_C_RUNTIME`.

A symbol that Rust code inside `ms-rt` also calls (lists, descriptors) is gated with `#[cfg_attr(not(ms_c = "<symbol>"), unsafe(no_mangle))]` instead of `#[cfg(not(...))]`: the Rust function stays for Rust callers under its mangled name and only the exported name goes to C, so no `extern` declarations are needed (verified 2026-11-20 with `nm`: `msrt_list_push` is `T` in `list.o`). A header with data (`msrt_desc_*`) lists one function of its group for the switch. C calling something Rust still defines declares it in `runtime/core/rt_calls.h`; `runtime/tests/support/rt_stubs.c` stubs those for the unit tests. `cargo xtask symbols` maps the role aliases `ElemDesc`, `KeyDesc`, `ValDesc`, `ValueDesc`, `CmpFn` and `ErrSlot` to pointers and `HasRaw` to `uint8_t`.

Apply when: porting any runtime symbol to C or changing the C build. Evidence: `crates/xtask/src/main.rs` (`add_c_runtime`, `check_c_abi`), `crates/ms-rt/build.rs`, [proposals/c-runtime.md](../../proposals/c-runtime.md). Verify: `cargo xtask symbols --check`, `make c-test`, the conformance corpus on the built archive.
