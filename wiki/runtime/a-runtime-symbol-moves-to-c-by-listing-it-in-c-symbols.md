# A runtime symbol moves to C by listing it in `runtime/symbols/<module>.txt`

Verified (2026-11-20, Linux x86-64): `cmake -P cmake/BuildRuntime.cmake` compiles `runtime/{sys,core,io,net,std}/**/*.c` (see [the C libraries](the-c-libraries-are-folded-into-each-runtime-archive.md)) with clang per target (musl gets `--target`; `third_party` and `tests` are skipped) and adds the objects to every archive with `ar`. `ms-rt/build.rs` reads `runtime/symbols/<module>.txt` only when xtask sets `MS_C_RUNTIME`, and emits `cfg(ms_c = "<symbol>")`; the Rust definition carries `#[cfg(not(ms_c = "<symbol>"))]`, so the archive has one definition and `cargo test` and clippy keep the Rust one. To port a symbol: write it in C, declare it in `runtime/include/ms_rt/<module>.h`, list it in `runtime/symbols/<module>.txt`, gate the Rust fn, and run `cargo xtask symbols --check`, which fails when the header and the recorded signature disagree or a header function is unlisted. C unit tests live in `runtime/tests/core_*.c` and run under ASan and UBSan with `make c-test` (nightly, not the PR gate).

`runtime/sys` is the exception to "a symbol is a native": its `ms_sys_*` functions (declared in `runtime/include/ms_rt/sys.h`, as module `sys`) are the runtime's own door to the OS, listed in `runtime/symbols/sys.txt` like any symbol but without a recorded signature to compare in `check_c_abi`. Rust calls them through `crates/ms-rt/src/sys_c.rs`, which stands in for the gated `sys.rs` / `sys_windows.rs` definitions. xtask compiles `sys/posix` (Linux and macOS, constants under `__APPLE__`) or `sys/windows` per target; `make c-test` links `sys/posix` only, so the Windows layer is checked by the corpus on Windows. OS functions are declared by hand beside their constants instead of including libc headers.

Rules: C under `core` and `sys` includes only freestanding headers (`stdint.h`, `stddef.h`, `stdbool.h`) so one source builds for glibc, musl and mingw; a symbol whose state is shared with Rust (the allocator, a table both sides touch) moves together with every Rust reader of that state, never alone, because Rust code inside `ms-rt` calls its own copy directly and would bypass the C one.

The allocator moved as one group (verified 2026-11-20): `msrt_alloc` is the switch for the whole Rust module (`crates/ms-rt/src/alloc.rs` picks `alloc/c.rs`, a binding, or `alloc/rust_heap.rs`, the old implementation kept only so `cargo test` runs without the C archive). Rust-only callers keep the `alloc::alloc` names. A C function the Rust runtime must supply (out of memory) is an unlisted `msalloc_*` symbol, because a module header may only declare listed functions. C code that needs the system goes through `runtime/sys` (`ms_rt/sys.h`, `ms_sys_*`), with the few libc functions declared by hand so no libc header is included. Counting (`stats`) builds still use the Rust allocator and fail to compile with `MS_C_RUNTIME`.


Building strings and lists in C (2026-11-20, split and replace): `ms_rt/strbuild.h` holds the header-only string builders (`ms_str_from_bytes`, `ms_str_view_of`, `ms_str_cloned`, `ms_str_alloc`, ASCII flag and inline rules mirroring `string.rs`); `MsVec` (in `ms_rt/base.h`) is the list value. C allocates through `msrt_alloc`/`msrt_realloc`/`msrt_free` and faults through `msrt_fault`; `runtime/tests/support/rt_stubs.c` stands in for the Rust-owned one-byte string table and fault functions in unit tests. A header with no exported symbols still needs a `runtime/symbols/<module>.txt` comment file. Inline the string builders into the hot loop (`always_inline`): a non-inlined piece builder cost 20% more instructions than Rust on small splits. Needle search for many calls on one text goes through `ms_needle_for` and `ms_needle_find` (rare byte chosen once; one-byte needles scan the first 16 bytes by words before `memchr`); the long path tests 16 starts per vector compare on two needle bytes with portable `vector_size` types.
When other Rust modules call a symbol that moved (`ffi`, `glue`), declare it in an `extern` block under `#[cfg(ms_c = "<symbol>")]` next to the gated definition so their imports still resolve. A C file that needs `msrt_fault` or the ASCII character table (still Rust) declares the symbol locally, and the unit tests supply both from `runtime/tests/support/fault.c`.

A symbol that Rust code inside `ms-rt` also calls (lists, descriptors) is gated with `#[cfg_attr(not(ms_c = "<symbol>"), unsafe(no_mangle))]` instead of `#[cfg(not(...))]`: the Rust function stays for Rust callers under its mangled name and only the exported name goes to C, so no `extern` declarations are needed (verified 2026-11-20 with `nm`: `msrt_list_push` is `T` in `list.o`). A header with data (`msrt_desc_*`) lists one function of its group for the switch. C calling something Rust still defines declares it in `runtime/core/rt_calls.h`; `runtime/tests/support/rt_stubs.c` stubs those for the unit tests. `cargo xtask symbols` maps the role aliases `ElemDesc`, `KeyDesc`, `ValDesc`, `ValueDesc`, `CmpFn` and `ErrSlot` to pointers and `HasRaw` to `uint8_t`.

A native that exists only in C has no Rust function to scrape, so its header carries the table line (verified 2026-11-20): a `/* ms-sig: name(param: type, ..) -> ret @flag .. */` comment above the prototype, in the exact text of a line of `crates/ms-lower/rt_symbols.txt`, and a `/* ms: domain <words> */` comment naming the failure domain of the header's functions. `cargo xtask symbols` reads both, `check_c_abi` compares the sig's kinds with the C prototype, and a symbol with a Rust definition and a header sig must agree or the command fails. `ErrSlot` compares as a pointer and `HasRaw` as a byte. Once a native's sig is in its header the Rust body can be deleted.

Deleting the Rust bodies (string, number and fmt symbols, 2026-11-20): unit tests in `ms-rt` link the C runtime (`build.rs` `link_c_runtime`, all platforms), so a deleted symbol resolves to its C object there; Rust callers and tests declare it once in an `unsafe extern "C-unwind"` block at the top of `string.rs` or `num.rs`, and the `#[cfg(ms_c)]` shims and fallbacks go. Delete a whole group at once: C objects hold several symbols (`fmt.c` defines the `msrt_string_fmt*` joins and the `msrt_fmt_*` kernels), so deleting one Rust body pulls the object in and any symbol Rust still defines from it is a duplicate-symbol link error. Rust unit tests that compared the deleted Rust algorithm with std (shortest float digits, split and search) go with it; the C unit tests own that coverage. Dead helpers surface as `dead_code` warnings: delete until clippy `-D warnings` is clean. A failed CMake build leaves a stale or truncated `libms_c.a` or `libms_native*.a` (a killed build left truncated OpenSSL objects: `xtask runtime` then failed with "adding the C objects ... failed", and a link missed whole C objects); delete `target/ms-native/build*/cmake`, `c-objects` and the `libms_native*.a` and rebuild, and never run `ms run tools/conform.ms` (it runs `cmake -P cmake/BuildRuntime.cmake` itself) while another build or edit of the C is in progress. `__clear_cache` for aarch64 Linux lives in `runtime/sys/posix/clear_cache.c` because the Manuscript link has no libgcc or compiler-rt (PCRE2 JIT needs it).

C natives reach the Rust scheduler through `runtime/include/ms_sched.h` (`crates/ms-rt/src/glue/c_sched.rs`, names `ms_sched_*`, outside the symbol check): cancel by return, the blocking pool (`ms_sched_pool_run` abandons a job on cancel and calls its release on the runtime thread; `ms_sched_pool_run_shielded` borrows caller data, even a stack local), admission permits, and on Windows overlapped pipes and waitable objects. A pool job allocates with `malloc` and never calls the runtime. These shims go away when the scheduler is written in C (W11). `msstd_fs_admit` and `msstd_fs_release` (`runtime/std/fs.c`, header `ms_rt/fs.h`) were the first natives to use them (2026-11-20).

The path-based @std/fs natives moved as the second group (verified 2026-11-20): the OS layer is `runtime/sys/{posix,windows}/fs.c` (`ms_rt/sys_fs.h`: host error codes read only through `ms_sys_fs_error_kind` and `_text`, malloc'd results), the portable layer `runtime/std/fs_support.c` (failures with Rust-compatible text, validated paths, the pool wrapper `ms_fs_run`), `fs_pathname.c` (path rules of both hosts, testable on either) and `fs_ops.c` (the natives). Lessons: a fallible native must write its `err` slot for every failure status, empty when it has no text, because the caller reads it whatever the status (a skipped write made `ms test` segfault only sometimes); `err` may also be null. Linux headers may lack `struct statx` under musl, so `posix/fs.c` declares the kernel layout itself and calls `syscall`. The `std_*` C tests link all of `runtime/std`, so scheduler calls are stubbed in `runtime/tests/std_support/runtime_stubs.c`.

Directories, temporaries, copy and glob moved as the third group (2026-11-20): handles with a path (`fs_dir.c`) are `MsObj` headers with a `drop` that frees with `msrt_free`; a temporary's drop does not remove its tree, `close` does (as in Rust). `copy` and `glob_entries` (`fs_copy.c`, `fs_glob.c`, shared helpers in `fs_tree.c`) run on the runtime thread, not the pool, because the filter is a program closure and the glob matcher allocates with `msrt_alloc`. A closure is `{MsObj header; code}` with the code at offset 16, called with each string as its two words; the temporary strings and every buffer live in one state struct that a `msrt_cleanup_push` frees if the closure faults or is cancelled by a jump. Recursion has a stated depth limit (1024, `LimitExceeded`). Bug found while porting: returning `ok && !excluded && ...` as the visit's result stops the parent's loop for an excluded entry; keep "stop" and "failed" apart. A multi-line prototype under an `ms-sig` comment is not found by `symbols --check`: write it on one line.

Apply when: porting any runtime symbol to C or changing the C build. Evidence: `crates/xtask/src/main.rs` (`add_c_runtime`, `check_c_abi`), `crates/ms-rt/build.rs`, [proposals/c-runtime.md](../../proposals/c-runtime.md). Verify: `cargo xtask symbols --check`, `make c-test`, the conformance corpus on the built archive.

Lists, maps, sets, descriptors and Bytes were deleted from Rust (2026-11-20): `vec.rs`, `desc.rs` and `map.rs` keep only `extern` declarations for the C symbols that Rust still calls, the Rust-only helpers (string builder, UTF-8 decode, the equality-cycle guard), and the layout words `tree.rs` reads. The `safe static` form declares the immutable descriptors so no call site needs `unsafe`. Rust code that built a map from Rust (JSON objects) calls a C primitive (`msrt_map_fill_strings`) instead of copying the table layout.
Streams and files (fourth group): `runtime/std/stream.c` is one host stream object over a descriptor (regular files go through `ms_fs_run` on the pool; pipes and ttys wait with `msrt_task_wait_fd`). Process pipe ends are C streams too: Rust holds them as `ms_rt::ffi::PipeEnd` (ms_stream_new/take_fd/retire), because ms-std-process forbids unsafe. On Windows a console wait and a pipe read run as jobs sharing a ref-counted `SharedJob`, so a cancelled task can abandon the job and the last owner frees it. A header with no exported symbols (`ms_rt/stream.h`, `sys_fs.h`) still needs a comment-only `runtime/symbols/<module>.txt`.
Apply when: porting any runtime symbol to C or changing the C build. Evidence: `cmake/BuildRuntime.cmake`, `cmake/`, `crates/ms-rt/build.rs`, [proposals/c-runtime.md](../../proposals/c-runtime.md). Verify: `cargo xtask symbols --check`, `make c-test`, the conformance corpus on the built archive.

Watchers (fifth group): `runtime/std/fs_watch.c` runs a native watcher on its own thread with its own libuv loop and `uv_fs_event` handles; the thread only queues events under a mutex and posts the token the task parks on (`msrt_token_post_remote`). Linux has no recursive fs event, so a recursive watcher there holds one handle per directory and adds one when a directory appears, reporting its existing entries; macOS and Windows use `UV_FS_EVENT_RECURSIVE`. A bounded read (`ms_sched_read_limit_passed`) must be checked before each park, or a timeout never fires. The polling mode is public API (`WatchOptions.interval`), so it stays, as a snapshot diff on the runtime thread.

Process state (sixth group, 2026-11-20): `runtime/std/process.c` takes the working directory, environment, `send_signal` (`uv_kill`), memory (`uv_get_available_memory`, `uv_get_constrained_memory`, which are cgroup-aware) and rusage (`uv_getrusage`, kilobytes on every host) from libuv; umask, groups, identity and title are `runtime/sys/{posix,windows}/process.c` (`ms_rt/sys_process.h`). libuv's `uv_get_process_title` fails with ENOBUFS unless `uv_setup_args` ran at startup, so the title stays on `/proc/self/comm` (Linux) and the console title (Windows). `ms_fs_fail_uv` maps a libuv code to a status. The signal watcher is C too (`runtime/std/signals.c`, platform halves `runtime/sys/{posix,windows}/signal.c`) but does not use `uv_signal`: libuv replaces the handler without chaining to the previous one, and the runtime's SIGINT/SIGTERM handler (`start.rs`) must run first so a stop request is recorded before an observer wakes. It keeps the self-pipe design (POSIX) and console control events (Windows). A macOS FSEvents stream starts asynchronously after `uv_fs_event_start`, so `fs_watch.c` waits for a readiness file before `watch_native` returns. `info`, `memory_usage`, `runtime_counts`, `uptime`, `elapsed` and `environment_map` read Rust runtime state and stay in `ms-std-process` until startup moves to C; `ms-std-fs` is deleted.

The extern-shim C ABI moved as the eighth group (2026-11-20): `runtime/core/cabi.c` (header `ms_rt/cabi.h`, list `symbols/cabi.txt`) defines the `ms_*_v1` functions of `ms_abi.h` and `msrt_fn_new`; `cabi.rs` is deleted. `ms_*_v1` names have no recorded signature (xtask skips names ending `_v1`); the public header still comes from `ms-rt-abi`. The C file cannot include `ms_abi.h` (its `ms_str_len` clashes with `ms_rt/string.h`), so `MsValue` and `MsListRef` are redefined in `ms_rt/cabi.h` with layout asserts. Shim-visible copies use the C library's `malloc` through `ms_sys_malloc`, because shims free them with `free`. A stop hook handle is the address of its slot. Rust reaches the hooks through `ms_stop_hooks_run` (signal path in `start.rs`). Gate: `core_cabi` plus `ms-cli` `extern_link`.

Child processes (seventh group): `runtime/std/process_spawn.c` runs `run` and `spawn` on `uv_spawn` with one loop thread per child, like `fs_watch.c`: callbacks only record state under the child's lock and post the token a task parks on. The child is `UV_PROCESS_DETACHED` (its own session, so `kill(-pid)` takes the whole group), and `run` kills the group on a limit, a timeout or a cancel and reports a background process that keeps the pipes open after exit 0 as `output_kept_open`. libuv reports no child rusage, so `max_resident` is sampled (`/proc/<pid>/status` VmHWM every 20 ms on Linux, `GetProcessMemoryInfo` at exit on Windows); it can miss a peak between samples, so a child that exits before its first sample reports the process-wide `RUSAGE_CHILDREN` peak (an upper bound). On Windows the job object is assigned after the spawn, so a grandchild started in that window escapes `kill`, and `replace` is `STATUS_UNSUPPORTED`. The Rust `ms-std-process` keeps only process control and signals.
 A remote token counts as a pending wake-up only until its first post, so a native that parks more than once on one child makes a fresh token before each park (`child_arm`); one token for the whole wait is reported as a deadlock when the loop thread posts twice. libuv's forked child sets only the program's copy of `environ` while `execvp` reads glibc's, so `uv_spawn` runs with `ms_sys_swap_libc_environ` under a lock.

Blocking pool (2026-11-20): `runtime/std/pool.c` implements the `ms_sched_pool_*` services of `ms_sched.h` (run, run_shielded, admit, release) on libuv threads (`uv_thread_create_ex`) with a queue under a `uv_mutex`, and wakes the parked task by posting a remote token from the thread. It does not use `ms_io_work`: the reactor is only in the glibc Linux and Windows archives, so macOS and musl would lose the pool. A queued job is removed and released when its waiter gives up; a running one is abandoned and released on the runtime thread at the next submit. `MS_POOL_THREADS` (default 4) is still the thread count. The Rust `glue/pool.rs` stays only for `ms-std-net` and goes with it. `ms_sched_task_pin` (Rust task records) lends the caller's stack to a shielded job; the C scheduler takes it over.

A native the lowerer must call takes at most one `out` result (plus the status and `err`): `msstd_xchg_head` with four outs and `msstd_xchg_next` with a second `reject` out could not be declared in `.ms`, so each became one native per value (`msstd_xchg_method`, `target`, `protocol`, `headers`, `reject_status`; verified 2026-11-20 by writing `stdlib/net/exchange.ms`). A handler's `HttpExchange` is moved into the interface, so the connection loop keeps its own handle (`msstd_xchg_share`) to finish the response; a `var Iface` parameter given a concrete value copies it, so state cannot be read back from the concrete value.
