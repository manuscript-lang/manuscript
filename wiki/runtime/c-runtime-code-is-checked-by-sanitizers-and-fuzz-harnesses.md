# C runtime code is checked by sanitizers and fuzz harnesses, nightly

Verified (2026-11-20, Linux x86-64): `make c-test` runs `src/runtime/tests/core_*.c` and `http1_test.c` under ASan and UBSan. `make c-fuzz` builds each `src/runtime/fuzz/<name>_fuzz.c` harness (`LLVMFuzzerTestOneInput`, aborts on a broken invariant) with the same sanitizers and runs it over the seed files in `src/runtime/fuzz/corpus/<name>/`. Without libFuzzer the portable `src/runtime/fuzz/driver.c` mutates the seeds (exact-size heap inputs, so a one-byte overread is reported); `FUZZER=libfuzzer` (clang with its runtime) gives coverage guidance. 200k inputs take about 2 s per harness. A planted bug (the `\n` check removed from `ms_h1_write_field`) was caught by the harness in 37k inputs, so the harnesses check invariants, not only crashes.

Rules: a new C module with a parser or a buffer writer gets a harness and a seed file in the same PR, and a build line in `src/runtime/tests/fuzz.sh`. A crash input that is fixed joins the corpus. Both targets run nightly in `nightly-safety.yml` (job `c-safety`, Linux and macOS, a date seed so each night explores new inputs); neither is in the PR gate. Windows is not covered yet: it needs the MSYS2 setup from the system-packages work.

Apply when: adding or changing C runtime code. Evidence: `src/runtime/fuzz/`, `src/runtime/tests/fuzz.sh`, `.github/workflows/nightly-safety.yml`.
