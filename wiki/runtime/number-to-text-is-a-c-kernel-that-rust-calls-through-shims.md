# Number-to-text is a C kernel (`src/runtime/core/fmt.c`) that Rust reaches through shims

Verified (2026-11-20, Linux x86-64): decimal and radix integers, shortest `Float` and `Float32` text, and the `to_precision`, `to_exponential` and `to_fixed` forms write into a caller's buffer in C and allocate nothing; the string natives (which build the `StrVal` with the Rust allocator) call them through `num.rs` helpers while `msrt_fmt_*` is listed in `src/runtime/symbols/fmt.txt`. The Rust bodies are deleted (2026-11-20): `ms-rt` declares the C kernels and its unit tests link the C runtime, as on every platform now; fix a formatting bug in C. The JSON writer calls `msrt_fmt_float` too (`src/runtime/std/json_write.c`): Go's float text and the language's agree, so there is one shortest-digits search, in C. The precision forms use an exact base-1e9 expansion (`c * 5^-q`, rounded half to even), not `snprintf`, because `core` includes no libc header and mingw's printf is not exact. The C and Rust output was compared on 13.5M generated lines and 138M binary32 patterns; `src/runtime/tests/core_fmt.c` keeps golden values and checks reading back and printf agreement. The power-of-ten table is generated: `ms run tools/float-table.ms -- c > src/runtime/core/float_table.h`.

The string natives are C too (verified 2026-11-20): `string_fmt.c` (`to_string`, `to_string_radix`) and `string_join.c` (`msrt_string_fmtN`, `msrt_string_append_fmtN`, the f-string joins, written in place onto an owned string). The joins take integers through `ms_fmt_i64_fixed`, which skips the sink; with the sink they cost 15% more instructions than Rust, with it they are 2% under (callgrind, f-string loop). Loops over the parts stay `MS_ALWAYS_INLINE` so a constant count unrolls. Append masks count the appended string as bit 0.

Apply when: changing number formatting or f-string joins, or deleting `ms-rt`.
