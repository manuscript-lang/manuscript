# A native signature change needs a regenerated table and a fresh runtime archive

Verified: lowering marshals native calls from `crates/ms-lower/rt_symbols.txt` (generated by `cargo xtask symbols`), not from the Rust source, and programs link `target/ms-native/libms_native.a`. Adding parameters to `msstd_process_command_spawn` without regenerating its table entry (it was a hand-written catalogue then) made compiled calls pass the out pointer as a mode and segfault inside the native; a stale archive instead ignored the new arguments. Crate tests that call the native directly passed both times.

A default that an implementation inherits from a bundled interface must be one `literal_default` understands (literals, `none`, `[]`, `Map[K, V]()`, `Bytes`, payload-free cases); anything else fails lowering with "missing argument" in programs that implement the interface (`Commands` fakes). A map parameter reaches the native as two lists through `split_map_argument`.

The table spells types as `type_name` shows them with paths dropped (`*const ObjCell<NetH>`), and lowering tests a few spellings by name (`*const ObjCell<`, `*mut Handle<`, `*const Timestamp`, `*mut InfoOut`, `...Wire`, `*const u8`); renaming such a type changes marshalling, so grep `rtcall.rs` and `natiface.rs` first.

Apply when: changing the parameters of any `ms-std-*` or `ms-rt` export.
Evidence: [table](../../crates/ms-lower/rt_symbols.txt), [Stdio default](../../crates/ms-lower/src/call.rs), [called source check](../../tests/e2e/testdata/stdlib/host.ms).
Verify: run `cargo xtask symbols`, `make runtime` and rebuild `ms-cli`, then run a compiled program that calls the native, not only crate tests; `runtime_symbol_catalogue_matches_archive` checks names, not parameters.
