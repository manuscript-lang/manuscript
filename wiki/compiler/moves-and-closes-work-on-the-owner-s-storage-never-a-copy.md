# Moves and closes work on the owner's storage, never a copy

Decision (Chinmay, 2026-11-02, concurrency redesign workstream B, "go with option one"): runtime objects lose their reference count, so lowering may never make a second reference to an object as a way to move or close it. A move takes the value out of its local; a close runs on the value where it lives.

Moves (`crates/ms-check/src/ownership/moved.rs`, `crates/ms-lower/src/func.rs`): the checker records every whole-binding move it accepted (`Program.moves`) and a backward must-move dataflow (`conditional_moves`: the moved bindings some path keeps to the scope end). Lowering keeps three forms. A binding every path moves is in `must_move`: the move takes the SSA value and the scope end drops nothing. A conditionally moved unslotted binding lives in an optional variable (`Local.opt`: `opt.some` at bind, `opt.unbox` on the move then `none`, `Drop` of the optional at scope end), because a stack slot across blocks is invisible to the unwind pass and leaks on cancellation, and because slotting defeated `copyelim`/`lastuse` (release allocations rose in `consumed_buffers`, `record_return`, `wrapper_capture_generic`). A conditionally moved slotted binding keeps a `held` flag and `DropIf`. Assignment to a moved local drops the old value only where the local still holds one; `try` on a local takes it and releases the alt shell (`alt.take`/`alt.release`); a moved var-method receiver is taken and put back; `for` over an owned list takes its elements (`list.take`) and releases the shell past them (`list.release`). A `match`, `if let` or `for` over a local at its last use consumes it: the checker records an ordinary move, and lowering takes the value out of the local (`hold` in `matching.rs`, `for_stmt`), so the match owns the value, arms take their payloads out of it and the other arms drop it. A borrowed scrutinee that lives in a slot or an optional variable is read through a borrow variable there, never through `name()`, which would clear the closer's flag. (An earlier design kept the consumed scrutinee as a checker-only fact and read the local in place; that left the loop variable and payloads as copies of the owner's parts.)

Closes (`crates/ms-lower/src/close.rs`): every close site has either the value's address or an owned value. `close_at_result(ptr)` loads for an interface or borrowing close and passes the address to a `var fn close`; `close_owned_result(v) -> (v', r)` closes an owned value, through a temporary slot when the close writes back. The generated `close_parts` helper takes the holder's address (`writes_back: true`) and closes record fields through `ptr.field`, optional and alternative payloads by take/close/rebuild/put, list elements through `list.addr.u`. A binding whose close writes back, that a resource field moves out of, that some path moves, or that is `var` lives in a slot; its cleanup thunk takes the slot address and sets `Func.slot_close`, which the unwind pass reads to drop what the slot still holds after a fault-time close. Split bindings register `ptr.field` chains; closure captures are closed through the capture's address (`Glue::ClosureDrop`); the `Shared` closer closes the payload through the state's field address. `close_replaced`, `assign_closing`, `close_discarded*` return the closed value for the caller to drop; temporaries use `drop_temp`/`close_finish`/`drop_unused`, which close then drop. A `var fn close` that marks itself closed (`self.open = false`) therefore logs once across an explicit close and the scope end: the fixture `close-in-place.ms` checks exactly that for a binding, a holder's field, an optional, a list, an alternative case, a closure capture, a map value, a reassignment, two fault paths, and the names a record or list pattern binds. A destructuring pattern over an owned value moves the parts out (`bind_pattern`: `ptr.field` + `take` for records, `list.take` for lists) and the checker registers each resource it names for the scope-end close (`pattern_resources` in `walk.rs`); lowering binds such a name with `bind_closing`, whose `closer_opt` falls back to the type's own `Closeable` implementation because a pattern binding's statement names no cleanup method. A part the pattern leaves out (`_`, an unnamed field) is closed and dropped (`drop_temp`), never just dropped. (Before this, a destructured `Latch` was never closed and its stream cell was freed under the binding, #2430.) A binding of a call result owns it whatever the callee was called on: a resource a method on another resource returns (`client.request(..)`, a `StreamingResponse`) closes at the scope end like any other. The checker used to exempt such "derived" results on the theory that the receiver owned and closed them, which was the refcount era's second reference; with one owner it only lost the close (#2435). A borrowed part a `var` pattern binds (`if var value = map[key]?`) is an alias of the holder's entry: a part-wise close of it (`value.close()` on a record of resources) takes the entry out, closes it and puts it back (`close_receiver`), rather than looking the name up as a local.

Apply when: adding a lowering path that reads a moved local, closes a value (a new container, a new cleanup site), registers a cleanup thunk, or emits `Op::Copy` on an object or function type.
