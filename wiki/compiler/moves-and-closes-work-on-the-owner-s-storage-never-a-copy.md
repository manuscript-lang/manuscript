# Moves and closes work on the owner's storage, never a copy

Decision (Chinmay, 2026-11-02, concurrency redesign workstream B, "go with option one"): runtime objects lose their reference count, so lowering may never make a second reference to an object as a way to move or close it. A move takes the value out of its local; a close runs on the value where it lives.

Moves (`crates/ms-check/src/ownership/moved.rs`, `crates/ms-lower/src/func.rs`): the checker records every whole-binding move it accepted (`Program.moves`) and a backward must-move dataflow (`conditional_moves`: the moved bindings some path keeps to the scope end). Lowering keeps three forms. A binding every path moves is in `must_move`: the move takes the SSA value and the scope end drops nothing. A conditionally moved unslotted binding lives in an optional variable (`Local.opt`: `opt.some` at bind, `opt.unbox` on the move then `none`, `Drop` of the optional at scope end), because a stack slot across blocks is invisible to the unwind pass and leaks on cancellation, and because slotting defeated `copyelim`/`lastuse` (release allocations rose in `consumed_buffers`, `record_return`, `wrapper_capture_generic`). A conditionally moved slotted binding keeps a `held` flag and `DropIf`. Assignment to a moved local drops the old value only where the local still holds one; `?` on a local takes it and releases the alt shell (`alt.take`/`alt.release`); a moved var-method receiver is taken and put back; `for` over an owned list takes its elements (`list.take`) and releases the shell past them (`list.release`). A `match`, `if v := x` or `for` over a local at its last use moving_params it: the checker records an ordinary move, and lowering takes the value out of the local (`hold` in `matching.rs`, `for_stmt`), so the match owns the value, arms take their payloads out of it and the other arms drop it. A borrowed scrutinee that lives in a slot or an optional variable is read through a borrow variable there, never through `name()`, which would clear the closer's flag. (An earlier design kept the consumed scrutinee as a checker-only fact and read the local in place; that left the loop variable and payloads as copies of the owner's parts.)

Closes (`crates/ms-lower/src/close.rs`): every close site has either the value's address or an owned value. `close_at_result(ptr)` loads for an interface or borrowing close and passes the address to a `var fn close`; `close_owned_result(v) -> (v', r)` closes an owned value, through a temporary slot when the close writes back. The generated `close_parts` helper takes the holder's address (`writes_back: true`) and closes record fields through `ptr.field`, optional and alternative payloads by take/close/rebuild/put, list elements through `list.addr.u`. A binding whose close writes back, that a resource field moves out of, that some path moves, or that is `var` lives in a slot; its cleanup thunk takes the slot address and sets `Func.slot_close`, which the unwind pass reads to drop what the slot still holds after a fault-time close. Split bindings register `ptr.field` chains; closure captures are closed through the capture's address (`Glue::ClosureDrop`); the `Shared` closer closes the payload through the state's field address. `close_replaced`, `assign_closing`, `close_discarded*` return the closed value for the caller to drop; temporaries use `drop_temp`/`close_finish`/`drop_unused`, which close then drop. A computed receiver of a `var fn` (`open().advance()`) is a temporary too: `restore_var_arguments` closes it through `drop_temp` once the call returns (it only dropped it before, so a stream temporary in `for x in lines(src).wait()` leaked its cell, #2645). A `var fn close` that marks itself closed (`self.open = false`) therefore logs once across an explicit close and the scope end: the fixture `close-in-place.ms` checks exactly that for a binding, a holder's field, an optional, a list, an alternative case, a closure capture, a map value, a reassignment, two fault paths, and the names a record or list pattern binds. A destructuring pattern over an owned value moves the parts out (`bind_pattern`: `ptr.field` + `take` for records, `list.take` for lists) and the checker registers each resource it names for the scope-end close (`pattern_resources` in `walk.rs`); lowering binds such a name with `bind_closing`, whose `closer_opt` falls back to the type's own `Closeable` implementation because a pattern binding's statement names no cleanup method. A part the pattern leaves out (`_`, an unnamed field) is closed and dropped (`drop_temp`), never just dropped. Omitted record fields close in reverse declaration order, including resource types with no heap storage to drop (for example integer-backed stream handles); use `holds`, not just `needs_drop`, to decide whether the field needs cleanup. (Before this, a destructured `Latch` was never closed and its stream cell was freed under the binding, #2430.) A binding of a call result owns it whatever the callee was called on: a resource a method on another resource returns (`client.request(..)`, a `StreamingResponse`) closes at the scope end like any other. The checker used to exempt such "derived" results on the theory that the receiver owned and closed them, which was the refcount era's second reference; with one owner it only lost the close (#2435). A borrowed part a `var` pattern binds (`if var value = map[key]?`) is an alias of the holder's entry: a part-wise close of it (`value.close()` on a record of resources) takes the entry out, closes it and puts it back (`close_receiver`), rather than looking the name up as a local.

Copies (`crates/ms-mir/src/copies.rs`, `make copy-check`): a written `.clone()` lowers to `copy 1` (`FnLower::clone_value`, `Imm::Int(1)` on `Op::Clone`); every other `copy` of a value that holds a closure, interface or runtime object is lowering duplicating what it should have moved or borrowed, and the sweep lists exactly those (a copy of a `none` is exempt). The 2026-11-03 sweep, which had counted explicit clones as sites, found four lowering gaps worth remembering: `List.pop` copied the last element and dropped the original (`list.take` + `list.droplast 1`, whose immediate says the element was taken); `Result.get` and `Optional.get` on a borrowed receiver copied the payload where a borrow serves a reader and a `:=` (an owned receiver hands its payload over with `alt.take`/`opt.unbox`); JSON `parse` copied the decoded value out of the decoder's optional instead of unboxing it; and the default-argument thunk behind a function value (`alias := copy`) copied every supplied argument although the callee borrows them (`unlift_param_borrowed` passes the supplied value through and holds only a built default until the call returns). A copy that remains after those is either a lambda-parameter copy the language rule asks for, a call on a field of a temporary (`make().f()`), or `x := r.get()` of a borrowed `Result`, which the checker treats as owned.

Function values are not `Clonable` (owner decision, 2026-11-03: "anything that contains a function should not be clonable"), and neither is a record, alternative or collection holding one (`Kind::Function => false` in `contracts.rs` `clonable` and `ownership::Classifier::clonable`; `types::holds_function` names the reason in remedies). The standard library kept function-holding values by cloning them, so the redesign that removed those clones is the pattern to follow: `Router` stores each mounted router's middleware once in `groups` and a route names its groups by index; `mount` and `handler` take the router (`var mounted = routes` moves a by-value parameter without a copy, and `drain`/`in_order` empty a list by `pop`, which moves); the middleware chain's continuations are lambdas passed to a function-value call, which lends them, so they borrow the routing table instead of owning clones of it; `cli` walks the command tree with borrow-returning function (`child`, `node_at`, `help_at`, `walk_from`) and `Parsed.Run` carries only the `Matches`, with `Command.run` finding the handler by `matches.path`. The rule reached the corpus too: eight fixtures cloned, filled, took or `get(default)`-ed function values and were rewritten (`clonable-function.ms` was removed; the reject fixtures `clone-holds-function*.ms` and `get-default-takes-borrowed-function.ms` hold the new errors), and a `get(default)` whose receiver is itself a native lend (`m.get(k).get(f)`) of a one-owner payload is rejected at the consuming-receiver switch in `walk.rs`, where lowering used to copy the element. Two lowering limits shaped it: a partial move out of a by-value parameter (`Route(handler: source.handler)`) still copies before `copyelim`, so a value is rewritten in place through a `var` parameter instead of rebuilt from parts, and a call with two or more `var` field arguments (`f(var a.xs, var b.ys)`) copies each field into its slot (`in_place` in `call.rs` handles one), so such calls take one `var` place each.

Cursor walks (#3884): `n := cur.get()` then `cur = n.next` cloned the rest of the list twice per step (20k nodes 15 s, 40k 55 s). Two checker facts fixed it. `get()` at the last use of an owned local records the receiver as moved even for a `Clonable` payload, matching `native_borrow_of`, so lowering `opt.unbox`es instead of copying. A field move that is also the root's last use (`let`/`var`, no resource parts) records the whole root as moved, so lowering takes the field with `move.out` and releases the rest with `type.release`. Fixture: `e2e/accept/linked-list-cursor-walk.ms` (100k nodes, quadratic would not finish). Parameters and resource roots still copy.

Apply when: adding a lowering path that reads a moved local, closes a value (a new container, a new cleanup site), registers a cleanup thunk, or emits `Op::Clone` on an object or function type.
Evidence: [moved.rs](../../crates/ms-check/src/ownership/moved.rs), [close.rs](../../crates/ms-lower/src/close.rs), [close-in-place fixture](../../tests/conformance/fixtures/e2e/stdlib/close-in-place.ms), [resource_field_move fixture](../../tests/ownership-counts/resource_field_move.ms), [concurrency redesign](../../proposals/concurrency-redesign.md).
Verify: `ms run tools/leak-check.ms` sweeps 0 leaking; `ms run tools/count-check.ms` shows no new release-allocation diffs against `tests/ownership-counts/`; `ms test tests/conformance/fixtures/e2e/stdlib/close-in-place.ms` passes 15/15; `ms run tests/conformance/fixtures/e2e/stdlib/close-resource-once-per-owner.ms` prints its expected log.

A `var` resource an escaping closure changes (`promise(fn: send(var writer))`) moves into the closure's environment: the capture is the value, the body works on it in place through `closure.cap_addr`, the capture closer closes it when the closure is dropped, and the maker's scope neither closes nor drops it (#2660; before, the closure shared the maker's slot, so a promise that outlived the scope worked on a closed resource, and the unclosable-drop leaked #2653). Closing is therefore idempotent for pipe ends (`PipeSink.close` clears its id), since the body closes by hand and the environment closes again.

An intact caller-owned resource passed to a borrowed source parameter needs `hold_resource_temp`, including Optional payloads (#2972). Do not remove the generic temporary-wrapper exemption: those other wrappers may already have yielded their payload. Stage arguments in written acquisition order through later operands/defaults, keep borrowed owners registered, and take only consumed/returned-whole owners. Retire a completed temporary with `msrt_cleanup_remove`, not suffix-discard: statement cleanup can occur after a new result-local closer was registered. Exact retirement uses removed tombstones, distinct from canceled entries whose handles remain reserved; only removed tail entries are pruned. A removed handle is never used again on that execution path. Verify mapping/observation, whole and partial returns, newer result-owner faults, failed closes, later argument/default failures, named argument order, and loop-condition cleanup in `source-borrowed-wrapper-temporary-cleanup.ms`.

Interface dispatch has the same intact borrowed-argument duty (#2989): register owned resource arguments in written order before evaluating later operands, retain their guards through the interface call, and leave named borrowed owners untouched. Ordinary temporary borrowing alone loses Optional/Result payload closes. The interface regression fixture covers later `?`, faults, named order, returned owners, failed closes, named `var` controls, and loop conditions; its exact retirement depends on #2972.
An implicit Optional argument converted from a borrowed payload owns only its transport-copy storage, not the original resource cleanup duty. Carry that pre-conversion provenance by parameter slot through named reordering and receiver insertion; exclude it from intact-owner guards. The caller still drops its transport storage under the existing boundary rule. Tests distinguish repeated borrowed reads/defaults from a last-use conversion retained as a moved result, and check later operand/default faults.

List insertion operands retain their registered owner through later written arguments, current bounds, old-entry close and native reserve (#3027). Pass the intact slot to the leaf mutator and retire exactly that registration only after successful consumption; taking it early loses cleanup on validation or overflow. Computed resource-list receivers use their authoritative registered slot, including after reallocation, and close on Unit completion. `set` detaches the already-closed old entry through native replace before dropping its storage: a storage drop can invoke a captured resource closer and fault. Guard a returned replacement owner before closing a computed receiver. Verify negative/end bounds, later fault/try, optional conversion, ordinary/field/indexed/closure-slot receivers, capture-drop faults and repeated transfers in `list-incoming-resource-transfer.ms`; do not silently extend this to the separately tracked bound consuming-call contract (#3049).
Function-value calls add a generated ABI Optional for omittable parameters (#2991). Resolve an owned payload's closer before that lift, then compose the existing in-place Optional closer around it; the generated type has no checker-type entry. Cache by the resolved closer as well as MIR type so implementation evidence is retained. Guard-before-lift would make the borrowed slot pass through an extra boundary copy; global MIR-shape cleanup inference is unnecessary. Capture payload ownership before both source Optional conversion and ABI lifting, leaving named borrowed transport copies drop-only.
Literal list-index identity is numeric, not spelling-based: normalize radix literals before parsing the index. Hexadecimal `d`/`e` digits are not Decimal/exponent markers. Distinct nonnegative literal indexes remain disjoint, equal indexes in different radixes overlap, and computed or negative indexes remain conservative ([acceptance](../../crates/ms-check/tests/ownership/accept/disjoint_hex_indexes.ms), [rejection](../../crates/ms-check/tests/ownership/reject/overlapping_hex_indexes.ms)).

Incoming arguments (`proposals/call-argument-staging.md`, #2989, #3027): an owned argument stays registered from acquisition until the callee stores it, or a fault or later operand failure loses it, and the fault path only runs registrations on the cleanup stack (plain MIR registers are not closed). A resource is registered with `hold_resource_temp`; direct list mutators pass its authoritative slot through validation and storage, then use exact retirement after successful consumption. `close_temp` exempts untracked Optional and Result shells; source/interface calls explicitly register intact owned payloads instead, without acquiring close duty for borrowed transport copies (#3078). Verify with the fixtures `interface-call-closes-optional-temporary.ms` and `list-mutator-fault-closes-incoming.ms`, which log close order to a file. The MIR verifier cannot see a user `close` that never runs, so such bugs need these observable tests.
