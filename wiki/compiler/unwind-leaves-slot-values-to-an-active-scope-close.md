# Unwind leaves slot values to an active scope close

Verified (#2376): after inlining, a mutable method such as `Wrapper.read` becomes `take` from a local slot, a borrowing call, then `put`. The slot's scope close is registered as `close_drop_slot`, which closes and then drops what the slot holds. The unwind pass also registered a drop for the taken value. Cleanups run last-in first-out, so that drop freed the receiver before the older close used it, and two promise faults in a row corrupted the heap.

The fix is narrow. A `take` from a local slot whose scope close is registered and not yet discarded does not own its result when every use only borrows it or puts it back into that slot (`covered_slot_takes` in `unwind.rs`). Coverage is a must-analysis over the control-flow graph that ends at the matching `msrt_cleanup_discard`; after it the value is owned again and gets its own unwind drop. A taken value that is consumed, mutated by `type.set`, moved in parts or returned keeps the old behavior.

The 1000-line #2281 pass was reverted (#2350) because the faulting fixtures lost frames on Windows and macOS; do not restore it, `SharedGuard` or `TaskGroup`.

A slot passed to a `call.ind` is covered when every closure of that arity only borrows the pointer at that position (`closures_borrow`). The compiler-built `serve.stream` thunk keeps the exchange in such a slot, so before this a faulting HTTP handler leaked one 8-byte block per fault (fixture `http-fault-handler-frees-exchange-view`).

A slot pointer a closure captures by reference (`closure.cap` of type `ptr`) is the enclosing function's slot, like a parameter: a `take` from it is the owner's, not the closure's (#3040). Before, a `promise(fn: input.next())` over a borrowed `var input` dropped the stream's source when its limit cancelled the read, and the caller's later `close` crashed. Fixtures: `net.ms` and `http-websocket.ms` (`a read cancelled by its timeout leaves the stream closable`).

A field moved out of a value taken from the caller's slot and refilled (`self.pending.pop()` before a park) yields the same value again, so the `type.fill` / `list.fill` result stays the caller's (#3130). Before, cancelling `fs.watch` mid-read dropped the watcher twice (BTreeMap panic, or a segfault in the allocator later). Fixtures: `fs-watch-cancel.ms`, `leaves_a_record_refilled_after_a_field_move_to_the_caller` in `crates/ms-mir/tests/unwind.rs`.

`expect_fault` runs the operation in a `Placement.Here` promise on every platform (the fork and Windows in-process trap are gone), so anything a fault skips is a leak the leak sweep (`CONFORM_LEAKS`) sees. A `noreturn` fault call gets a cleanup window like any call that can leave, and inline scope-end closes are covered by `cover_inline_closes`. Comparator-taking sort externs are not `leaf`: the comparator is program code that can fault or park. A fault inside a close no longer leaks the closing value's parts (fixture `faulting-close-releases-parts.ms`, which faults inside a `Placement.Here` promise so the leak sweep sees it on every platform). A close that only borrows the slot's value leaves it in place, so a slot drop is registered for the call: around a shielded close call (`cover_shielded_slots`, skipped when the callee or anything it passes the slot to can `take` from it, see `takes_from_slot`), inside `slot_with_closer` while a cleanup runs its close, and for the close's own window (`cover_inline_closes`). `close_parts` of an `Opt` or `Alt` takes the payload out and closes it as an owned local, so the ordinary unwinder releases it (and an `Alt` case's other fields) when the close faults; covering the slot as well would double-free (`source-borrowed-wrapper-temporary-cleanup.ms`). Probed 2026-11-12 with scope-end, pending-fault, `var`, list and temporary shapes: no leak (#3739; fixture `faulting-close-releases-parts.ms`). A closure whose captured resource's close faults still releases that capture's own parts (`ClosureDropFrom` starts at the faulting capture), `list.set` of an element that needs a drop moves the old one out and the new one in before dropping it so the list stays an owned value, and a `drop` of a closure, interface value or handle is a point where the unwinder registers the live owners.

Apply when: changing the unwind pass, inlining of mutable methods, or slot-held cleanup entries.
Evidence: [lifecycle fixture](../../tests/conformance/fixtures/e2e/accept/promise-fault-scope-close-unwind.ms), [MIR controls](../../crates/ms-mir/tests/unwind.rs).
