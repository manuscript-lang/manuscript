# Lowering borrows what the checker already holds as a borrow

Decision: a container read the ownership checker holds as a lexical borrow (`let x = m.get(k)`, `if let x = xs.first()`, `m.get(k).get()`, `m.get_or(k, d)`) must not copy the entry. Lowering reads the entry in place (`msrt_map_get_ptr`, `list.get.u`) and builds `opt.view`, an optional that borrows its payload and is never dropped (`crates/ms-lower/src/borrow_shape.rs`).

The same holds for source borrow-returning functions: a callable in `Program.returns_borrow` lowers with `Func.ret_borrowed`, so `Module::result_mode` classifies its call results as borrows (the verifier, `lastuse`, `copyelim` and `inline` all read that one function), `emit_return` returns the reference without `owned()`, a `let` of the call is bound borrowed, and a lend from a temporary (`Program.owned_borrows`) is copied at the call before the temporary is dropped. The verifier rejects an owned value returned from a borrow-returning function, so a lowering path that still copies shows up as `ret: %v is owned, but this function lends its result`.

Interface views are the owned cousin: a callable in `Program.returns_view` lowers with `Func.ret_view`, `fit_ty` of a borrowed value emits `iface.borrow` (a box of the leaves as they are, vtable tag 1, dropped like any owned value but freeing only the box), and a view local returned at its last use is taken out with its scope drop skipped on that path (`view_moves`, `closed_on_path`). `Module::result_views` tells `lastuse` and `copyelim` that such a result points into the operands; the copy of a value that may be a view is never elided into a move, since the copy is what makes the stored value own its payload.

Apply when: adding a lowering path for an accessor result, a payload binding or a join of two borrows (`two_ways_mode`), a MIR op that produces a borrow, or a new way a call result is bound.
Evidence: [borrowed reads](../../crates/ms-lower/src/borrow_shape.rs), [fixture](../../tests/e2e/testdata/accept/borrowed-container-reads.ms), [lastuse and simplify tests](../../crates/ms-mir/tests/opt_lastuse.rs), [proposal](../../proposals/borrowed-results.md).
Verify: `ms emit` of the fixture shows `msrt_map_get_ptr` and `opt.view`, no `msrt_map_get`; `make stdlib-bench BENCHFILTER=map.get` keeps `map.get_let` within 1.2x of `map.get_chain`.

Lesson (strict-copy gate, 2026-11-05): the gate is unconditional, so a borrowed place reaching an owning position without a declared copy fails the build (`internal: N implicit copies of a borrow at file.rs:LINE (Some(Op)) @src:line:col`). Fix a gap in this order: (1) make the checker record the borrow so lowering binds it borrowed (a `let` of a function-valued field needed `is_place` to stop excluding it; `var x = m.get(k).get()` borrows the entry exclusively, as `if var` does); (2) a move; (3) only then a declared copy: `owned_boundary` for the `Optional`/`Result` payload rule, `clone_value` for a capture or wrapper that owns its own copy, `boundary_reads` for a value the lowering reads as a declared copy, or `.clone()` in the source. The borrowed-signature instance of a function that moves a parameter is the `adapter`: its copies are the declared adaptation, so they are not gaps. `has_try` must skip lambda bodies (a `try` inside a lambda is not the enclosing function's). A sweep for gaps must cover project fixtures, `crates/*/tests/**/*.ms`, `tools/` and `bench/`, not only the accept and stdlib fixtures; `tools/e2e.ms` runs on `target/debug/ms`, so rebuild it first or stale-binary failures look like regressions.

Nonmutating source method environments that own a resource receiver must record its part closer in `Func.capture_closers` (#2892), including ordinary source thunks and default-argument adapters. Preserve this metadata when queued default thunks replace their prototypes. Borrowed/shared receiver addresses carry no closer; their original binding remains responsible. Receiver selection must also preserve borrows of scalar resources even without drop glue (the common #2896 no-drop receiver correction is a prerequisite). `source-bound-capture-close.ms` exercises repeated calls, defaults, generic methods, escaped named receivers, and borrowed/shared controls. Owning temporary mutating methods (#2895) and interface-default adapters are outside this fix; current implicitly resource-owning interfaces provide no nonmutating/default operation that needs this metadata.
