# Lowering borrows what the checker already holds as a borrow

Decision: a container read the ownership checker holds as a lexical borrow (`x := m.get(k)`, `if x := xs.first()`, `m.get(k).get()`, `m.get_or(k, d)`) must not copy the entry. Lowering reads the entry in place (`msrt_map_get_ptr`, `list.get.u`) and builds `opt.view`, an optional that borrows its payload and is never dropped (`crates/ms-lower/src/borrow_shape.rs`).

The same holds for source borrow-returning functions: a callable in `Program.returns_borrow` lowers with `Func.ret_borrowed`, so `Module::result_mode` classifies its call results as borrows (the verifier, `lastuse`, `copyelim` and `inline` all read that one function), `emit_return` returns the reference without `owned()`, a `:=` of the call is bound borrowed, and a lend from a temporary (`Program.owned_borrows`) is copied at the call before the temporary is dropped. The verifier rejects an owned value returned from a borrow-returning function, so a lowering path that still copies shows up as `ret: %v is owned, but this function lends its result`.

Interface views are the owned cousin: a callable in `Program.returns_view` lowers with `Func.ret_view`, `fit_ty` of a borrowed value emits `iface.borrow` (a box of the leaves as they are, vtable tag 1, dropped like any owned value but freeing only the box), and a view local returned at its last use is taken out with its scope drop skipped on that path (`view_moves`, `closed_on_path`). `Module::result_views` tells `lastuse` and `copyelim` that such a result points into the operands; the copy of a value that may be a view is never elided into a move, since the copy is what makes the stored value own its payload.

Nonmutating source method environments that own a resource receiver must record its part closer in `Func.capture_closers` (#2892), including ordinary source thunks and default-argument adapters. Preserve this metadata when queued default thunks replace their prototypes. Borrowed/shared receiver addresses carry no closer; their original binding remains responsible. Receiver selection must also preserve borrows of scalar resources even without drop glue (the common #2896 no-drop receiver correction is a prerequisite). `source-bound-capture-close.ms` exercises repeated calls, defaults, generic methods, escaped named receivers, and borrowed/shared controls. Temporary mutating method values (#2895) are separately handled by upstream #2905; interface-default adapters remain outside this fix; current implicitly resource-owning interfaces provide no nonmutating/default operation that needs this metadata.

Apply when: adding a lowering path for an accessor result, a payload binding or a join of two borrows (`two_ways_mode`), a MIR op that produces a borrow, or a new way a call result is bound.
Evidence: [borrowed reads](../../crates/ms-lower/src/borrow_shape.rs), [fixture](../../tests/conformance/fixtures/e2e/accept/borrowed-container-reads.ms), [lastuse and simplify tests](../../crates/ms-mir/tests/opt_lastuse.rs), [proposal](../../proposals/borrowed-results.md).
Verify: `ms emit` of the fixture shows `msrt_map_get_ptr` and `opt.view`, no `msrt_map_get`; `make stdlib-bench BENCHFILTER=map.get` keeps `map.get_let` within 1.2x of `map.get_chain`.

Lesson (strict-copy gate, 2026-11-05): the gate is unconditional, so a borrowed place reaching an owning position without a declared copy fails the build (`internal: N implicit copies of a borrow at file.rs:LINE (Some(Op)) @src:line:col`). Fix a gap in this order: (1) make the checker record the borrow so lowering binds it borrowed (a `:=` of a function-valued field needed `is_place` to stop excluding it; `var x = m.get(k).get()` borrows the entry exclusively, as `if var` does); (2) a move; (3) only then a declared copy: `owned_boundary` for the `Optional`/`Result` payload rule, `clone_value` for a capture or wrapper that owns its own copy, `boundary_reads` for a value the lowering reads as a declared copy, or `.clone()` in the source. The borrowed-signature instance of a function that moves a parameter is the `adapter`: its copies are the declared adaptation, so they are not gaps. `has_try` must skip lambda bodies (a `?` inside a lambda is not the enclosing function's). A sweep for gaps must cover project fixtures, `crates/*/tests/**/*.ms`, `tools/` and `bench/`, not only the accept and stdlib fixtures; `tools/conform.ms` runs on `target/debug/ms`, so rebuild it first or stale-binary failures look like regressions.

Lesson (wrapper passthrough, #2878/#2883): `Optional.or_else` must preserve the receiver's ownership: `owned_boundary(recv)` transfers an owned wrapper without finishing it, and copies a borrowed data wrapper under the declared boundary rule. The checker requires a move when native `or_else` preserves a non-Clonable payload: Optional’s present value or Result’s success value. Do not test the whole Result: its error is only borrowed by the recovery callback, so a resource error alone must not force a move. A reusable bound method cannot transfer its captured preserved payload on every invocation and requires that payload to be `Clonable`. Do not generalize this to every same-typed method: source methods may return inferred borrows, and `map` may construct an independent resource. Native resource transfer, data/lazy/bound-method controls, and checker guards live in `wrapper-passthrough-resource-transfer.ms`, `optional-or-else-ownership.ms`, and `crates/ms-check/tests/wrapper_passthrough.rs`.

A native receiver held across a later `?` must keep its original ownership until all arguments and defaults succeed (#2887). Register intact resource wrappers with `hold_resource_temp`, not plain `hold_temp`, so an expected-error exit closes their payload. On success retire only this call's registration and restore the owned receiver without refreshing its moved source; genuine borrowed receivers keep their existing borrow. The close-log fixture `wrapper-passthrough-resource-transfer.ms` covers temporary and named Optional/Result receivers on success and expected-error exits, plus a borrowed resource-error control. Owning bound-method capture cleanup is a separate boundary.

Wrapper combinators preserve particular payload slots, not arbitrary equal output types (#2883). Checked native Optional `or_else`/`ok_or`/`ok_or_else` and Result `or_else`/`map_error`/`to_optional` preserve T; Result `map`/`and_then` preserve E. A non-Clonable preserved payload requires an owned receiver, including zero-written-argument conversions of collection lends. Reusable method values require that preserved payload to be Clonable, but callback input resources remain borrowed. Lower preserved Result fields through `take_alt_field_through`, without finishing a transferred receiver again. Checker fixtures under `wrapper_passthrough` and `wrapper-preserved-payloads.ms` distinguish transfer, collection lends, repeated bound calls, and independently created same-typed callback outputs.

Explicit type application on a direct method call does not create a reusable method value (#2906). Reuse checked `method_callee` normalization for receiver modes, call walking, borrowed-result operands, nested writes, and method-value detection. Do not strip runtime index applications, and keep a returned-function call (`get()(x)`) distinct. Specialized direct generic resource transfers and source receiver borrow/mutation overlap controls live beside the preserved-payload tests; valid direct calls need no new Clonable bound.

Wrapper qualification must include scalar-only Closeable payloads: no heap drop glue does not mean no cleanup duty. The existing owning scalar joins from #2908 must still close retained Optional/Result branches and transformed-away owned callback inputs, while repeated bound transforming callbacks leave their captured resource alive. `wrapper-scalar-payload-cleanup.ms` and its exact-stdout ownership-counts counterpart distinguish those cases without hiding duplicate close calls behind idempotence. Borrowed Optional/getter boundaries #2910/#2911 remain separate.

A scalar-only resource still carries a close duty even when MIR needs no heap drop glue (#2910). Zero-argument Optional.get must select its existing borrowed payload path using `holds(inner)`, not `needs_drop(inner)`, or an owning branch join turns the borrowed projection into a second owner. Keep owned scalar joins owning; borrowed Optional and collection-lend controls must remain live through later owner use and close only at the actual owner. `borrowed-scalar-optional-get.ms` asserts this across explicit faults, with owned scalar and heap-resource controls; the matching ownership-counts fixture pins single-close stdout.

Inline container lends must carry the checker's normal held-origin borrow result to lowering too (`BorrowedRead`), not only lexical bindings and return sites. Reuse `borrowed_shape`/`borrowed_read`/`borrowed_optional` inside expression value selection, keeping conversion/wrapping postprocessing and existing boxed/key-conversion exclusions. Do not mark temporary-source owned-borrow or view adaptations as this fact, and do not change arbitrary indirect-call result ownership: reusable bound getter resource results are the separate #2911 boundary.

For the checked single-parameter Map.get call, `key:` is only a binding spelling: it must not turn an inline lend into an owning copy. Borrow-shape recognition accepts both spellings while preserving exact-key-type and boxed-Optional exclusions. Labeled present/missing reads, named bindings, receiver/key once-in-order, and converted-key controls pin that boundary.

An eager `Optional.ok_or(cause)` evaluates the cause even when the receiver is present (#2901). That success arm discards the cause with `close_finish`, not only `finish`: an owned resource closes immediately, while a borrowed cause remains alive with its original owner. The absent arm still transfers the cause, and `ok_or_else` must not execute its skipped callback. `optional-unused-resource-cause.ms` uses a non-idempotent close log to check immediate owned cleanup, owned transfer and laziness, with an ordinary borrowed scalar control. Borrowed heap-data and resource causes have a separate checker/lowering gap (#2903), not qualified by this cleanup fix.

Closing an unused cause can itself fault. Before that cleanup, guard an intact owned resource receiver with the existing resource-temporary registration; retire the guard only after cleanup succeeds, then transfer its payload with no intervening user evaluation. Unboxing first loses the receiver cleanup on the fault path. `optional-unused-cause-receiver-cleanup.ms` checks both the failing cause and successful receiver transfer with a non-idempotent close log.

List loops preserve the lowered iterable ownership (#2943): an `!it.own` list is walked in place. The checker holds its source-origin borrow across the entire loop even for scalar elements with no Shared binding. Do not infer this from syntax or just the element binding: source helpers and receiver methods return borrows too. Fresh results and temporary-owner adaptations stay owned. `borrowed-helper-loop.ms` and `borrowed-helper-loop-cleanup.ms` cover source calls, direct/prebound controls, owned results, and resource-owner cleanup after break/return/try.

String `chars()`/`scalar_values()` scans are different from plain-list iteration (#2945): the source operation produces a fresh list, so the checker does not hold its receiver origins through the loop. The scan optimization may borrow only a source proven unchanged; otherwise it must retain an already-owned string or explicitly copy a borrowed string as the eliminated operation’s snapshot. Do not relax the copy gate or borrow unconditionally. `borrowed-string-loop.ms` compares helper scans with materialized snapshots while source slots are replaced, retains emitted characters, and exercises temporary owners and early exits.

Bound native consuming adapters must declare only their legal Clonable parameter copies (#3053). Capture native argument modes before substituting method parameters away from the generic receiver, then check concrete Clonable eligibility on instantiated parameter types. Exclude erased interfaces recursively: the ordinary Clonable classifier permits an interface whose hidden payload can still lack clone. Mark the actual borrowed values after default/Optional unwrapping, not raw ABI parameters; exclude the receiver and nonconsuming parameters. Do not enable every adapter copy or equate non-Resource with Clonable. `bound-native-clonable-arguments.ms` covers caller reuse, aggregate independence, effects, defaults and faults; consuming Resource callable policy remains separate (#3049).

Lesson (one native-borrow table, 2026-11-12): the natives whose result points into the receiver (`get`, `first`, `last`, `view`, `split`, `lines`, `chars`, `keys`, `values`, `slice`) are listed once, in `ms-check/src/ownership/native_borrow.rs` (`native_borrow`). The checker and `ms-lower/src/borrow_shape.rs` both read it; do not match these names anywhere else. A method written in Manuscript is judged by its body (`ResultBorrow`), never by name. Design: [borrowed parts](../../proposals/borrowed-parts.md).

Copy elision keeps the copy of any value that may be a view (`view_tainted` in `ms-mir/src/opt/copyelim.rs`), and taint must follow the value through memory: a `for` loop keeps the `split` list (views of its source) in a cursor slot, so a write of a tainted value taints the address, and loads and fields read back through it. Without that, `for p in text.split("."): out.append(p.clone())` stored the view and read freed bytes once `text` died; it looked thread-related because only reused heap blocks showed it (#3849, `split-view-clone-outlives-source.ms`).
