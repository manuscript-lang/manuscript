# The C body checker admits maps by key and value type

- `check_map.c` admits `Map[K, V]` with `K` in `Int`, `String`, `Bool` (the key bounds hold without a lookup) and `V` any admitted type; annotations and literals only. An empty literal with no expected type, a `Float` key and every method stay with Rust.
- `m[k]` is admitted when the value is an `Int`, `Float` or `Bool` (a value with one owner would be borrowed in place, which the walk does not follow). The ownership walk moves each entry of a literal. Methods, `var` maps and `for` over a map still go to Rust.
- `lower_map.c` lowers a literal (`msrt_map_new`, one `msrt_map_add` per entry) and `m[k]` through `msrt_map_get_ptr` with a fault naming the missing key, for any key and value the lowering has a MIR type for: owned entries are put in the slots, and layout, hash, equality and drop come from the type descriptors, never from a type list. The lookup entry point (`msrt_map_get_ptr`, or `_w8`/`_sw8` for a one-word key over a one-word value) is chosen from the layout leaves. Rust inlines the probe while lowering; the diff oracle turns that off with `KEEP_PROBE_CALLS` (workaround, #5305) so `m[k]` compares as text, and the interpreter holds maps itself (`mir_interp_map.c`, `MV_MAP`), so it also compares by running. A C pass should inline the probe later.

- A map method the runtime implements (`length`, `contains`) lowers from the runtime's `ms-sig` (`lm_runtime_method`): the generated `rt_ops` table now holds every runtime function with a role per parameter type (map, key descriptor, value descriptor, key by address, value) and the `@word_key_of` / `@text_key_of` twins declared in `map.h`, so no method or symbol is named in the compiler. A parameter with no role marks the method unsupported (it stays with Rust). A one-entry literal evaluates its entry before the map's slot, as Rust does, so the text diff is exact.
