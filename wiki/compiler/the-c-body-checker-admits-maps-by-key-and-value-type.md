# The C body checker admits maps by key and value type

- `check_map.c` admits `Map[K, V]` with `K` in `Int`, `String`, `Bool` (the key bounds hold without a lookup) and `V` any admitted type; annotations and literals only. An empty literal with no expected type, a `Float` key and every method stay with Rust.
- `m[k]` is admitted when the value is an `Int`, `Float` or `Bool` (a value with one owner would be borrowed in place, which the walk does not follow). The ownership walk moves each entry of a literal. Methods, `var` maps and `for` over a map still go to Rust.
- `lower_map.c` lowers a literal (`msrt_map_new`, one `msrt_map_add` per entry) and `m[k]` through `msrt_map_get_ptr` with a fault naming the missing key, for any key and value the lowering has a MIR type for: owned entries are put in the slots, and layout, hash, equality and drop come from the type descriptors, never from a type list. Rust inlines the hash probe, so `lower-diff.sh` marks a function that indexes a map `; divergent` and checks it with the verifier; a literal matches Rust text exactly. The MIR interpreter has no maps, so there is no run comparison. Lists own their own files (`check_list.c`, `lower_list.c`): follow their shape for index, `for` and drops.
