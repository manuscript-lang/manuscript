# Tooling change checklist

Verified: rules gathered from past formatter, LSP, CLI, and diagnostics work; the linked lessons carry the evidence.

Apply when: changing `ms-tooling`, `ms-lsp`, `ms-cli`, `extensions/vscode/`, line tables, or profiling.

Use for `crates/ms-tooling`, `ms-lsp`, `ms-cli`, `extensions/vscode/`, or line tables/profiling. Read [implementation/limits](../../documentation/developer-tooling/implementation.md) and [lessons](../tooling-and-docs/index.md).

- Keep the supplied `Names` handle in editor visitors and look up existing symbols directly instead of re-interning their text through the current session. Retained analysis can outlive the active session guard; test a second empty and populated name table (#3480).
- Derive semantics from checked symbols/types and shared traversal. Direct-recursion lint compares the checked callee symbol even when explicit type arguments wrap its syntax; stripping that wrapper can lose the symbol facts. Reuse one source index per request; do not re-lex names for import usage or generate inspection output just to find a receiver.
- A formatter change that rewraps existing code reformats the repo (`ms fmt stdlib tests tools`; `reject` fixtures stay unparsable) and needs `UPDATE_SNAPSHOTS=1 cargo test -p ms-lsp --test it -- snapshots::`, since navigation snapshots hold stdlib positions. `ms fmt` sorts and merges imports into sections (`@std/`, `@std/internal/`, other) and wraps bare imports over the width into `import (...)`. A formatter change also needs `ms fmt` over every repo `.ms` file except `tests/conformance` and `crates/*/tests`, and every `-fmt` conformance twin re-recorded: `ms-conform record --ms target/release/ms --phase parse`; `tests/conformance` sources stay unformatted on purpose, and `repo-check` covers `bench/` and `crates/` `.ms` files too.
- `ms fmt` output is the fixed point of `format`: a pass that judges the unjoined text (the one-line `if` compaction) can become eligible only after multi-line headers join, so `format` repeats until the compact pass has nothing to do. To find idempotence bugs, format every repo `.ms` file twice, as LF and as CRLF, and diff the passes.
- Formatting preserves semantics and is idempotent for inline/indented suites, defaults, closures, interpolation, and multiline parameters. Use the [compiler checklist](../compiler/compiler-change-checklist.md) for changed syntax/recovery.
- `--drop-labels` preserves comments between label names, colons and values. Find punctuation through lexer tokens, not colons inside comment text; index once when needed, keep forward-copy edit assembly, and count removed labels rather than edit fragments (#3243).
- Semantic-token text and byte positions must use the same original-source coordinate space. Lexer text is CRLF-normalized; use original token spans when splitting multiline tokens and test LF/CRLF parity with Unicode (#3210).
- Code folds use lexer suite boundaries when source lexes, not line-local scans of multiline payloads (#3220). End at the last code token rather than attaching trailing comments to a suite. Keep forgiving indentation fallback for lexically incomplete snapshots; test comments, multiline text, nesting and LF/CRLF.
- Completion context, literal boundaries and private-query delimiter recovery share the tolerant text scanner for multiline snapshots. Test unfinished interpolation, raw quoted payload, nested text, unrelated lexical errors and UTF-16/CRLF positions with actual completion and signature-help requests (#3224, #3225). Recovery must not edit user text or suppress diagnostics.
- Test valid source and incomplete snapshots: preserve neighboring declarations and positions; check navigation/completion with malformed input, LF/CRLF, and relevant Unicode positions.
- Import organization moves complete declarations with their comments, but preserves the import block's final-newline policy separately. Test EOF without a newline, grouped imports, LF/CRLF and idempotence; a moved EOF declaration must not join its neighbor (#3235).
- Crash recovery snapshots share the worker's validated edit decoder and transactional application. Rejected edits must preserve both text and version before replay; test malformed ranges/text, later invalid edits, stale/empty updates and sequential UTF-16 edits (#3415).
- Analysis/completion/workspace discovery share nearest-manifest and canonical identity. Confine overlays; malformed nested manifests cannot inherit parent aliases silently. Edits respect versions, shadowing, and binding identity.
- Diff containment checks normalized parent components with `pathops::escapes`: in-root names such as `..hidden.ms` and `..pkg/part.ms` remain sources, while actual `../` paths stay excluded. Exercise both review findings/diagram overlays and after-state mismatch rejection (#3449).
- Standard virtual documents are checked source: navigate workspace → stdlib, within stdlib, and across modules, including signature types/hover. Keep documents immutable/outside overlays; register their scheme with the client and test restarts.
- Whitespace hygiene uses lexer spans shared by CLI and editor. Never offer deletions inside text payloads, including raw/multiline whitespace-only lines. If lexical boundaries are unknown, withhold destructive whitespace fixes; test LF/CRLF coordinates and actual editor edits (#3208).
- Diagnostics read `<cause>; <fix>`: name the cause, the location, and a concrete fix (nearest name, import line, valid options). Code classification keys on the text before the first `; `, and recovery matches some messages by prefix. Add a hint test for each new message.
- Parse diagnostic remedies are executable examples: after syntax migrations, test foreign-keyword hints with current `call()?` and `if value := result:` forms. Unterminated single-line text at EOF must identify its opening delimiter and a closing-quote repair, including CRLF and Unicode sources.
- `ms check` and `ms lint` take `--fix` to apply machine-applicable fixes (the `fix` field of `--json` diagnostics: misspellings, missing imports, `:=`→`var`, `Some`/`Ok`/`true` habits, `Case()` parentheses, Int→Float and →String conversions, `.clone()`); `ms explain <code>` describes a diagnostic code; `ms run` and `ms test` take `--json` and report a runtime fault as structured data. Diagnostics name the Manuscript replacement for habits from TypeScript, Go and Rust (`unwrap`, `len`, `for (...)`, `Int("1")`), and any camelCase member maps to its snake_case one.
- Watch invalidation must retain loader inputs independently of successful modules: failed parses, confined missing import prefixes and the nearest manifest still decide the result. Preserving only the previous successful graph misses failures present at startup. Exercise repair/creation without touching the entry source, including directory/file links and missing alias targets. Retain negative ancestor-manifest lookups too, so creating a new or nearer manifest wakes a bare-file watch.
- Keep CLI modes, checking, status/output, and native build/run/test paths shared. Source-only commands work without lowering; failed checks preserve outputs. Update command help/examples.
- Before publishing build artifacts, check their directory entries against the requested source, canonical module sources, manifests and embedded inputs. Apply the same check before a cache restore; source freshness alone does not detect an output-directory symlink being retargeted. Preserve distinct metadata links to source by replacing their entries rather than writing through them.
- Diff after-state validation includes added and deleted sources: reverse-check additions against the complete head text and require deleted directory entries to be absent, including dangling links. Do not treat metadata lookup errors as absence. `review_and_diagram_reject_mismatched_added_and_deleted_sources` covers wrong/incomplete/missing additions, existing deletions and valid empty-file controls (#3435).
- For final symlinks with a shared canonical parent and target, distinctness needs two different exact names from that directory. Following links erases their entry identity; case-folding guesses or inode equality cannot distinguish every alias from a safe second link. Reject ambiguous or unreadable listings before publication, and validate actual case-alias lookup on native filesystems.
- Native builds emit DWARF line tables and `app.ms-build.json`; `ms profile` provides folded stacks, pprof, and a top report. Check native artifacts rather than only metadata. `ms emit` prints MIR; there is no `ms debug`.
- CLI text, JSON shape, and exit codes are pinned by the conformance corpus (`make conform`); update `tests/conformance/` expectations deliberately.
- Git metadata-only sections carry their paths in `diff --git`, without `---`/`+++`. Decode the repeated matching path pair rather than splitting at spaces, keep added/deleted empty-file identity, and preserve rejection of binary sections without reconstructable text (#3429).
- Unified-diff ranges must use unsigned decimal coordinates, start nonempty ranges at one, and leave room for traversal's exclusive end or zero-length anchor's following line. Reject invalid ranges in the parser before reverse application or touched-line arithmetic; `hunk_ranges_*` and `review_and_diagram_reject_invalid_ranges_without_panicking` cover these boundaries (#3430).
- Diff traversal must consume the complete hunk body and check old-side positions against the reconstructed prefix, as well as matching new-side positions. EOF notes must follow their side's last line; preserve an old EOF note across later insertion-only hunks. Keep subsequent plain/Git file sections and standard mail-patch signature trailers valid. `hunk_structure_*` and the paired CLI regression cover rejected inconsistencies and valid boundaries. Deleted-file overlays also reverse-apply against the known empty head, so they cannot bypass coordinate checks (#3446).
- Run affected crate tests (`cargo nextest run -p ms-tooling` etc.); client changes need extension tests with pinned Node dependencies. Standalone claims need `make dist-check`.
- Program-map sequence returns belong to traversal unwinding, not to the last emitted event: a leaf call ends in a message too. Test sibling/nested calls, depth limits, recursion and both event/participant caps through the production event builder. Same-participant calls need visible SVG loops; event-only tests miss renderer omissions (`tests/diagram/sequence-rendering.test.cjs`, #3418, #3422).
- `tools/conform.ms` builds a debug `ms` with MIR verification on, so a fixture can fail there and pass in a release `ms`. Reproduce with `target/debug/ms test <file>`. The verifier exempts calls and closures of `keeps_scoped` functions, so inlining and specializing them is safe.

- Keep case-only filename variants in separate filesystem fixtures. The VS Code notice test wrote `thirdpartynotices.txt` and `ThirdPartyNotices.txt` with different contents in one directory, so default macOS filesystems overwrote one despite Linux tests passing. Preserve exact filename/content assertions and sibling-license coverage in each isolated fixture.
- Adding or renaming a `test` block in a conformance fixture changes its recorded `report.tests` list, so the PR also needs `cargo run --release -p ms-conform -- record --ms target/release/ms --id <fixture id>` (verified 2026-11-12: CI failed `e2e/stdlib/text-padding` after a new test was added without re-recording).
