# The language server is C in src/cli, and the Rust crate is its oracle

Verified: 2026-11-23, `src/cli/lsp_*.c`.

Chinmay chose (2026-11-23) to write `ms lsp` in C beside the other commands, not in Manuscript: nothing in the C build runs embedded Manuscript commands, and the C checker already has the occurrence index. This replaces the earlier plan to rewrite `crates/ms-lsp` as a Manuscript program.

- `crates/ms-lsp` is the behavioural oracle: copy its error codes, capabilities, position rules and message shapes, and advertise a capability only once it works.
- Each open document is checked as the entry of its own graph, with every open document's text as the overlay. Only findings in that document are shown.
- Sessions are tested with `tests/lsp/<case>/requests.jsonl` and `expected.jsonl`, replayed over standard input and output by `cmake/LspSession.cmake` (`-DRECORD=1` records). `$ROOT` and `$ROOT_URI` stand for the case directory; the version is `$VERSION`. The script is CMake so it runs the same on all three platforms.
- `file(READ)` turns CRLF into LF, so the replay finds a header's end at a blank line.
- Completion and signature help re-check the document with the word under the cursor replaced by a marker name written as a call (not in type position); the scope walk at the marker gives the locals. Function types intern without parameter names, so names and defaults come from the declaration.
- Analyses are cached per entry file and invalidated by a global generation counter that every document change and `workspace/didChangeWatchedFiles` bumps.
- Completion of a word also offers every exported bundled and project name that matches it, each with an `additionalTextEdits` import (placed by `lsp_import_insertion`), so a replay case must use a prefix no bundled name contains in order (`zq...`) or its expected file grows to hundreds of KB. Imports: module paths and exported names are completed straight from parsed bundled and project files (no checker run). Opened `manuscript-stdlib:` documents take the bundled text (the client's is ignored) and are checked as a stand-in file in the temporary directory (`ms-stdlib-<name>`); they publish no diagnostics and refuse edits, formatting, fixes and renames. A type variable's type row holds a variables index in `def`: never pass it to `ms_defs_get`.
- `ms lsp` is a supervisor around a worker copy of itself (`MS_LSP_WORKER=1`). A crash fails the unanswered requests, restarts the worker and replays `initialize` and the open documents. Input is read on its own thread (`lsp_input.c`), which is how `$/cancelRequest` is seen mid-request and how a run of `didChange` frames is published once. Never leave the process through `exit`: the reader thread holds stdin's lock inside `fread`, so `exit` deadlocks; use `lsp_input_exit`. The restart is tested by the conformance fixture `e2e/stdlib/lsp-restart` (it kills the worker; `MS_LSP_LOG=1` prints worker pids on standard error, and the runner gives fixtures the `ms` under test in `MS_UNDER_TEST`). Replay tests cannot check cancellation (all input arrives before the first request is handled); verify it by hand.
- Latency (2026-11-23, release build, typing in a 500 to 5,000 line file): every analysis re-parses and re-checks the whole graph, so keep per-keystroke work to one analysis. A mistyped name asks the checker for an import hint, which once parsed all bundled modules (now one process-wide index, `std_exports.c`). Diagnostics wait behind a queued completion request (`lsp_input_next_defers_publish`), and publishing re-analyses only open documents whose last graph contains a changed file (`LspDoc.deps`). Measure with a driver that sends `didChange`, then times `publishDiagnostics`, hover and completion; use `callgrind` on `MS_LSP_WORKER=1 ms lsp` and dump with `callgrind_control -d` (the server leaves through `_Exit`).
- Parity oracle without building Rust (2026-11-23): `crates/ms-lsp` no longer builds, but `crates/ms-lsp/tests/snapshots/*.jsonl` are recorded replies of scripted sessions (scripts in `tests/snapshots.rs`; fixtures in `tests/fixtures`; lines over 4,096 bytes are `"#large"`, std ranges are masked to `""`). Replay a script against `ms lsp` and diff by request id: navigation, rename, unfinished and broken now match. Known differences left on purpose or open: Rust hints `void say(...)` at a column inside `void` and gives a method the doc comment of its receiver type; `ms_ty_show` prints `move` in parameters where Rust does not; references on a std symbol do not list uses inside bundled modules; hover on a statement `match` has no type; and an unresolved import drops every feature of the file (Rust checks it against an empty module), which needs a loader change.
- Semantic tokens colour comments only in the forgiving scan, as Rust does; a bare standard constructor (`none`) has only a `native:` occurrence and is classed by its non-function type.
