# Readable formatting needs paragraphs while retaining inline guards

Decision: the user's formatter request keeps inline `if` bodies and introduces natural reading boundaries around declarations, guard sections, substantial control flow. Later feedback in [issue #102](https://github.com/manuscript-lang/manuscript/issues/102) requested authored spacing between match arms and compact short lists and callback signatures. The latest user direction supersedes authored spacing: discard authored blank lines and derive paragraphs from syntax.

Verified: a colon can belong to an inline conditional within a larger expression. Ending formatter grouping at that colon inserts a closer inside the conditional header. Use the parsed expression's end for statement grouping, and preserve the parsed tree as well as idempotence in [the boundary regression](../../crates/ms-syntax/tests/format_edits.rs).

Apply when: changing source formatting or adding layout heuristics.
Evidence: [formatting policy](../../documentation/developer-tooling/implementation.md#linting-and-formatting), [formatter](../../crates/ms-syntax/src/format.rs), [formatter CLI tests](../../crates/ms-cli/tests/fmt.rs), [format corpus](../../crates/ms-syntax/tests/data/format).
Verify: setup stays with its immediate uses and simple return; guards stay attached to setup and following work starts a paragraph; section comments stay attached to their code and substantial callbacks get their own paragraphs; branch families remain together; LF/CRLF output preserves literal spellings and is identical after a second format. Outdented comments must not set the code indentation baseline: [binding-group regressions](../../crates/ms-syntax/tests/format_comments.rs) preserve entries and comments independently.

Whitespace-only lines inside multiline text can carry data beyond the closing delimiter indentation. Shift them with the delimiter, not as blank source layout; compare parsed literal values across wrapping, raw text, CRLF, tabs and non-ASCII spaces ([regression](../../crates/ms-syntax/tests/multiline.rs), [#3111](https://github.com/manuscript-lang/manuscript/issues/3111)).

Token density (2026-11-10): the formatter also compacts. [compact.rs](../../crates/ms-syntax/src/format/compact.rs) rewrites `x = x + y` to `x += y` and joins `if c:` over a lone `return`, `break` or `continue` into one line when it fits 88 columns and no comment is between. It never touches an `else if` link, an `if` with an `else`, or a body with a comment. Rewrites that need types are lint fixes, not formatter edits: `MSL118` (`xs.length() == 0` to `xs.is_empty()`) and `MSL119` (`xs.get(i)` to `xs[i]` on a list in a name or field) in [terse.rs](../../crates/ms-tooling/src/lint/terse.rs). Both are warnings until the repository's own sources are fixed; then raise them to errors so verbose forms cannot land. Evidence: reference solutions were 21% above Go in o200k tokens, and hand-written terse c16 was 27% below it.

Leading tabs are one indent level, counted as four columns by the lexer (tab bytes are one byte, so `Pos.offset` stays exact and `Pos.column` is the display column). `ms fmt` expands code-line tabs to four spaces on entry and leaves text and block-comment lines alone; `shift_lines` strips columns, not bytes. Writing tabs from `ms fmt` waits for the `:=` rewrite so the repository is reformatted once ([proposal](../../proposals/tab-indentation.md): 3.0% on the agent references, 2.1% on stdlib with comments).

`ms fmt` works in spaces and writes one tab per leading group of four spaces on exit (`tabify`); leftover spaces align continuations. Anything that measures indentation must count columns (`ms_syntax::doc::indent_columns`), not bytes. Repo-check formats everything outside `/tests/` paths; crate test inputs and fixtures keep their spelling, and tests that hardcode LSP columns break if such a fixture is reformatted (tab is one UTF-16 unit).
