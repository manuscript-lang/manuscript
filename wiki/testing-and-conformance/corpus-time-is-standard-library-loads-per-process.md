# Corpus time is standard-library loads per process

Verified: every `ms check` of a file that parses loads the standard library first, and the corpus starts one `ms` per fixture and phase. Pure source modules nothing eager imports load on first import ([proposal](../../proposals/load-pure-source-modules-on-import.md)), which cut a two-line check from 303M to 193M instructions; do not make a native or extension module import a large source module, because that makes it eager again. The parse phase used `ms check --json` only to keep its parse diagnostics; `ms fmt --check --json` reports the same diagnostics without the load and cut the phase from 187 s to 24 s of fixture time with all 1559 fixtures unchanged. Pick the cheapest command that observes what a phase compares, and batch inputs into one process where the output can still be split per fixture. `ms check a.ms b.ms --json --with-text --each` checks every input as its own run against one standard-library load and returns `{target, exit_code, document}` per input; `ms-conform` sends the check phase through it in batches of up to 24 (a standard-library load is now about 127 ms and 448M instructions, so a per-fixture process costs more than the check), and the check phase fell from 107 s to 23 s with identical results. A fixture that mentions `../` runs alone, because a batch root changes how an escaping path prints; a batch that fails to report a fixture reruns that fixture alone. The check phase reads the terminal output from the same `ms check --json --with-text` run instead of a second process (check fixture time 449 s to 228 s). Per-fixture harness work counts on every platform: `taskkill` after each fixture cost Windows about 250 ms each (an exited root has no tree to kill, so it now runs only on timeout), and `cpus()` is Linux-only, so `tools/conform.ms` ran on one worker on macOS and Windows until it used `system_info().cpu_count`. Compare fixture times across platforms before blaming the platform. A second pass with another backend runs only `run` and `test`: check and parse do not reach a code generator, and skipping them cut the Cranelift corpus from 153 s to 124 s.

Apply when: adding a conformance phase, a fixture runner, or a test that loops over `ms` invocations.
Evidence: [observe.rs](../../crates/ms-conform/src/observe.rs), [standard library loading](../../crates/ms-check/src/stdlib.rs).
Verify: `ms-conform run --phase parse` prints fixture time per phase and the slowest fixtures.
