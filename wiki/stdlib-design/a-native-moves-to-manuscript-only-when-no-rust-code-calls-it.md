# A native moves to Manuscript only when nothing calls it from Rust and a bench shows no loss

Verified (2026-11-11): `reverse_bits`, `reverse_bytes` and `filled` are `.ms` and measured faster than the natives (3.2 to 2.4 ns and 0.97 to 0.39 ns per op). Tried and reverted: BigInt `gcd`/`lcm`/`sqrt`/`inverse_mod` (22% to 41% slower than num-bigint's in-place code) and the float helpers `copy_sign`, `sign_bit`, `frexp`, `modf`, `next_after`, `round_to_even`, `is_integer` (each looked equal or faster alone, but 38% slower together in a loop, because pure natives inline into release code). Bench several together in a realistic loop, with the merge-base binary on the same machine, before keeping a port of a pure float or integer native.

Measured 2026-11-15 (callgrind, same machine, Manuscript against the Rust it would replace): `range_by` as a `.ms` loop plus `flatten` via `extend` cost 152M instructions against 35M for the natives (4.3x) over 20000 loops; a `.ms` `.env` loader was 1.27x the Rust one on a 3-line file; a `.ms` `decode_component` was 1.8x the instructions and about 6x the wall time. Cause for the text cases: a small `Map` or `BytesBuilder` goes through the large-allocation path and each string slice or trim is a runtime call ([issue 4021](https://github.com/manuscript-lang/manuscript/issues/4021)); for list helpers a per-element `append` is about 100 instructions where the native bulk-fills. Rule from the owner: a moved operation must not be slower than the Rust it replaces; keep generic bulk list primitives in Rust, and redo the text moves (dotenv, URL) after 4021 lands. The regex template expander runs inside the engine's match loop (`Captures::expand` for uncapped calls), so moving it means per-match span lists in `.ms`; not attempted.

Blockers found for other candidates: `crc32`/`adler32`/base64 are called by `ms-std-archive`, `ms-std-net` and TLS; glob by `ms-std-fs` walk; `msstd_url_parse` and `msstd_url_format` are called by name from `ms-lower/json.rs` (typed JSON of `Url`); Duration `+`/`-` and `5.seconds()` are lowered from `expr.rs`. Remove the Rust caller or lowering special case in the same change.

Apply when: choosing the next Rust native to port, or removing an `extern fn` from `src/stdlib/internal/*.ms`.
Evidence: [math.ms](../../src/stdlib/math/math.ms), [collections.ms](../../src/stdlib/collections/collections.ms), `grep -rn <symbol> crates` before porting.
Verify: `ms test tests/conformance/fixtures/e2e/stdlib/numeric-helpers.ms` and `collections.ms` pass.

Update 2026-11-15 ([issue 4033](https://github.com/manuscript-lang/manuscript/issues/4033)): the `flatten` gap was `List.extend` copying element by element, not the loop. `extend` is now a bulk-copy native (`msrt_list_extend`), and `flatten` is a `.ms` reserve-then-extend loop that beats the old native on five 200-int lists (5.10M against 5.13M instructions over 3000 calls), string lists (68.1M against 71.6M) and empty lists (13.2M against 20.8M). `range_by` stays native: a plain append loop compiles to about 8 instructions per element against about 3 for the Rust fill, a loop-shape cost (capacity check, bound check, jump) that needs loop optimisation, not a stdlib change. Receiver-typed arguments of `Clonable`-bound mutators (`extend`, `merge`) are borrowed, since those methods copy from them; `splice` still takes its replacement.
