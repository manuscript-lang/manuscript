# Compiler change checklist

Verified: rules gathered from past compiler, syntax, and build work; the linked lessons carry the evidence.

Apply when: changing `ms-syntax`, `ms-check`, `ms-mir`, `ms-lower`, `ms-clif`, `ms-driver`, `ms-build`, or `ms-native`.

Use for `src/compiler/` (`syntax`, `project`, `check`, `own`, `lower`, `mir`, `opt`, `emit`, `link`). Read [architecture](../../../documentation/contributing/architecture.md), [`src/README.md`](../../../src/README.md), [`src/compiler/README.md`](../../../src/compiler/README.md), relevant [compiler rules](../../../documentation/contributing/compiler/_index.md), and [language](../language/index.md) / [compiler lessons](index.md); syntax work also reads the [grammar](../../../documentation/core-language/basics/grammar.md) and [editor recovery lessons](../tooling-and-docs/editor-recovery-must-preserve-delimiter-continuations.md).

- Pipeline: `ms-syntax` (lexer, parser, formatter) -> `ms-check` (resolution, types, contracts, effects, cleanup, ownership; typed HIR) -> `ms-lower` and `ms-mir` (MIR, ownership elaboration, optimizer, verifier) -> `ms-clif` (Cranelift object code) -> `ms-driver` (module graph, entry rule) and `ms-build` (lowering seam, codegen, link). Keep parse/resolution/type/lowering diagnostics attributable to source.
- Diagnostic remedies must preserve the source expression, not substitute its ownership root: cloning `rows` is not the same loop as cloning `rows.get(0)` (#2941). Check the proposed repair as source as well as checking the error wording.
- Preserve source-only analysis: recovery is editor analysis, and diagnostics prevent executable generation. Entry validation independently checks `fn main()` returns `Void`, `Void!`, `Int?!`, or `Int` (a wrapper entry in `ms-lower` turns all but `Int` into an exit status).
- The bundled standard library and the binding counter live in `ms_check::Session`, not in globals. `check` makes a fresh session (reloads the library, tens of ms); a long-lived caller (`ms-lsp`) keeps one and uses `check_in`/`Options::session`, and later queries read `program.session`. A session is `!Send` and stays on its thread because primitive types are thread-local `Rc`s (`types.rs` `PRIMS`). `ms_syntax::Symbol` is still a process-wide leaking interner (about 20k symbols, 0.5 MB after the whole library; growth is per distinct identifier): see `design/proposals/compiler-session.md`.
- Compiler layers are enforced by `ms_lint` from `src/layers.txt` (history: `design/proposals/compiler-stage-layering.md`): an include may cross only downward, and the exception list may only shrink. Lowering reads checker facts and decides no ownership question; do not add a second analysis in `ms-lower` (the removed `infer_mutated` re-derived `var` parameters and added nothing). Lowering's path-sensitive drop bookkeeping (`closed_on_path`, `scope_done`, `rest_closers`, `hidden_closers`, `copy_gaps`) must not grow (the Rust `stages.rs` ledger is gone; reviewers hold the line): a change that adds a use must instead put the decision in the ownership walk, and the next matrix row for a new exit shape goes in `tools/close-matrix.ms` first.
- Scope-end cleanup belongs to the elaborate pass (`src/compiler/mir/mir_elab*.c`). Lowering emits `scope.begin/own/disown/mark/end` and never closes or drops a binding at scope end; `bind_closing_kind` hands the binding to the pass or reports an internal error, so a case it cannot own is a bug to fix in the pass, not a fallback to add. Two traps: a close thunk shared by `HelperKey` can be turned into a returning close by a fallible binding (use a private thunk for temporaries and fields), and a function whose scopes close resources keeps its `var` parameters in the caller's slot (`closing_fn`), because the pass's error exit cannot write a register-held `var` parameter back. See `design/proposals/elaborate-drops.md`, stage 4 outcome.
- A value `scope.own`ed again by an inner scope after the outer scope disowned it keeps the outer tag only while its definition dominates every end of the outer scope (`defined_before_every_end` in `elaborate.rs`); a value defined inside a branch and bound there (`var kept = outer`) belongs to the inner scope, or the join after the branch finds an unreleased owner (#4270). Generated ownership programs (random moves, reassignments and branches over strings, lists and records, built on both backends and leak-checked) found it; the existing fixtures never had a branch-local value.
- Release shorthands (`alt.own`, `alt.unbox`, `alt.release`, `type.release`, `opt.unbox`) exist for lowering and the optimizer only. `ms_mir::expand_owned` rewrites them into `alt.get`/`type.get`/`opt.get`, `drop` and `free` after `unwind` and before codegen, so Cranelift and LLVM lower primitives and carry no copy of the release rules; the test interpreter expands on construction, and tests that call a backend directly run `expand_owned::run` first. A new ownership shorthand gets an arm in that pass, not in a backend. `free` frees a value's heap block (boxed alternative or optional, indirect type) or, with a field, the nullable box of a map or set field inside an indirect type; a payload-less case of a boxed alternative is a shared static block and is never freed (a bug here showed as a segfault in `expect_equal` of two errors with `details`: `alt.unbox` dropped the field it returned).
- Resolve nominal symbols, implementations, defaults, and effects in checking; reuse checked identities in consumers. Do not infer semantics from spelling.
- Return completeness composes reachable exits: a nonreturning condition makes branch breaks unreachable, but a break originating in the condition still exits the enclosing loop. Continue checking unreachable branches for source errors; control-flow regressions cover both rules.
- Retain module-local implementation selection through views, bound methods, generics, and cleanup. Defaults must not survive mutable callable replacement or generic inference as omission permissions.
- An implementation names its parameters like the interface: lowering labels arguments of a call through the interface by the interface's names, so a renamed parameter (`fn equals(o: P)`) once passed check and failed lowering with "no parameter other". The checker now rejects it (`impl_parameter_names` test).
- Keep manifest/alias/path/overlay identity in `ms-driver`'s `project` module. Resolver changes need symlinked roots, confined unsaved files, dangling links, conflicting overlays, and malformed nested manifest cases.
- Lower in source evaluation order, including defaults and cleanup on every exit. The [lowering pages](../../../documentation/contributing/compiler/lowering/_index.md) and [`src/abi/README.md`](../../../src/abi/README.md) record value layout and the runtime ABI; use the [runtime checklist](../runtime/runtime-and-stdlib-change-checklist.md) for execution contracts. Write the AGENTS.md proposal with an independent skeptical review before changing fault-frame, cancellation, dispatch, or representation semantics.
- Ownership and `var` rules live in [ownership rules](../../../documentation/contributing/ownership-rules.md). A `var` argument that is a field (`var self.out`) must change in place through `place_update`, as the source-call path does; going through `var_argument` copies the whole value per call. One field or element place beside other `var` arguments that are different locals still changes in place (`lone_place_var`); two place arguments, or one that shares a root with another, take the copy-in path (JPEG decode was quadratic until the one-place case was allowed: `jpeg_block(data, var bits, var comps[c], ...)` copied the whole component per block). Do not add code only to reproduce old Go output where Rust std covers the concept.
- A long list literal of scalar constants lowers to `list.const` (static data memcpy'd into a fresh list), never to one function as long as the literal: register allocation, SLP and the scheduler are quadratic in function length. A long literal of runtime values is built in 64-element `list.lit` chunks joined by `list.concat`, each chunk outlined into a helper function (`FuncBuilder::outline`) so no function grows with the literal and no pass is disabled. A chunk that reads a value needing a drop stays in place.
- Choose the right algorithm and data structure: passes stay linear (or n log n) in source size. Share visited sets/memos across roots, index instead of rescanning, and avoid per-byte or per-query allocation. Time `ms check` and `ms build` at N/2N/4N and profile anything above 2x per doubling; see [the lesson](compiler-passes-use-the-right-algorithm-and-data-structure-f.md).
- Drop and clone of a record, an enum, a flag-and-payload optional or a list (clone only when its elements need one; plain lists are block-copied by the backends) that cannot reach itself are MIR functions, made only for the types the program drops or clones (`ms_mir::glue::run`, `Module::drop_glue` and `clone_glue`, looked up with `Module::made_glue`), not backend code: change their cases there, and both backends follow. Run `glue::run` after `expand` and before `expand_owned` so its release ops are lowered; the verifier skips these functions. Interface, closure, string, map and self-containing drops and clones are still written in each backend (`design/proposals/mir-drop-glue.md`).
- MIR passes and codegen read `ExternDef::role` (`ExternRole`) and `Func::sort` (`SortThunk`), never a symbol or function name. Lowering sets roles in one table, `rtcall::extern_role`; a pass that creates such an extern sets the role itself, and textual MIR carries it as an attribute. New special-cased runtime calls add a role, not a string compare. A fact about a runtime function (one MIR instruction `op=`, `spawns`, `keeps:`, `takes:`, its error domain) is a `// ms:` flag in its Rust source, read from `rt_symbols.txt`, never a symbol prefix or name list. What a declaration binds to is `Native` (`Source`, `Contract`, `Extern { symbol, bundled }`, `Builtin`), primitives and time types are `Builtin` tags, and a diagnostic's meaning is its `Cause`: never test an identity string, an `@std/` path or message text. Glue functions are identified by `Gen::glue_ids` and `Def::glue`, not the `ms.glue.` prefix. Lowering identifies `Result`, `Comparable` and `Equal` by `AltDef::std`/`IfaceDef::std` (case order `Std::OK`, `Std::ERROR`) and the `close` slot by `IfaceDef::close`, never by name.
- Run `ctest --preset ci`, `make repo-check`, and `make conform` (the frozen conformance corpus in `tests/conformance/`; known differences are in `expect-fail.txt`). Execute changed semantics through corpus programs; build/link changes need a native artifact and `make dist-check`. Declaration-only acceptance does not establish execution.

## Syntax and parsing

- `src/compiler/syntax/ast.h` owns the untyped tree and positions; checked semantics belong in `ms-check`. Keep syntax independent of checker/runtime/editor machinery.
- Update parser, checker, lowering, formatting, and inspection consumers together when a syntax node changes. `make repo-check` checks nested matches, `.ms` formatting, and stdlib syntax.
- Use the shared visitor in `src/compiler/syntax/walk.h` for executable traversal: defaults, interpolation, collections, closures, branches, and match bodies in source order. Do not manufacture statements to visit defaults. Types/patterns need separate handling.
- Preserve file identity and original offset/line/column positions. Check LF/CRLF and editor position conversion when slicing/recovery changes; synthetic repairs must not shift valid declarations.
- Exercise strict parsing and editor partial parsing (`partial.rs`). Incomplete neighboring declarations must not erase multiline parameters or scopes. Use lexer continuation boundaries instead of splitting at lines/closing delimiters.
- Inline suites stop at enclosing delimiters, implicitly return expressions only in callable bodies, and enforce one statement/conditional branch per line. Follow current grammar rather than restoring blanket indentation restrictions.
- Route new shapes through [tooling](../tooling-and-docs/tooling-change-checklist.md). Verify traversal, accepted/rejected parsing, recovery, formatting idempotence, and affected editor scopes/navigation. Preserve reproducible parser failures as regression tests.

- Every source function-value thunk has an owned-result callable ABI, including plain free functions as well as bound/defaulted methods. Adapt inferred borrowed Clonable results at that boundary; never return a borrowed MIR value as owned or copy a resource result (#3112).

- Public-signature closure also needs generic defaults: inspect both declaration variables and interface-operation variables, including parameters unused in the signature. Default well-formedness and bounds checking does not establish visibility. Preserve private defaults on private declarations.

## Run `make perf-counts` after a change to generated glue or inlined helpers

(2026-11-16.) Two merges moved counts that nobody saw until the baselines were rerun: #4305 (MIR drop functions) dropped an `Error`'s empty `details` map through `msrt_slot_drop` on every error (`guard-resultvar` 5.30M to 8.66M), and #4303 (inline `String` order) raised the `strings` suite program 17% because its byte loop was slower than `memcmp` on the sort's keys while its own guard improved 57%. Fixes: a map with no slots is not dropped through the runtime, and the compare reads eight bytes at a time. Judge an inlined helper on a program that sorts strings, not only on its guard.
- Lowering a call that omits an argument copies an earlier `var` argument only when the default names it (`call.rs` `default_argument`); an unconditional copy cloned a resource that has one owner and faulted at runtime (`upgrade(var exchange)`). `default-after-var-resource-argument.ms` pins it.
