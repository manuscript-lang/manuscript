# Compiler change checklist

Verified: rules gathered from past compiler, syntax, and build work; the linked lessons carry the evidence.

Apply when: changing anything under `src/compiler/`.

Use for `src/compiler/` (`syntax`, `project`, `check`, `own`, `lower`, `mir`, `opt`, `emit`, `link`). Read [architecture](../../../documentation/contributing/architecture.md), [`src/README.md`](../../../src/README.md), [`src/compiler/README.md`](../../../src/compiler/README.md), relevant [compiler rules](../../../documentation/contributing/compiler/_index.md), and [language](../language/index.md) / [compiler lessons](index.md); syntax work also reads the [grammar](../../../documentation/core-language/basics/grammar.md) and [editor recovery lessons](../tooling-and-docs/editor-recovery-must-preserve-delimiter-continuations.md).

- Pipeline: `syntax` (lexer, parser, formatter) -> `project` (module graph, entry rule) -> `check` (resolution, types, contracts, effects, cleanup; typed HIR) -> `own` (moves, borrows) -> `lower` (HIR to MIR) -> `mir` and `opt` (ownership elaboration, optimizer, verifier) -> `emit` (LLVM IR text) -> `link` (object, lld, runtime archive). Keep parse/resolution/type/lowering diagnostics attributable to source.
- Diagnostic remedies must preserve the source expression, not substitute its ownership root: cloning `rows` is not the same loop as cloning `rows.get(0)` (#2941). Check the proposed repair as source as well as checking the error wording.
- Preserve source-only analysis: recovery is editor analysis, and diagnostics prevent executable generation. Entry validation independently checks `fn main()` returns `Void`, `Void!`, `Int?!`, or `Int` (`lower_entry.c` turns all but `Int` into an exit status).
- Compiler layers are enforced by `ms_lint` from `src/layers.txt` (history: `design/proposals/compiler-stage-layering.md`): an include may cross only downward, and the exception list may only shrink. Lowering reads checker and ownership facts and decides no ownership question; do not add a second analysis in `compiler/lower`. Lowering's path-sensitive drop bookkeeping must not grow: a change that adds a use must instead put the decision in the ownership walk (`compiler/own`), and the next matrix row for a new exit shape goes in `tools/close-matrix.ms` first.
- Scope-end cleanup belongs to the elaborate pass (`src/compiler/mir/mir_elab*.c`). Lowering emits `scope.begin/own/disown/mark/end` and never closes or drops a binding at scope end, so a case the pass cannot own is a bug to fix in the pass, not a fallback to add. A function whose scopes close resources keeps its `var` parameters in the caller's slot, because the pass's error exit cannot write a register-held `var` parameter back. See `design/proposals/elaborate-drops.md`, stage 4 outcome.
- A value `scope.own`ed again by an inner scope after the outer scope disowned it keeps the outer tag only while its definition dominates every end of the outer scope (`defined_before_every_end` in `mir_elab_tags.c`); a value defined inside a branch and bound there (`var kept = outer`) belongs to the inner scope, or the join after the branch finds an unreleased owner (#4270). Generated ownership programs (random moves, reassignments and branches over strings, lists and records, leak-checked (`make ownership-fuzz`)) found it; the existing fixtures never had a branch-local value.
- Release shorthands (`alt.own`, `alt.unbox`, `alt.release`, `type.release`, `opt.unbox`) exist for lowering and the optimizer only. `mir_expand_owned` (`mir_expand.c`, `mir_expand_owned.c`) rewrites them into `alt.get`/`type.get`/`opt.get`, `drop` and `free` before emission, so the emitter lowers primitives and carries no copy of the release rules. A new ownership shorthand gets an arm in that pass, not in the emitter. `free` frees a value's heap block (boxed alternative or optional, indirect type) or, with a field, the nullable box of a map or set field inside an indirect type; a payload-less case of a boxed alternative is a shared static block and is never freed (a bug here showed as a segfault in `expect_equal` of two errors with `details`: `alt.unbox` dropped the field it returned).
- Resolve nominal symbols, implementations, defaults, and effects in checking; reuse checked identities in consumers. Do not infer semantics from spelling.
- Return completeness composes reachable exits: a nonreturning condition makes branch breaks unreachable, but a break originating in the condition still exits the enclosing loop. Continue checking unreachable branches for source errors; control-flow regressions cover both rules.
- Retain module-local implementation selection through views, bound methods, generics, and cleanup. Defaults must not survive mutable callable replacement or generic inference as omission permissions.
- An implementation names its parameters like the interface: lowering labels arguments of a call through the interface by the interface's names, so a renamed parameter (`fn equals(o P)`) once passed check and failed lowering with "no parameter other". The checker now rejects it.
- Keep manifest/alias/path/overlay identity in `src/compiler/project`. Resolver changes need symlinked roots, confined unsaved files, dangling links, conflicting overlays, and malformed nested manifest cases.
- Lower in source evaluation order, including defaults and cleanup on every exit. The [lowering pages](../../../documentation/contributing/compiler/lowering/_index.md) and [`src/abi/README.md`](../../../src/abi/README.md) record value layout and the runtime ABI; use the [runtime checklist](../runtime/runtime-and-stdlib-change-checklist.md) for execution contracts. Write the AGENTS.md proposal with an independent skeptical review before changing fault-frame, cancellation, dispatch, or representation semantics.
- Ownership and `var` rules live in [ownership rules](../../../documentation/contributing/ownership-rules.md). A `var` argument that is a field (`var self.out`) must change in place, as the source-call path does; copying the whole value per call is the failure. One field or element place beside other `var` arguments that are different locals still changes in place; two place arguments, or one that shares a root with another, take the copy-in path (JPEG decode was quadratic until the one-place case was allowed: `jpeg_block(data, var bits, var comps[c], ...)` copied the whole component per block).
- A long list literal of scalar constants lowers to static data memcpy'd into a fresh list (`emit_string.c` constant data), never to one function as long as the literal: register allocation, SLP and the scheduler are quadratic in function length. A long literal of runtime values is built in chunks outlined into helper functions, so no function grows with the literal and no pass is disabled.
- Choose the right algorithm and data structure: passes stay linear (or n log n) in source size. Share visited sets/memos across roots, index instead of rescanning, and avoid per-byte or per-query allocation. Time `ms check` and `ms build` at N/2N/4N and profile anything above 2x per doubling; see [the lesson](compiler-passes-use-the-right-algorithm-and-data-structure-f.md).
- Drop and clone of a record, an enum, an optional or a list (clone only when its elements need one; plain lists are block-copied) are MIR functions made by the glue pass (`compiler/mir/mir_glue*.c`, `mir_desc_glue.c`), only for the types the program drops or clones: change their cases there and the emitter follows. Run the glue pass after `mir_expand` and before `mir_expand_owned` so its release ops are lowered; the verifier checks these functions like others (`design/proposals/mir-drop-glue.md`).
- MIR passes and the emitter read the extern's role (`MR_*` in `compiler/mir/mir.h`) and its flags (`pure`, `fresh`, `reads`, `retains`), never a symbol or function name. Lowering sets roles from the native signatures (`src/compiler/natives`, `@borrows` and friends on `src/stdlib/*.ms` declarations); a pass that creates such an extern sets the role itself. New special-cased runtime calls add a role, not a string compare. What a declaration binds to is its kind (source, contract, extern, builtin), and a diagnostic's meaning is its code: never test an identity string, an `@std/` path or message text.
- Run `ctest --preset ci`, `make repo-check`, and `make conform` (the frozen conformance corpus in `tests/`; known differences are in `expect-fail.txt`). Execute changed semantics through corpus programs; build/link changes need a native artifact and `make dist-check`. Declaration-only acceptance does not establish execution.

## Syntax and parsing

- `src/compiler/syntax/ast.h` owns the untyped tree and positions; checked semantics belong in `compiler/check`. Keep syntax independent of checker/runtime/editor machinery.
- Update parser, checker, lowering, formatting, and inspection consumers together when a syntax node changes. `make repo-check` checks nested matches, `.ms` formatting, and stdlib syntax.
- Use the shared visitor in `src/compiler/syntax/walk.h` for executable traversal: defaults, interpolation, collections, closures, branches, and match bodies in source order. Do not manufacture statements to visit defaults. Types/patterns need separate handling.
- Preserve file identity and original offset/line/column positions. Check LF/CRLF and editor position conversion when slicing/recovery changes; synthetic repairs must not shift valid declarations.
- Exercise strict parsing and editor partial parsing (`partial*.c`). Incomplete neighboring declarations must not erase multiline parameters or scopes. Use lexer continuation boundaries instead of splitting at lines/closing delimiters.
- Inline suites stop at enclosing delimiters, implicitly return expressions only in callable bodies, and enforce one statement/conditional branch per line. Follow current grammar rather than restoring blanket indentation restrictions.
- Route new shapes through [tooling](../tooling-and-docs/tooling-change-checklist.md). Verify traversal, accepted/rejected parsing, recovery, formatting idempotence, and affected editor scopes/navigation. Preserve reproducible parser failures as regression tests.

- Every source function-value thunk has an owned-result callable ABI, including plain free functions as well as bound/defaulted methods. Adapt inferred borrowed Clonable results at that boundary; never return a borrowed MIR value as owned or copy a resource result (#3112).

- Public-signature closure also needs generic defaults: inspect both declaration variables and interface-operation variables, including parameters unused in the signature. Default well-formedness and bounds checking does not establish visibility. Preserve private defaults on private declarations.

## Run `make perf-counts` after a change to generated glue or inlined helpers

(2026-11-16.) Two merges (Rust era) moved counts that nobody saw until the baselines were rerun: #4305 (MIR drop functions) dropped an `Error`'s empty `details` map through `msrt_slot_drop` on every error (`guard-resultvar` 5.30M to 8.66M), and #4303 (inline `String` order) raised the `strings` suite program 17% because its byte loop was slower than `memcmp` on the sort's keys while its own guard improved 57%. Fixes: a map with no slots is not dropped through the runtime, and the compare reads eight bytes at a time. Judge an inlined helper on a program that sorts strings, not only on its guard.
- Lowering a call that omits an argument copies an earlier `var` argument only when the default names it (`default_argument` in `lower_default.c`); an unconditional copy cloned a resource that has one owner and faulted at runtime (`upgrade(var exchange)`). `default-after-var-resource-argument.ms` pins it.
