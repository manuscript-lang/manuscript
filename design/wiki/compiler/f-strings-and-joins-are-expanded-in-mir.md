# F-strings and string joins are expanded in MIR, not passed to a runtime join

Verified: `f"{a}{n}{b}"` and `a + b + c` lower to one join call of any length (`TEXT_MAX_PIECES` is 16; two strings and no Int stay `msrt_string_concat`). `mir_expand` writes the join out: each Int is formatted by `msrt_int_format` into a `MIR_BYTES` slot, the part lengths are added with `str.bytes`, `msrt_string_open(total, slot)` makes the string, and each part is copied with `str.data` and `mem.copy` (`llvm.memcpy`), moving a cursor with `ptr.add`. Chinmay's rule (2026-11-23): string handling that the compiler can see belongs in MIR, not behind opaque numbered entry points (`msrt_string_fmt2..6`, `append_fmt1..5`, `concat3..6` are gone).

- An in-place append (`s = s + f"…"`, found by `opt_strfuse` when the first string dies at the call) is the role `MR_STRING_JOIN_GROW`: the string goes into a frame `{text, pending}`, `msrt_string_extend(frame, total)` grows an owned block that has the spare room or moves the text to a new block, and `msrt_string_close` frees the old block only after every copy. A part may be a view into the old text, so the old block must outlive the copies.
- Faults keep their text: a result past 1 GiB faults `string: limit exceeded` inside `open` or `extend`.
- The runtime keeps three small primitives: open, extend/close, int format. Add a new numbered entry point instead of a part count and this rule is broken.

Apply when: changing string building, adding a part kind, or seeing `msrt_string_*` calls in an f-string's MIR (`ms build --emit mir file.ms`).
Verify: `ms build --emit mir` shows `str.data`, `mem.copy` and one `msrt_string_open` per join; edge cases (empty parts, an inline result, a view into the grown string, 1 GiB) behave as before; `make conform` has no new failures. Evidence: [`mir_expand.c`](../../../src/compiler/mir/mir_expand.c), [`opt_strfuse.c`](../../../src/compiler/opt/opt_strfuse.c). Microbenchmark of `s += f"{i}={i * 3};"` plus 5M joins: about 320 to 440 ms before, 240 to 300 ms after.

Lesson (builder append and shrinking replace, 2026-11-23): `StringBuilder.append` is a `strfast` helper (role `strbuilder_append`, from the name table in `lower_native.c`): text within the builder's spare room is copied in place (`opt_copy_short` up to 16 bytes, `mem.copy` above) and a full buffer calls the runtime. `msrt_string_replace` with a replacement no longer than the match searches once into a block the size of the input and trims it, instead of counting matches first. `string_build_split_join_replace` at 400k words: 312M to 232M instructions under callgrind.

Lesson (list pop in line, 2026-11-23): `List.pop` lowers to `list.len`, a branch, `list.take` of the last element, `list.droplast` and an `opt.some`, through `@inline=list_pop` on `msrt_list_pop` (`fn_list_pop`); an empty list goes back unchanged and answers `none`. The runtime call cost a slot, a descriptor and a copy per pop. `vm_5M` 107 to 51 ms.

Lesson (dead fast-path roles, 2026-11-23): the `strfast` and `bytesfast` passes find their runtime calls by `MirExtern::role`, and lowering sets a role only from the name table in `lower_native.c` (`string_role`). Roles for `bytes_append`, `bytes_read_word`, `bytes_index_of_byte`, `string_parse_int`, `string_contains` and `string_scalar_step` were never in it, so those passes rewrote nothing. They are now, and the helpers accept a `u8` answer declared as `uint8` as well as `bool` (`sf_flag`, `bf_status`). `BytesBuilder.append` is one `bytes.push` plus a branch (2M bytes: 62M to 22M instructions); a parse_int, index_of_byte, read_word and contains loop 223M to 121M. When a pass seems to do nothing, print `ms build --emit mir --opt` and look for the role on the extern line.

Map and set lookups with an `Int` key (and an `Int` or `Float` map value) get a probe role in `lower_native_roles.c` and are read inline by `opt_probe`, which depends on the slot layout in `src/runtime/core`. String keys are not wired: the helper loaded a droppable `str`. Role tables live in `lower_native_roles.c`; `lower_native.c` is near the 1000-line lint.
