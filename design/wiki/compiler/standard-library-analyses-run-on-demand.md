# Standard-library analyses run on demand

Verified: a one-line `print` program imports bundled standard modules through `core.ms`, and analyzing every callable in them dominated `ms check` (measured on the Rust `ms`, 2026-11-14: 60% of 317.5M instructions; on-demand analysis cut it to 167.7M). A callable's analysis does not depend on the program that imports it (its facts come from its body and the summaries of what it calls), so the project's callables are analyzed first and a bundled one when something asks.

- Bodies: `compiler/check/lazy_std.c` sets the bundled standard bodies aside before the body walk and gives one back, checked, only when a checked body names that function or method, until nothing new is named. It applies to every command that checks a program, build and run included (2026-11-25; before that only analysis commands). Lowering calls some standard methods that no written reference names, so reach also restores the hook methods in `compiler/check/hooks.h` for every type a checked body mentions, the functions lowering calls by name, and the defaults of native functions and record types. lowering looks methods up only through `lower_named_method(cx, type, MsHook)`, so a name outside that table does not compile, and `reserve` faults on a deferred body, naming the function: a missed edge is a loud failure, never a miscompile. A lowering change that looks up a method by a new name adds it to the table. `ms_func_has_body` (not `body.len`) asks whether a function has source, because a deferred body is empty until restored.
- Shared parse cache (2026-11-25): deferral writes into the functions of a module, so a program on the language server's shared trees would blank them for the next program (a later document then missed diagnostics that depend on a standard summary). A program that defers over a cache first copies each module's function and method records (`ms_check_clone_for_deferral`, nodes below stay shared), so deferral and restoring touch only its own copy and the editor checks lazily too. A change that makes deferral write below a function record breaks this: `std_bodies_between_documents` and `lsp_parity` pin it.
- Effects: `compiler/check/effects_scan.c` builds the callable graph from checked bodies and scans from the project callables; a node reached from them is scanned before propagation, since an edge to an unscanned node would read as unknown. A tool that lists library items asks per callable.
- Ownership: result-borrow masks (`compiler/own/result_borrows.c`) and summaries are computed from the project callables plus every callable a summary reads. Interface conversions to a type variable read every implementation's summary, so they use the whole program's methods.
- Rejected probe (Rust era): a bump allocator with no `free` cut `ms check` instructions 26% but made a larger check slower (86 to 110 ms, 26 to 63 MB peak): fresh pages cost more than glibc reuse. Judge allocator changes by wall time and peak RSS, not instructions.
- Parsing (2026-11-25): bodies are about half of the parse work, so a lazy check parses a bundled body when it is reached. `std_index_gen` logs body ranges and node ids from the real parser at build time and fails the build unless a lazy parse plus restored bodies equals the whole parse; `ms_parse_bodies` skips them, `ms_parse_body` restores one (`ms check` of a one-line program 80.0M to 70.5M). A second scanner or a layout-keyed one was rejected: it drifts and cannot keep node ids. A change to the lexer or parser that alters ids is caught by that build check.

Apply when: adding a program-wide pass over the checked program, or a tool that reads effects or ownership of library callables (ask per callable, do not read the whole table).
Verify: `make conform` unchanged; the build runs `std_index_gen`'s whole-parse comparison; `ms check` and `ms build` of a hello program do not check every bundled body (front end 135M to 75M instructions on a one-line build); `ctest -R std_full` checks every body.
