# Benchmarks and performance

Perf benchmarks, profiling.

- [There is one perf suite, indexed by `groups.txt`](there-is-one-perf-suite-indexed-by-groups-txt.md): `make perf-list`, `make perf GROUP=<name>`, and a check that no benchmark sits outside the index.
- [Binary search moves one select per step, and a captured comparator still gets the generated sort](binary-search-and-captured-comparators-must-not-branch-or-call.md): `binary_search` 270 to 31 ms per 2M searches (Rust 90); sorts by a capturing comparator 148 to 35 ms.
- [A lone task runs file calls in place](a-lone-task-runs-file-calls-in-place.md): `treegrep` over 2000 small files 100 to 40 ms; the pool hand-off cost about 50 us per read.
- [Eager arena commit made a program's first large allocations slow](eager-arena-commit-made-the-first-large-allocations-slow.md): a first run of a map block took 1.8 ms and the second 0.22 ms; `map_put_get_8k` 92 to 33 ns per op (Rust 33).
- [A bound on `n - 1` also bounds `n`](a-bound-on-n-minus-one-also-bounds-n.md): range analysis narrows the operand of a checked constant add or subtract; a stencil's index wraps vanish (Cranelift 1,949M to 1,412M instructions, C 438M).
- [`ms run` builds Debug: time `ms build` binaries](ms-run-builds-debug-so-time-ms-build.md): an HTML parse read 2,000 ms under `ms run` and 150 ms built.
- [A lone file read runs where it is waited on](a-lone-file-read-runs-where-it-is-waited-on.md): `read_file` defers to its waiter when nothing else runs and opens with one `fstat` (3.7 to 2.2 us per small read; Rust 1.8).
- [Independent files use every core, and a known name is looked up without the lock](independent-files-use-every-core-and-name-lookups-take-no-lock.md): `ms fmt` over 8 files 3.28 to 0.89 s; the interner mutex capped scaling at two cores; diagram html and LSP completion stopped repeating a compile and a sibling parse.
- [A cloned `none` that is only dropped is deleted](an-emptied-local-must-not-clone-or-drop-its-none.md): a stored-to `Result` variable cloned and dropped its emptied slot every pass (48.2M to 5.3M instructions).
- [A boxed optional field is changed where it lies](a-boxed-optional-field-is-changed-where-it-lies.md): `self.child?.method()` freed and re-allocated the child block at every level (`objgraph` 2,383M to 958M instructions).
- [A block that moves into the growth region is freed, not cached](a-block-that-moves-into-the-growth-region-is-freed-not-cached.md): the presized block a growing list leaves behind stayed resident in the large-block cache (3M-element list 35 to 27 MB, Rust 25).
- [A block above the cached range asks for huge pages](a-block-above-the-cached-range-asks-for-huge-pages.md): blocks over 16 MiB take one fault per 4 KiB; `MADV_HUGEPAGE` on their 2 MiB units cut 13,000 faults to 2,300 (c16 86 to 73 ms).
- [Platform parity means functional parity](platform-parity-means-functional-parity.md): Chinmay's decision, each platform uses its best native fast path, no mirrored mechanism required.
- [Runtime string results are built in place, not through a `Vec`](runtime-string-results-are-built-in-place-not-through-a-vec.md): inline `starts_with`/`ends_with`, one-allocation `lower`/`upper`/`reverse`, an exact `parse_float` fast path, Schubfach float digits, exact `to_fixed`, byte-loop `fields` (lower 40 to 22 ms, reverse 66 to 14, `to_string` 167 to 61 per million).
- [Sorting records that own data uses the generated sort over bitwise scratch](sorting-owning-records-uses-bitwise-scratch.md): inlined comparator for `String`-holding records, 225M to 102M instructions, then 82M with the driftsort; scratch owns nothing so a comparator fault is safe.
- [User `hash()` values are mixed before they index a table](user-hash-values-are-mixed-before-indexing.md): identity-like hashes of small-int records clustered under linear probing (562 to 103 ms for 1M `Set[Pt]` operations).
- [Runtime fast paths are generated MIR with a runtime twin](runtime-fast-paths-are-generated-mir-with-a-runtime-twin.md): the Rust `ms-rt-hot` is deleted; map probes, `String.view`, `String.slice` and `Bytes.view` inline through generated MIR; hash and probe change together; `update` passes a map address.
- [Numeric parsing needs invalid-input performance controls](numeric-parsing-needs-invalid-input-performance-controls.md): valid-input gains can hide overflow and malformed-input regressions; preserve error precedence and equivalent Rust validation.

- [`var` record parameters stay in the caller's slot](var-record-parameters-stay-in-the-callers-slot.md): wide-record methods no longer move every field out and back per call; `Bytes` reads inline (`Lines.next` 147 to 75 instructions per line).
- [Constant list tables iterated in a loop are built once](constant-list-tables-in-loops-are-built-once.md): `for d in [[1, 0], [-1, 0], ...]` inside a loop no longer allocates per pass (248 to 20 ms for 5M passes).
- [A list built by one loop and read once by the next never exists](a-list-built-and-read-once-never-exists.md): the `fuse` MIR pass runs the reader's body at the builder's push (closures_20M 46 to 23 ms).
- [Two arms that run the same operations are one block with selects](arms-that-run-the-same-operations-are-one-block-with-selects.md): the `twins` MIR pass turns data-dependent arms with checked stores into selects (merge sort 93 to 66 ms).
- [A predecessor that knows a join's branch skips the join](a-predecessor-that-knows-a-join-branch-skips-the-join.md): the late `thread` pass copies a pure join and the chosen successor into the predecessor, so a Result built on each arm and tested after the join folds away.
- [A self-recursive function gets a copy for a known closure](a-self-recursive-function-gets-a-copy-for-a-known-closure.md): closure specialization now covers a callee whose only cycle is itself, so recursive sorts and walks call their comparator directly.
- [A wrapper closure takes the captures of the closure it calls](a-wrapper-closure-takes-the-captures-of-the-closure-it-calls.md): `promise(fn: ...)` builds one closure object, not two, and the work inlines into the wrapper.
- [Arms with checked arithmetic are selected with a predicated guard](arms-with-checked-arithmetic-are-selected-with-a-predicated-guard.md): `ifconv` hoists arms with checked `+` and `-` on Int, faulting through one guard on the taken arm's overflow flag.
- [Small string primitives are straight-line code](small-string-primitives-are-straight-line-code.md): pad stays in `.ms`; inline concat, one-byte repeat and short scalar counts need no variable-length copy (`report` -25% instructions).
- [An index in range is one unsigned compare, before the negative fix-up](an-index-in-range-is-one-unsigned-compare-before-the-negative-fix-up.md): `list.get/set` test `index <u len` first; negative indexes take a slow block (interp -10%, graph -5%, sim -4%, workers -6%).
- [A count before the list pays only for short texts](a-count-before-the-list-pays-only-for-short-texts.md): `split` counting its pieces first cost grep +24% on 22 MB; count only texts of at most 4 KiB.
- [A string held in a slot is appended in place](a-string-in-a-slot-is-appended-in-place.md): `b += f"..."` copied the whole string per append when `b` lived in a slot (200k appends 40 s); a late `strfuse` lifts the take so it grows in place.
- [`map`/`filter` chains over numbers run as one loop](map-filter-chains-over-numbers-run-as-one-loop.md): filter/map/sum over reading lambdas build only the final result (163 to 78 ms on 2M elements).
- [`for x in xs.filter(f)` walks `xs` in place](filtered-for-loops-walk-the-list-in-place.md): no filtered list or deep copies when the lambdas cannot fault (c13 392M to 350M instructions).
- [`for e in list.entries()` walks the list in place](list-entries-loops-walk-the-list.md): no entry records when `e` is only read as `.index`/`.value` (28 to 3.2 ms on 2M elements).
