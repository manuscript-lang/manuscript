# The unwind pass follows owners as they die and are born

Verified 2026-11-15 (#3979): in a program that starts tasks or catches faults (every `ms test` run), `crates/ms-mir/src/unwind.rs` registers a cleanup for each owner live across a call that can park or fault. A window used to end whenever an owner died, and the next call registered every live owner again, so N long-lived owners with a temporary around each call cost N² `cleanup.push` instructions and N² 24-byte stack slots. A `test` with 150 list locals captured by closures had a 569 KB frame and died with `stack overflow` on the 512 KiB task slot (Release segfaulted); 200 pairs were 438K Cranelift lines against 6K in `main`. Now a window keeps its registrations and, when the live set changes, discards the first dead entry (a discard pops it and everything newer) and registers again only the owners above it plus the new ones; 200 pairs lower to about 37K lines in total.

Across blocks (`plan_flow`): a window used to end with its block, so a body that branches between statements (an `if` after each of 100 statements with a captured list: 238K Cranelift lines, stack overflow) re-registered the live owners per block. Now a plain block (no scope open or close, no `discard`, no moved-out hole) starts with the longest prefix of registrations that all its predecessors leave open, provided every predecessor is plain and earlier in reverse post-order (a loop header starts empty), and leaves open the prefix every successor starts with, discarding the excess with one `discard`. A registration is named by the block and push that made it, so equal names mean one handle, and that push dominates every block holding it. Blocks that carry nothing keep the per-block windows. 400 inlined `expect_fault` pairs now lower to 98K Cranelift lines, about 210 per pair.

Compile time is still quadratic in the owners live at once: the walk builds the whole live set at every instruction that can park or fault, and the verifier, `hoist_loops` and the elaborate fixpoint also touch every live owner per block (a test with 3840 locals captured by closures and a branch after each takes 16 s; 960 take 1.6 s). Code size and the frame are linear. `plan_flow` stops after `4n + 8` passes with an internal compiler error naming the function (a plan that never settled would miscompile).

Owners dying out of order (2026-11-23): discarding the first dead entry re-registers every live owner above it, so a scope exit that drops N owners while a call can still fault (inlined `?` exits of a 45-line router test) cost N² pushes: 1,707 `cleanup.push` in one 21k-line function, the bulk of the Debug build time. `uws_plan` now cancels the dead entries (`msrt_cleanup_cancel`, a no-op in place, newer entries stay) when more owners live above the first dead one than died, and marks them with `UW_TAG_DEAD` in the rebuilt chain so a later discard by handle still pops them; otherwise it discards as before. Test: `accept/unwind-owners-dying-out-of-order`.

Lent slots (2026-11-23): a `var` call takes a value out of its slot, lends it to the callee, and puts it back. The slot's own cleanup entry must not stay live meanwhile: the callee changes what the slot's bytes point at (it frees `pending` and stores a new list), so a cancellation closing the slot would free the old pointers again (`fs-watch-cancel`: a watcher thread running over freed memory). Lowering now emits `scope.disown` at the take and `scope.mark refill` at the put-back for a closing local (`fn_take_place`, `fn_put_place`), so elaboration cancels the entry and re-arms it. The callee owns what it took until it puts it back. A join takes the owners every edge carries (an owner one path made is not defined where they meet), and a `type.set` on a value the caller covers stays the caller's.

Rules that keep it sound: a window closes at a scope open or close (`CleanupPush`, `CleanupRun`), at a loop-exit `discard`, and inside a moved-out hole; an exit instruction with no live owners still pops what the window holds, so a consumed value is never left registered across a call that can fault.

Apply when: changing `analyze` or the window materializer in `unwind.rs`, or adding an instruction that consumes an owner.
Evidence: `unwind.rs`, tests `registrations_grow_linearly_with_the_owners_a_function_holds` and `registrations_cross_branches_instead_of_repeating_per_block` in `crates/ms-mir/tests/unwind.rs`.
Verify: `cargo test -p ms-mir --test it unwind::`; `ms test` on a body of 200 `xs: List[Int] := [...]` locals each captured by a closure passed to a function passes in Debug and Release.
