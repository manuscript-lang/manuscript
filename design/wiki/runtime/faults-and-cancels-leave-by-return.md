# Faults and cancels leave by return

Decision (Chinmay, 2026-11-24: "can we fault as normal return path so everything works?"): a fault a program can see is posted, not raised. `ms_fault_post*` builds the sealed report in `MsUnwind.pending`, sets the task's `unwinding` byte and returns; a cancel sets the same byte (`ms_cancel_deliver`). Every compiled call site tests the byte (`fn_unwind_site`) and leaves by `fn_unwind_exit`: pause, the scope closes, resume, `ret undef`. A check emits `fault.site`, and the verifier rule `mv_fault_sites` requires one per faulting op. There is no cleanup stack, no `longjmp` and no unwind pass (`mir_unwind*`, `mir_shed` deleted).

Contract: a native or compiled callee that posts consumes nothing the caller still owns and returns an empty or undef result, which the caller treats as dead (`dead_result`). Held arguments stay in their closing slot across the call; a precheck that runs before a taken value is passed puts it back first (`fn_unwind_site_forgetting`).

Terminal faults: `ms_fault`, stack overflow (exit 139), out of memory, and a fault while reporting end the process with the report, the record and the status of their kind. They are not recoverable: Go and Rust make the same choice. Fixtures for them are `run` fixtures (`accept/stack-overflow`, `call-depth-runaway`, `task-stack-overflow`); conform masks `repeated N more times` as `<COUNT>`.

Guards (`ms_guard_call`) are plain calls: they read the byte afterwards, end the promises the code started (numbered by `ms_started_next`, ended above the guard's mark) and hand the report on.

Cost control (#6880): the byte is clear on every normal edge, so `opt_unwind_thread` sends an edge that knows it (a `fault.site` false edge: clear; an exit that ends in `resume`: set) straight past the site test, after inlining; `opt_unwind_sites` drops the test after a call that cannot post; a native that cannot park or fault says `@leaf` in its `ms-sig` (`string_eq`, `string_compare`) so no site follows it. `opt_unwind_pairs` drops a `pause` right before a `resume` (an exit that closes nothing) and shares the bare cold exits of a function. The facts are local to one edge or a chain of single-predecessor blocks with no call, drop or check between; do not widen them to a dataflow without a case.

Compile cost (2026-11-26): every site has its own exit, so exits that each dropped every live owner made a function of n calls hold n*n drops (6.9 GB for 640 statements). Drop elaboration now ends an exit whose owners are all plain drops in a branch into a shared chain, one block per owner keyed by (next block, owner) in `mir_elab_chain.c`, and `walk_block` does not release owners in a block that returns. Any call that posts a fault, `msrt_panic` included, must carry `MR_POSTS_FAULT` (`nomerge`), or two blocks that now end the same way merge and the trace names the first line. `tests/lang/functions/long-function-compiles-linearly.ms`.

Compile time (2026-11-26): the rest of the superlinear cost in a 4000-statement `main` was LLVM's GVN (`findLeader` scans every leader of a value number) over the n copies of the same unwind exit that inlining and `fastpaths` leave, each dropping the same owners. `opt_unwind_tails` runs last and gives exits that close the same values the same way (found by their `msrt_unwinding_pause`, not by `cold`, which copies lose) one shared block; GVN fell from 3.6 s to 0.1 s at 2000 statements. Still superlinear in LLVM's back end (greedy allocator, MachineCSE, branch folding): `ms build` of the `shape.py` main takes 1.5, 4.1, 13, 40 s at 500, 1000, 2000, 4000 statements. The text emitter writes no block for one that holds only `forget`s and a branch (`emit_plan_forwards`), and `copyelim` drops a clone of a string literal that is only borrowed and its drop (`print`'s default `end` was a runtime call per statement and a barrier to LLVM): at 2000 statements `ms build` fell from 13 s to 7.7 s. `tests/commands/emit/shared-exit-tails`.

Failure modes found: LLVM tail-merged post calls and moved fault lines, so post calls are `nomerge` (`MR_POSTS_FAULT`); `cancel_edges` must be program-wide (a per-scheduler flag made worker threads take the old path and leak); a flagged slot owner needs its drop flag cleared at `scope.disown`, or a conditional move closes twice.

Apply when: adding a runtime fault, a native that can post, or a lowering that takes values out of closing slots.
Evidence: `src/runtime/core/unwind.c`, `fault.c`, `src/compiler/lower/lower_unwind.c`, `leak_check` and `tools/cancel-sweep.ms`.

Verified (2026-11-25): `opt_unwind_sites` ran only before the inliner, so a test left after an inlined closure that never parks stayed in the loop (`String.fields_by` with a separator closure: a byte load and branch per character). It now runs again after `inline`; `wordfreq` went from 2,580M to 2,368M instructions, and no counted guard moved. Separately, `ms build` does not verify the module and `ms build --emit mir` does: a declaration whose parameter types disagree with its call (the inline `Map.update` probe) passed every conformance run and failed `ms build --emit mir`; ctest `mir_verify` now emits a map program.
