# The language server is C in src/lsp

Verified: 2026-11-23, `src/lsp/lsp_*.c`; `ctest --preset ci` replays `tests/lsp`.

Chinmay chose (2026-11-23) to write `ms lsp` in C beside the other commands, not in Manuscript: nothing in the C build runs embedded Manuscript commands, and the C checker already has the occurrence index. The Rust `ms-lsp` crate was the behavioural reference during the port (error codes, capabilities, position rules, message shapes) and is deleted; its last commit is `660429d4`, and `git show 660429d4:crates/ms-lsp/<path>` reads it if a difference needs a second opinion. Advertise a capability only once it works.

- Each open document is checked as the entry of its own graph, with every open document's text as the overlay. Only findings in that document are shown.
- Sessions are tested with `tests/lsp/<case>/requests.jsonl` and `expected.jsonl`, replayed over standard input and output by `cmake/LspSession.cmake` (`-DRECORD=1` records). `$ROOT` and `$ROOT_URI` stand for the case directory; the version is `$VERSION`. The script is CMake so it runs the same on all three platforms. A line inside a bundled module is written `@LINE:<file>|<text>@` (optionally `|<n>` more lines), which the script resolves to the first line holding the text in `src/stdlib`; a literal stdlib line number breaks every case when someone edits a comment in that file, and `-DRECORD=1` writes literals, so put the placeholders back after recording. Outline, rename and formatting cases of a whole module hold its text, so point them at a small module (`collections/ordering.ms`), not `math.ms`.
- `file(READ)` turns CRLF into LF, so the replay finds a header's end at a blank line.
- Completion and signature help re-check the document with the word under the cursor replaced by a marker name written as a call (not in type position); the scope walk at the marker gives the locals. Function types intern without parameter names, so names and defaults come from the declaration.
- Analyses are cached per entry file and invalidated by a global generation counter that every document change and `workspace/didChangeWatchedFiles` bumps.
- Completion of a word also offers every exported bundled and project name that matches it, each with an `additionalTextEdits` import (placed by `lsp_import_insertion`), so a replay case must use a prefix no bundled name contains in order (`zq...`) or its expected file grows to hundreds of KB. Imports: module paths and exported names are completed straight from parsed bundled and project files (no checker run). Opened `manuscript-stdlib:` documents take the bundled text (the client's is ignored) and are checked as a stand-in file in the temporary directory (`ms-stdlib-<name>`); they publish no diagnostics and refuse edits, formatting, fixes and renames. A type variable's type row holds a variables index in `def`: never pass it to `ms_defs_get`.
- `ms lsp` is a supervisor around a worker copy of itself (`MS_LSP_WORKER=1`). A crash fails the unanswered requests, restarts the worker and replays `initialize` and the open documents. Input is read on its own thread (`lsp_input.c`), which is how `$/cancelRequest` is seen mid-request and how a run of `didChange` frames is published once. Never leave the process through `exit`: the reader thread holds stdin's lock inside `fread`, so `exit` deadlocks; use `lsp_input_exit`. The restart is tested by the conformance fixture `e2e/stdlib/lsp-restart` (it kills the worker; `MS_LSP_LOG=1` prints worker pids on standard error, and the runner gives fixtures the `ms` under test in `MS_UNDER_TEST`). Replay tests cannot check cancellation (all input arrives before the first request is handled); verify it by hand.
- Latency (2026-11-23, release build, typing in a 500 to 5,000 line file): every analysis re-parses and re-checks the whole graph, so keep per-keystroke work to one analysis. A mistyped name asks the checker for an import hint, which once parsed all bundled modules (now one process-wide index, `std_exports.c`). Diagnostics wait behind a queued completion request (`lsp_input_next_defers_publish`), and publishing re-analyses only open documents whose last graph contains a changed file (`LspDoc.deps`). Measure with a driver that sends `didChange`, then times `publishDiagnostics`, hover and completion; use `callgrind` on `MS_LSP_WORKER=1 ms lsp` and dump with `callgrind_control -d` (the server leaves through `_Exit`).
- Parity with the Rust server (2026-11-23) was checked by replaying its recorded scripted sessions against `ms lsp` and diffing by request id; navigation, rename, unfinished and broken matched. Differences left on purpose: Rust hinted `void say(...)` at a column inside `void`, gave a method the doc comment of its receiver type and a broken `type` the detail `T`; references on a std symbol list the import clauses in every bundled module, read from the parsed-std cache without loading anything (Rust sorted those three after the first user place; we sort by range). Editor type displays drop `move` (`ms_ty_show_plain`; diagnostics keep it). A missing local import is a diagnostic plus an empty module (loader `recover` only), so the rest of the file keeps hover, symbols and tokens.
- Semantic tokens colour comments only in the forgiving scan; a bare standard constructor (`none`) has only a `native:` occurrence and is classed by its non-function type.
- A bundled module has two URI spellings: the server writes `manuscript-stdlib:///core.ms`, and VS Code's `uri.toString()` hands back `manuscript-stdlib:/core.ms`. `lsp_normalize_uris` rewrites every `uri` member of an incoming message to the three-slash form once, in `handle_message`, so handlers and open documents see one spelling; matching only `///` made go-to-definition into the standard library fail in the editor while replay cases passed (`tests/lsp/stdlib_normalized_uri`, `stdlib_navigation`).
- A document's path is its real path (`canonicalize_path` in `lsp_doc_set`). The project loader reports real paths, and a document is found again from them by equality; on macOS the temporary directory holding a bundled module's stand-in file is a symlink (`/var` to `/private/var`), so with the client's spelling every definition inside a stdlib document came back empty. Cases holding a `symlinked_tmp` file run with `TMPDIR` behind a symlink (`stdlib_navigation_tmp_symlink`); reproduce a path bug like this on Linux the same way.
