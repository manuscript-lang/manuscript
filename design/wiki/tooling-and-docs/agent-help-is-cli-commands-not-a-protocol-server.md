# Agent help is CLI commands, not a protocol server

Decision: the user evaluated an MCP server (PR #528), judged the CLI the better surface for coding agents, and had it removed. Agents with a shell already get compact output from `check`, `lint`, `fmt`, and `test`; the gaps became `ms search_symbol` and `ms guide`. Navigation is by name, not `file:line:col`, because agents track names better than positions; `ms search_symbol` wraps workspace symbols, definition and references, and the next language-server feature to expose is a checked rename.

Decision: the Manuscript skill is a concise writing reference for agents, not a human tutorial. Prefer inferred locals, flat error propagation and short pipe flows; verify terse spellings against the compiler rather than carrying forward old guide claims. Keep API details discoverable through `search_symbol`.

Apply when: adding agent-facing commands, changing search ranking, or touching the agent skill or standard-library index.

Verified: supplemental standard-library matches must share the CLI's result budget with project matches. Reserving a minimum of two library results made `--limit 1` return two matches and a full ten-project-result list grow to twelve. The CLI limit regression checks library-only and project-filled lists, text output, and the cap at ten.

Evidence: search, workspace queries, project search regressions, skill, search_symbol CLI tests, [agent commands](../../../documentation/developer-tooling/implementation.md#commands-for-agents).
Verify: `ctest --preset ci`; search tests pin typo, synonym, partial, and dedup behavior; compare release timings and output for project, standard-library and no-match queries in a large source tree. The skill's complete examples must check; its entry point stays short.

Superseded (2026-11-18, Chinmay): the `ms skill` command is removed. The skill ships separately from the compiler as a release asset, `manuscript-skill.tar.gz` (built by `toolchain/package-skill.sh`, stamped with `.msversion`), installed with `install-skill.sh` or `install-skill.ps1` on the site, with no compiler needed. The notes below describe the removed command; the bench found agents mostly read the skill by running it as one document (58 of 63), so a run now relies on the folder install.

Decision (removed): `ms skill` prints a self-contained Markdown skill with all concept references inlined and local anchors, suitable for piping without writing files. `ms skill -o <parent>` installs `manuscript/SKILL.md` and separate references, stamping the compiler version and refusing existing skill directories to preserve edits. The old `ms guide` command is removed; `ms explain <code...> [--json]` retains diagnostic-code lookup. Test stdout/redirection, installation outside the source checkout, version parity, complete references, and no-overwrite behavior.

Verified (bench run f37b8c6, Sonnet): all 63 agents read the skill, 58 by running `ms skill` (the whole document in one result) and 59 before their first write, and 60 ran `ms search_symbol`; they still failed 49 first builds, 12 on a guessed standard-library name (`contains_key`, `remove_last`, `is_err`) that was not in the text, and 19 on a syntax shape, nine of which the skill did state but only in prose or in a deep reference. So the entry page carries one-line wrong and right pairs from measured failures, and the exact standard calls come from the declarations, never from memory (no use-count file: Chinmay judged ranking by counts not useful). The Rust generator and its drift test were deleted with the Rust implementation. A from-scratch first build matters less than edits to existing code, which later bench tasks measure.

Verified (bench run f37b8c6, 2026-11-15): agents ran `ms skill` (58 of 63) or opened the skill natively (5 of 63) and rarely opened reference files (4), so the content reaches them through the folder install and the entry page's links. `ms skill -o` repeats, so `ms skill -o .claude/skills -o .agents/skills` installs the same bundle where Claude Code and Codex look; the bench setup uses it.

Lesson (2026-11-25, Chinmay asked for the skill to be brought up to date): the skill had fallen behind the language after the braces and colon-free syntax, `T!`, borrow by default with `move`, `hold` and `&`, the Optional rewrite (no methods; `x != null`, `x or d`, `ok_or(x, cause)`), the empty-literal rule and `xs[i]`. Its worst advice was "clone everything you hand over": under borrow by default that is wrong, so the entry page now teaches borrow, `var` to change, `move` to keep and `.clone()` for a real second owner. `standard-calls.md` and `standard-modules.md` were regenerated from `src/stdlib/` (the call tables from the declarations, the module table from `ms doc`). Chinmay chose not to add a check that fails when the skill goes stale, so a language change that touches ownership, Optional or Result handling, or the CLI should be followed by a read of `extensions/agent-skill/` (`ms run tools/example-check.ms` already type-checks its fences).
